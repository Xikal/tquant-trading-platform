## 2.2 抽取共享费用计算服务

当前费用相关代码分散在 3 处：

| 位置 | 职能 | 复用？ |
|------|------|--------|
| `paper/fees.py:19` — `calculate_fee()` | 单边费用明细（返回 `FeeDetail` dataclass） | ✅ 纯函数，可直接导入 |
| `paper/risk_control.py:229` — `_round_trip_fee_pct()` | 往返费用率（%，调用 `calculate_fee` × 2） | ❌ 前缀 `_` 表示模块私有 |
| `execution_simulation.py:9` — `ROUND_TRIP_COST_BPS = 16.0` | 回测硬编码常数 | ❌ 不适用于做 T 实际费用 |

**方案**：将 `_round_trip_fee_pct()` 从 `risk_control.py` 移到新的共享模块 `backend/app/services/shared/trading_costs.py`。做 T 引擎和模拟盘同时导入。

```python
# backend/app/services/shared/trading_costs.py (新建)
from decimal import Decimal
from app.services.paper.fees import calculate_fee

def round_trip_fee_pct(*, symbol: str, price: float, quantity: int) -> float:
    """往返费用占成交金额的百分比。已包含买入佣金+卖出佣金+印花税+过户费。"""
    if price <= 0 or quantity <= 0:
        return 0.0
    gross = Decimal(str(price)) * Decimal(quantity)
    if gross <= 0:
        return 0.0
    try:
        buy_fee = calculate_fee(symbol=symbol, side="buy", price=Decimal(str(price)), quantity=quantity)
        sell_fee = calculate_fee(symbol=symbol, side="sell", price=Decimal(str(price)), quantity=quantity)
        total = buy_fee.total_fee + sell_fee.total_fee
    except Exception:
        return 0.0
    return float((total / gross) * Decimal("100"))

def round_trip_fee_amount(*, symbol: str, price: float, quantity: int) -> float:
    """往返费用金额（元）。"""
    fee_pct = round_trip_fee_pct(symbol=symbol, price=price, quantity=quantity)
    return round(float(Decimal(str(price)) * Decimal(str(quantity)) * Decimal(str(fee_pct)) / Decimal("100")), 2)
```

`risk_control.py` 的 `_round_trip_fee_pct()` 改为从 `trading_costs` 导入（保持接口不变，避免影响模拟盘风控路径）。

## 2.4 新增 `attach_trade_costs()` 函数

```python
# quant_engine_execution.py 新增
from app.services.shared.trading_costs import round_trip_fee_pct, round_trip_fee_amount
from app.services.quant_engine_models import TradeCostEstimate

def attach_trade_costs(
    *,
    trade_plan: TradePlan,
    quote: QuoteSnapshot,
    position_shares: int,
    elasticity_score: float,
    fee_aware_enabled: bool = True,
    min_net_profit_pct: float = 0.30,
    max_breakeven_pct: float = 0.50,
    min_elasticity_score: float = 25.0,
) -> TradeCostEstimate:
    """在已有 TradePlan 上附加费用、弹性、方向数据。不修改 trade_plan 本身。"""

    action = trade_plan.action
    entry = trade_plan.entry_price

    # 方向
    direction = _direction_label(action)

    # 费用计算
    if entry and position_shares > 0:
        fee_amount = round_trip_fee_amount(symbol=quote.symbol, price=entry, quantity=position_shares)
        fee_pct = round_trip_fee_pct(symbol=quote.symbol, price=entry, quantity=position_shares)
    else:
        fee_amount = 0.0
        fee_pct = 0.0

    gross_amount = (entry or 0.0) * position_shares
    breakeven_pct = (fee_amount / gross_amount * 100) if gross_amount > 0 else 0.0
    net_profit_pct = trade_plan.expected_profit_pct - breakeven_pct - (trade_plan.slippage_bps / 100)

    # 费用警告
    fee_warning = ""
    if breakeven_pct > 1.0:
        fee_warning = f"手续费占比极高（{breakeven_pct:.2f}%），不建议操作"
    elif breakeven_pct > 0.50:
        fee_warning = f"手续费占比偏高（{breakeven_pct:.2f}%），建议增加操作股数"

    # 有效动作判断
    effective_action = action
    is_actionable = action != "hold"
    if action != "hold" and fee_aware_enabled:
        if breakeven_pct > max_breakeven_pct:
            effective_action = "hold"
            is_actionable = False
        elif net_profit_pct < min_net_profit_pct:
            effective_action = "hold"
            is_actionable = False
        elif elasticity_score < min_elasticity_score and fee_aware_enabled:
            is_actionable = False  # 信号保留但标记为不可执行

    # 建议最小股数
    min_shares = 0
    if entry and entry > 0:
        min_shares = _min_shares_for_fee_breakpoint(entry)

    return TradeCostEstimate(
        estimated_fee=round(fee_amount, 2),
        net_profit_pct=round(net_profit_pct, 4),
        breakeven_pct=round(breakeven_pct, 4),
        fee_warning=fee_warning,
        elasticity_score=elasticity_score,
        direction=direction,
        min_shares_suggestion=min_shares,
        effective_action=effective_action,
        is_actionable=is_actionable,
    )
```

**关键设计**：`trade_levels()` 保持不变（5 元组），`TradePlan` 现有字段保持不变，费用/弹性作为独立 `TradeCostEstimate` 附加。`quant_engine_decision.py:151` 的调用方无需修改。

### 2.7.2 计算逻辑

```python
# quant_engine_execution.py 新增
def compute_elasticity_score(*, symbol: str, db: Session) -> float:
    """近 20 日弹性评分。定义：盘中跌 >1.5% 后当日或次日反弹超过跌幅 60% 的次数。"""
    cached = db.query(TradingElasticityCache).filter(
        TradingElasticityCache.symbol == symbol,
        TradingElasticityCache.computed_at >= func.date('now', '-1 day'),
    ).first()
    if cached:
        return cached.elasticity_score

    bars = _load_intraday_range_bars(symbol=symbol, days=20, db=db)
    if not bars:
        return 10.0  # 数据不足，给最低基础分

    count = sum(1 for day_bars in bars if _day_has_elastic_rebound(day_bars))

    if count >= 3:
        score = min(100.0, 60.0 + count * 8.0)
    elif count >= 1:
        score = 25.0 + count * 15.0
    else:
        score = 10.0

    # 写入缓存
    db.merge(TradingElasticityCache(
        symbol=symbol,
        elasticity_score=score,
        rebound_count=count,
        computed_at=func.now(),
        data_quality="ok" if bars else "partial",
    ))
    db.commit()
    return score
```

**性能**：首次 ~10-20ms（分钟线查询 20 日 × 240 分钟 ≈ 4800 行），缓存命中 ~0.1ms。缓存 TTL 1 个交易日。批量预计算在每日盘前定时任务中执行（不在用户请求热路径）。

# Phase 3：新增两个波段策略

## 3.1 新增前必须跑的数据探针（前置步骤）

`leader_pullback_band` 依赖行业内涨停次数、成交额排名、20 日涨幅排名。当前 `candidate_rules.py` 的 `BoardCandidate` 和 `CandidateMetrics` 中没有这些聚合字段。必须在开发策略前验证数据可用性。

```python
# 探针脚本：backend/scripts/probe_leader_pullback_data.py
# 输出：
#   1. 近 24 个月每月涨停 ≥2 次的股票数（按行业分组）
#   2. 行业成交额排名的数据可用率
#   3. 20 日涨幅排名的数据可用率
#   4. DailyBarSnapshot 中 amount 字段的缺失率
#   5. 预估每日候选数（≥2 涨停 + 回撤 ≥6%）
```

**探针通过标准**：每月至少有一个行业产出 ≥3 个候选，数据可用率 > 95%。如果探针失败，`leader_pullback_band` 降级为仅回测不进入 Playbook。

## 3.2 策略设计

（策略逻辑与 v2 一致，此处仅保留规则摘要，详情见 v2 文档 3.2-3.3 节。）

### `ma_channel_band`（均线通道策略）
- 入场：MA20 > MA60 + 价格在 MA20 下方 0%-4% + 40 日内 ≥1 次通道反弹 + 量 OK + 分布风险 < 6.5
- 出场：触及 MA20+4% 止盈 / 破入场日最低 × 0.98 止损 / 15 日时间止损 / MA5 下穿 MA20 趋势止损

### `leader_pullback_band`（龙头回踩策略）
- 龙头确认：近 20 日涨停 ≥2 + 行业成交额前 3 + 行业涨幅前 5（满足 2/3）
- 入场：龙头确认 + 从最高点回撤 ≥6% + 缩量 + 价格在 MA10-MA20 间
- 出场：反弹 50% 止盈一半 / 反弹 80% 全部止盈 / 破 MA60 止损 / 12 日时间止损

**与现有策略的边界**：
- `ma_channel_band` vs `core_midcap_vwap_ma5_retrace`：后者要求热门行业 + 日均成交额 ≥5 亿 + 均线距离 ≤1.8%。ma_channel_band 不限行业、不限成交额（仅 5,000 万门槛）、不限热度。两者不会给同一标的同时发信号（入场条件互斥：ma_channel 在 MA20 下方 0-4%，core_midcap 在 MA5/MA10 下方 ≤1.8%）。
- `leader_pullback_band` vs `sector_mainline_first_divergence_low_buy`：后者捕捉主线板块的首分歧（首板后第一次回调）。leader_pullback 捕捉龙头股的第 2-4 次回踩，龙头已经确认（≥2 涨停）。两者信号时间点不同：首分歧在龙头确认前，龙头回踩在确认后。

# Phase 4：策略治理升级 + 权限/App 集成

## 4.1 策略升级机制（DB override，不改 frozenset）

当前 `strategy_policy.py` 用 Python frozenset 管理层级，升级需要改代码发版。改为 DB 层 override：

### 4.1.1 新增数据表

```python
# backend/app/models/entities.py 或新建 migration

class StrategyTierOverride(Base):
    __tablename__ = "strategy_tier_overrides"
    __table_args__ = (
        UniqueConstraint("strategy_key", name="uq_tier_override_strategy"),
    )

    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    strategy_key: Mapped[str] = mapped_column(String(64), unique=True)
    override_tier: Mapped[str] = mapped_column(String(16))  # "core" | "auxiliary" | "research" | "factor"
    reason: Mapped[str] = mapped_column(String(256))
    evidence_summary: Mapped[str] = mapped_column(Text, default="")  # JSON: {信号数, 胜率, Sharpe, MaxDD, 升级日期}
    promoted_by: Mapped[str] = mapped_column(String(64))   # 操作人
    promoted_at: Mapped[datetime] = mapped_column(DateTime, server_default=func.now())
    reverted_at: Mapped[Optional[datetime]] = mapped_column(DateTime, nullable=True)
```

### 4.1.2 读取逻辑

`strategy_policy.py` 的 `get_strategy_tier()` 改为：先查 `StrategyTierOverride` 表，有 override 且未被 revert → 用 override；无 → 用 frozenset 常量。

### 4.1.3 升级条件（60 日验证）

| 指标 | 阈值 | 数据来源 |
|------|------|---------|
| 模拟盘运行 ≥ 60 个交易日 | ≥ 60 | `LowBuyStrategyPerformanceSnapshot` |
| 总信号数 | ≥ 20 | `filled_signals` |
| 胜率 | ≥ 55% | 正向收益信号数 / 总信号数 |
| 最大回撤 | < 20% | `max_drawdown` |
| 日均信号 | ≥ 0.3 | 信号数 / 交易日 |

### 4.1.4 升级/降级 API

```
POST /api/strategy/governance/promote
Body: { "strategy_key": "ma_channel_band", "tier": "auxiliary", "evidence": { ... } }
仅管理员可调用。写入 StrategyTierOverride 表，记录审计日志。
```

# 十一、待澄清问题与回答

| # | 问题 | 回答 |
|---|------|------|
| Q1 | `ma_channel_band` 与 `core_midcap_vwap_ma5_retrace` 的边界？ | ma_channel 不限行业不限成交额，入场在 MA20 下方 0-4%。core_midcap 仅热门行业 + ≥5 亿成交额，入场在 MA5/MA10 下方 ≤1.8%。两者入场区间不重叠。 |
| Q2 | `leader_pullback_band` 与 `sector_mainline_first_divergence_low_buy` 的边界？ | 首分歧在龙头确认前（涨停后第一次回调），龙头回踩在确认后（≥2 涨停，第 2-4 次回踩）。时间序列上先后不重叠。 |
| Q3 | 新策略是否进入选股宝典 Tab？ | 是。research 策略在 Playbook 的"研究策略"分组中展示，带"研究"标签。不进入"核心策略"分组。 |
| Q4 | research 策略是否允许普通用户回测？ | 允许。所有登录用户可选中 research 策略运行回测。参数优化和样本外验证需要 `can_research` 权限。 |
| Q5 | 策略升级是手动还是自动？ | 手动。管理员审查 60 日验证数据后通过 API 执行升级。系统不自动升级。 |
| Q6 | Feature flag 管理入口？ | 管理员通过 `PUT /api/settings/feature-flags/{key}` API。初期无前端 UI，后续可在系统配置页增加开关面板。 |
| Q7 | 弹性缓存用哪个表？ | 选定 `trading_elasticity_cache` 新表（见 2.7.1）。不复用 `watchlist_signal_snapshots` 的 payload_json（通用字段不适合查询和索引）。 |
| Q8 | 费用降级是改 action 还是 blocking_rules？ | 保留 `action` 原始判断不变。新增 `effective_action` 字段（费用/弹性调整后）和 `is_actionable` 布尔字段。降级原因写入 `blocking_rules`。 |
| Q9 | 手续费占比 >0.50% 对 ETF/股票是否一致？ | ETF 豁免印花税 0.05%，往返费用更低。`round_trip_fee_pct()` 通过 `calculate_fee()` 自动根据 `instrument_type` 调整。阈值可以不同但当前使用统一的 0.50%。 |
| Q10 | leader_pullback 的"主板标的"如何判断？ | 检查 `symbol` 前缀：`60xxxx`（上海主板）、`00xxxx`（深圳主板）。排除 `300xxx`（创业板）、`688xxx`（科创板）。在 `candidate_rules.py` 预过滤分支中实现。 |
| Q11 | 新策略回测失败或样本不足时如何展示？ | 前端不隐藏策略，显示"样本不足（X/20 笔信号）"提示。回测结果为空时展示空态："该策略在当前区间未产生足够信号"。 |
| Q12 | App 是否需要策略工作台？ | 不需要。App 仅展示做 T 分析和低吸榜单。策略工作台（回测/优化/验证）仅在 Web 端。App bootstrap 不扩展策略 tabs。 |
