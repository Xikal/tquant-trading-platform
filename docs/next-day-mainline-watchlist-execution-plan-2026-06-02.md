# 明日主线观察池能力开发文档

- 状态：需求开发文档 / 待实施
- 适用项目：维斯量化交易平台 / `tquant-trading-platform`
- 适用范围：后端观察池服务、策略跟踪、实时监控、模拟盘 Shadow/Paper 验证
- 生成日期：2026-06-02
- 核心原则：只做观察与验证，不直接替换生产排序，不自动给买卖指令
- 关联文档：
  - `AGENTS.md`
  - `docs/engineering-conventions.md`
  - `docs/strategy-sector-mainline-first-divergence-low-buy.md`
  - `docs/reports/three-pages-layout-restructure-plan-2026-06-01.md`

## 1. 背景

当前平台已经具备低吸优先榜、策略跟踪、模拟盘、前排加权、数据中心等能力，但在“第二天应该重点观察哪些票”这个场景上仍偏弱。

现有问题：

1. 平台更擅长展示当日策略信号，缺少面向次日的观察池。
2. 页面容易把“推荐、观察、接近买点、可买”混在一起，用户需要额外判断。
3. 个股选择偏重单票分数，对“今日主线、板块地位、板块退潮、用户偏好过滤”的解释不够。
4. 缺少明确的观察条件和失效条件，用户不知道什么时候继续看、什么时候放弃。
5. 用户偏好无法稳定表达，例如“不要创业板、不要科创板、只看主板”。

本能力把人工选票方法拆解为可计算、可解释、可回测的“明日观察池”。

## 2. 目标

建设一个 `next_day_watchlist` 能力，用于收盘后生成“明日可观察股票池”。

目标输出：

1. 识别当日主线板块。
2. 按用户偏好过滤股票范围，例如只看主板、排除创业板、排除科创板、排除 ST。
3. 在主线内筛选前排、强跟随、中军，剔除后排杂票。
4. 为每只观察票生成白话解释、观察条件、失效条件和风险标签。
5. 接入实时监控和策略跟踪页面，明确显示“观察，不是确定买入”。
6. 接入 Shadow/Paper 验证，统计观察池转买点的质量。

不做：

1. 不自动下单。
2. 不替换原低吸策略排序。
3. 不把观察池直接纳入生产收益排行。
4. 不把 `near_entry`、观察类信号写成确定买入。
5. 不用信号日之后的数据反推观察池生成结果。

## 3. 业务定义

### 3.1 明日观察池

明日观察池是收盘后生成的次日候选列表，用于提醒用户重点观察。

它不是买入列表，也不是生产排序。

页面必须显示：

```text
当前性质：观察，不是确定买入
```

### 3.2 观察条件

观察条件表示“什么情况下这只票值得继续看”。

示例：

```text
观察条件：回踩 128-131 不破，板块继续强，分时重新转强。
```

### 3.3 失效条件

失效条件表示“什么情况下这只票应该放弃观察”。

示例：

```text
失效条件：放量跌破 125，或板块进入退潮。
```

### 3.4 板块地位

板块地位用于解释个股在主线中的角色。

| 代码 | 中文 | 说明 |
|---|---|---|
| `leader` | 龙头 | 板块最高辨识度或空间核心 |
| `front_row` | 前排 | 板块内强度靠前，资金优先选择 |
| `strong_follower` | 强跟随 | 跟随龙头最紧，强于板块平均 |
| `center_liquidity` | 中军 | 成交额大、趋势稳、容量适合大资金 |
| `back_row` | 后排 | 板块内排名靠后，只作降权或剔除 |

## 4. 用户偏好过滤

新增观察池偏好配置，默认不影响原策略。

建议配置项：

| 字段 | 类型 | 默认值 | 说明 |
|---|---|---:|---|
| `exclude_chinext` | bool | false | 排除创业板，代码通常为 `300/301` |
| `exclude_star` | bool | false | 排除科创板，代码通常为 `688` |
| `main_board_only` | bool | false | 只看主板，等价于排除创业板和科创板 |
| `exclude_st` | bool | true | 排除 ST、*ST |
| `exclude_suspended` | bool | true | 排除停牌 |
| `min_amount` | number | 200000000 | 最低成交额，默认 2 亿 |
| `max_gap_open_risk_pct` | number | 7 | 高开超过该值只观察不追 |
| `watchlist_limit` | number | 20 | 明日观察池最大数量 |

当用户选择“不要科创板和创业板”时，系统应设置：

```json
{
  "main_board_only": true,
  "exclude_chinext": true,
  "exclude_star": true
}
```

## 5. 主线识别

主线不是简单涨幅第一，而是强度、持续性、扩散性、辨识度同时较强。

建议主线评分：

| 因子 | 分值 |
|---|---:|
| 板块涨幅排名前 3 | 15 |
| 板块涨停数 >= 5 | 15 |
| 板块成交额较 5 日均值放大 >= 1.5 倍 | 15 |
| 龙头晋级、反包或强封 | 20 |
| 板块内有中军放量趋势 | 10 |
| 板块连续性 >= 2 日 | 15 |
| 板块强于指数 >= 2% | 10 |

主线分层：

| 分数 | 状态 | 处理 |
|---:|---|---|
| >= 80 | 强主线 | 优先进入观察池 |
| 65-79 | 次主线 | 限量进入观察池 |
| 50-64 | 观察主线 | 只展示方向，不推个股 |
| < 50 | 非主线 | 不进入观察池 |

## 6. 个股筛选

### 6.1 候选来源

候选股票来自：

1. 当日主线板块成分股。
2. 当日涨停、强趋势、放量突破、弱转强样本。
3. 现有低吸优先榜、策略跟踪、前排加权 Shadow 样本。
4. 用户自选或重点跟踪池。

### 6.2 入池条件

建议满足多数条件：

| 条件 | 建议阈值 |
|---|---|
| 所属板块 | 强主线或次主线 |
| 板块地位 | 龙头、前排、强跟随、中军 |
| 成交额 | >= 2 亿，容量票 >= 5 亿 |
| 换手 | 活跃但非极端派发 |
| 日 K | 收盘不破关键支撑，或强势收高 |
| 分时 | 有承接，不是一根线冲高回落 |
| 风险 | 无 ST、停牌、严重公告风险 |

### 6.3 剔除条件

以下情况不得进入明日观察池：

1. 板块已经退潮。
2. 个股明显高位爆量派发。
3. 后排补涨且无辨识度。
4. 当日天地板、准天地板、极端长上影且无修复。
5. 涨幅过大但次日只能追高，没有合理观察位。
6. 用户偏好排除的市场板块，例如创业板、科创板。

## 7. 评分模型

新增 `watch_score`，只用于观察池排序。

建议权重：

| 维度 | 权重 | 说明 |
|---|---:|---|
| 主线强度 | 25 | 板块是否为强主线 |
| 板块地位 | 20 | 龙头、前排、中军加权 |
| 个股强度 | 15 | 收盘位置、相对强弱、量价 |
| 承接质量 | 15 | 回踩、分时、VWAP、尾盘承接 |
| 风险惩罚 | -20 到 0 | 高开风险、冲高回落、退潮 |
| 用户偏好匹配 | 10 | 是否符合主板、流动性等偏好 |
| 触发条件清晰度 | 10 | 是否能给出明确观察/失效条件 |

重要边界：

1. `watch_score` 不等于 `production_score`。
2. 明日观察池不得进入生产收益排行。
3. 只有后续真实触发 `buy_now` 或 `soft_buy_now`，才允许进入生产排序候选。
4. `near_entry` 仍然只能进入观察池或 watch score。

## 8. 触发与失效条件生成

### 8.1 观察条件

系统应基于信号日及之前可见数据生成观察条件。

可使用：

1. 前一日高点、低点、收盘价。
2. 5 日线、10 日线、20 日线。
3. VWAP 或分时均价。
4. 支撑位、压力位、关键整数位。
5. 板块强度与主线状态。
6. 个股是否强于板块平均。

示例输出：

```text
观察条件：板块继续强，股价回踩 128-131 不破，重新放量转强。
```

### 8.2 失效条件

系统应为每只票生成清晰的放弃条件。

示例输出：

```text
失效条件：放量跌破 125，或所属板块从主线转为退潮。
```

### 8.3 高开处理

高开不直接等于买点。

规则建议：

| 情况 | 处理 |
|---|---|
| 高开 <= 3% | 可观察回踩承接 |
| 高开 3%-7% | 只看回踩，不追第一笔 |
| 高开 > 7% | 默认追高风险，除非强封或充分换手 |
| 一字或秒板 | 只作强度锚点，不作为普通观察买点 |

## 10. 前端需求

### 10.1 实时监控页

在实时监控页新增“明日观察池”入口。

展示字段：

1. 股票名称和代码。
2. 所属主线。
3. 板块地位。
4. 观察条件。
5. 失效条件。
6. 当前性质：观察，不是确定买入。
7. 风险标签。

### 10.2 策略跟踪页

策略跟踪支持筛选：

1. 全部。
2. 买入类。
3. 接近买点。
4. 明日观察池。
5. 已触发买点。
6. 已失效。

需要明确区分：

| 状态 | 页面文案 |
|---|---|
| `watch_only` | 观察，不是确定买入 |
| `near_entry` | 接近买点，只提醒观察 |
| `soft_buy_now` | 小仓验证信号 |
| `buy_now` | 买入类信号，仍需风控 |
| `invalidated` | 条件失效，停止观察 |

### 10.3 模拟盘

模拟盘只接入 Shadow/Paper 验证：

1. 记录观察池样本。
2. 记录次日是否触发买点。
3. 记录触发后表现。
4. 不自动开仓。
5. 不混入真实组合收益。

## 11. 文案要求

页面必须使用白话提示。

推荐文案：

```text
明日观察池：这些票只是明天重点观察，不代表现在可以买。
观察条件：满足这些条件才继续看。
失效条件：触发这些条件就停止观察。
高开不追：如果开盘涨太多，先等回踩确认。
板块退潮：所属方向转弱时，个股观察价值下降。
```

禁止文案：

```text
强烈推荐
确定买入
明天必涨
生产买入候选
自动买入
```

## 12. 回测与验证

必须先做 Shadow/Paper 验证，不直接上线。

验证指标：

| 指标 | 说明 |
|---|---|
| 观察池样本数 | 每日入池数量 |
| 触发率 | 次日满足观察条件并转买点的比例 |
| 失效率 | 次日触发失效条件的比例 |
| 触发后平均单笔 | 转买点后的平均收益 |
| 最大回撤 | 观察池触发样本最大回撤 |
| PF | 盈亏比 |
| 最长无票天数 | 是否长期没候选 |
| 高开追风险命中率 | 高开后冲高回落样本占比 |
| 板块退潮误入率 | 退潮时仍入池的比例 |
| 用户偏好过滤后留存 | 例如只看主板后的样本留存 |

必须分开展示：

1. 明日观察池收益。
2. 触发买点后收益。
3. 真实组合收益。
4. 每日信号等权复利收益。
5. 观察池失效样本。

## 13. 未来函数约束

生成观察池时只能使用信号日及之前数据。

禁止使用：

1. 次日开盘价决定前一日观察池。
2. 次日涨跌决定观察条件。
3. 次日板块表现反推主线状态。
4. 后验最高价生成压力位。
5. 后验最低价生成止损位。

所有报告必须写明：

```text
future_leak_check: passed / failed / not_checked
```

## 14. Feature Flag

新增能力默认关闭。

建议开关：

```text
NEXT_DAY_WATCHLIST_ENABLED=false
NEXT_DAY_WATCHLIST_SHADOW_ENABLED=true
NEXT_DAY_WATCHLIST_PRODUCTION_RANKING_ENABLED=false
```

默认行为：

1. 关闭时不影响现有低吸优先榜。
2. Shadow 开启时只生成观察池和报告。
3. 生产排序开关必须保持 false，除非后续经过单独评审和部署批准。

## 15. 测试要求

后端测试：

1. 主线评分分层。
2. 用户偏好过滤：排除创业板、科创板、ST。
3. `watch_score` 不生成 `production_score`。
4. `near_entry` 只能进入观察池。
5. 板块退潮时不入池。
6. 高开风险标签生成。
7. 观察条件和失效条件不使用未来数据。

前端测试：

1. 明日观察池入口展示。
2. `watch_only` 文案不是买入建议。
3. 用户选择“只看主板”后不展示创业板、科创板。
4. 空数据、加载态、错误态。
5. 375px 移动端无横向溢出、无挤压。

回测测试：

1. 观察池样本收益不混入真实组合收益。
2. 触发买点样本和未触发样本分开展示。
3. 用户偏好过滤前后样本留存正确。

3. 新增观察池 API。

## 17. 验收标准

1. 页面能看到“明日观察池”。
2. 每只票都有主线、板块地位、观察条件、失效条件、风险标签。
3. 用户可选择只看主板，结果不包含创业板和科创板。
4. 页面明确显示“观察，不是确定买入”。
5. `watch_score` 不进入生产收益排行。
6. `production_sort_replaced=false`。
7. 观察池报告和真实组合收益分开展示。
8. 未来函数检查通过。
9. 相关后端、前端、回测测试通过。
10. 未部署，未替换生产排序。

## 18. 风险与阻断项

| 风险 | 影响 | 处理 |
|---|---|---|
| 板块数据不完整 | 主线识别不准 | 显示数据不足，不生成强结论 |
| 成分股归属混乱 | 板块地位误判 | 支持多板块，优先行业 + 热点概念 |
| 观察池被误解为买入 | 用户误操作 | 页面强制显示观察性质 |
| 高开追涨风险 | 次日回撤大 | 增加高开风险标签和失效条件 |
| 样本过少 | 验证不稳定 | Shadow 至少覆盖 60 个交易日 |
| 未来函数 | 回测虚高 | asof 数据约束和测试守卫 |

## 19. 默认结论

该能力应作为平台的“观察和解释增强”，不是生产买入模型。

建议默认结论：

```text
明日观察池只用于盘前/盘中观察，不代表确定买入。
只有当观察条件被触发，并且原有生产策略生成 buy_now 或 soft_buy_now 时，才允许进入买入类排序。
当前阶段仅建议 Shadow/Paper 验证，不建议直接进入小流量生产观察。
```
