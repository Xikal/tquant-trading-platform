# TQuant v9 P0/P1 修复报告

## 策略元数据唯一规则

- `visibility="full"`：可作为普通展示入口；仍需满足 `enabled=true` 与 feature flag。
- `visibility="backtest_only"`：仅 `admin`、`backtest_research`、`backtest_optimizer` 可见和可提交回测；普通用户不可见且直传 strategy key 会被后端拒绝。
- `visibility="hidden"`：普通用户永远不可见；admin 只有显式 `include_hidden=true` 才能在 `/api/strategies/meta` 看到。Playbook、App、优先榜、生产预设均不展示 hidden。
- 生产预设只允许 `category_key in {"core","auxiliary"}`、`visibility="full"`、`enabled=true` 的策略。

## factor 权限裁定

`factor` 是后端权限能力，不是单纯 UI 隐藏。

- 普通用户：不能从 meta API 看到 factor；直传 factor key 到 `POST /api/backtests` 会返回 403。
- `backtest_research` / `backtest_optimizer` / `admin`：可查看和回测 factor。
- 禁用策略、未知策略、`probe_status="failed"` 策略会被回测接口拒绝。

## Quick Backtest 契约

不新增 `preset_key` 回测提交接口。

- `/api/strategy/presets` 只返回配置模板。
- 前端套用 preset 后，将 preset 展开成现有 `BacktestRunCreate` 契约。
- `POST /api/backtests` 继续只接收 `strategies` 数组和现有回测参数，避免双入口。

## 新策略指标口径

`ma_channel_band` 与 `leader_pullback_band` 不引用未接入字段。当前公式只使用 `CandidateMetrics` 已有字段：

- 均线/趋势：`ma20`、`ma60`、`strong_trend`、`close_to_ma20`。
- 位置与支撑：`support_distance_pct`、`board_low_held`、`retracement_days`。
- 量能：`volume_burst_ratio`、`latest_volume_ratio`、`post_volume_ratio`。
- 风险：`distribution_risk_score`、`false_breakout_flag`、`intraday_reversal_flag`、`long_upper_shadow`。
- 龙头强度：`board_count`、`amount`。

未在 `CandidateMetrics` 中验证的 `board_count_20d`、`drawdown_from_high_pct`、`recent_avg_volume`、`ma_volume_20` 不进入当前生产公式。

## Feature Flag API

- GET `/api/settings/feature-flags` 返回 `items` 兼容结构，同时返回 `flags` 映射。
- 每个 flag 返回：`key`、`enabled`、`value`、`default`、`type`、`description`、`source`、`updated_at`、`updated_by`。
- PUT `/api/settings/feature-flags/{key}` 仅管理员可用，写入 `feature_flag_audit_log`，记录 `operator_user_id` 与 `operator_ip`。
- GET `/api/settings/feature-flags/audit` 仅管理员可用，用于前端审计历史。
- 服务层有 60 秒进程缓存，更新后立即失效。

## 弹性数据质量枚举

`elasticity_data_quality` 只输出以下值：

- `fresh`：30 分钟内真实分钟/缓存数据。
- `stale`：已有数据但过期。
- `estimated`：样本不足或估算数据。
- `unavailable`：无可用弹性数据或功能关闭。

只有 `fresh` 会参与强弹性等级；`estimated/unavailable` 只做风险提示，不作为强信号。

## probe_status 生命周期

- `not_required`：无需探针，可按层级和权限使用。
- `pending`：探针未完成；普通生产入口不展示，研究权限可回测。
- `passed`：探针通过，可按治理规则提升。
- `failed`：探针失败；回测和生产提升均拒绝，需重新探针。

`probe_leader_pullback_data.py` 输出 JSON，包含日线覆盖、策略池覆盖、行业覆盖、盘中/结果覆盖四维探针。
