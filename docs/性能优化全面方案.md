## 一、网络 I/O 层（影响最大，优先处理）

### 1.1 全局 akshare 锁 → 分用途锁 + 连接池

**当前问题**：`MarketSectorMixin._call_akshare()` 使用类级 `_akshare_lock`（`sectors.py:209`），所有 akshare 调用（行业数据、股票列表、涨跌停池、大盘情绪、行情快照）全部串行化。任何一个慢调用（如全量行情快照，5000+ 行）会阻塞所有其他调用。

**方案**：

```python
# backend/app/services/market/akshare_pool.py（新建）

import threading
from collections import defaultdict

class AkshareCallPool:
    """按用途分锁的 akshare 调用池。
    
    不同用途的调用使用不同的锁，互不阻塞：
    - 行情快照可以和大盘情绪并行
    - 同一用途的重复调用共享锁（去重）
    """
    
    def __init__(self):
        self._locks: dict[str, threading.Lock] = defaultdict(threading.Lock)
        # 用途分类
        self._categories = {
            "spot_snapshot": "quote",       # 全量行情快照
            "instrument_list": "refdata",   # 股票列表
            "industry": "refdata",          # 行业分类
            "limit_pool": "emotion",        # 涨跌停池
            "market_breadth": "emotion",    # 大盘情绪
            "trade_dates": "refdata",       # 交易日历
            "minute_bars": "intraday",      # 分钟线（Sina）
        }
    
    def call(self, purpose: str, fn, *args, **kwargs):
        category = self._categories.get(purpose, "default")
        with self._locks[category]:
            return fn(*args, **kwargs)

# 全局单例
_akshare_pool = AkshareCallPool()
```

**预期收益**：行情快照与大盘情绪可并行，减少串行等待 30-60%。

### 1.2 QuoteSourceRouter 串行链 → 并行试探 + 早停

**当前问题**：`quote_router.py:10-25` 单符号行情获取链式调用 5 个数据源（Tencent → Eastmoney trends → minute bars → spot snapshot → Sina），每个失败才试下一个，最坏 5 次 HTTP 调用。

**方案**：改为"主力源优先 + 备源并行试探"模式。

```python
# backend/app/services/market/quote_router.py（修改）

class QuoteSourceRouter:
    def fetch(self, symbol: str) -> QuoteSnapshot:
        # 第一步：主力源（腾讯），大多数情况命中
        quote = self._fetch_tencent_quote(symbol)
        if quote and not quote.is_stale:
            return quote
        
        # 第二步：备源并行试探，谁先返回用谁
        with ThreadPoolExecutor(max_workers=3) as pool:
            futures = {
                pool.submit(self._fetch_quote_from_trends, symbol): "trends",
                pool.submit(self._fetch_quote_from_minute_bars, symbol): "minute",
                pool.submit(self._fetch_quote_from_spot_snapshot, symbol): "spot",
            }
            for future in as_completed(futures, timeout=3.0):
                try:
                    result = future.result()
                    if result and not result.is_stale:
                        # 取消其他未完成的请求
                        for f in futures:
                            f.cancel()
                        return result
                except Exception:
                    continue
        
        # 第三步：最后的兜底
        return self._fetch_sina_quote(symbol)
```

**预期收益**：单符号行情最坏从 5 次串行 HTTP → 1 次串行 + 1 次并行（3 个源竞速），P95 延迟降 50%。

### 1.3 分钟线串行获取 → ThreadPoolExecutor 并行 + 连接复用

**当前问题**：3 个位置（`priority_board.py:426`、`signals.py:789`、`screening_quotes.py:246`）各自以 `for symbol in symbols` 串行拉分钟线，每次独立 HTTP 连接。

**方案**：统一入口 + 并行获取。

```python
# backend/app/services/market/intraday.py（修改）

class IntradayDataService:
    def get_intraday_bars_batch(
        self, 
        symbols: list[str], 
        period: str = "1m", 
        limit: int = 30,
        max_workers: int = 8,
    ) -> dict[str, list[KlineBar]]:
        """并行获取多只股票的分钟线。"""
        results = {}
        with ThreadPoolExecutor(max_workers=max_workers) as pool:
            futures = {
                pool.submit(self.get_intraday_bars, s, period, limit): s 
                for s in symbols
            }
            for future in as_completed(futures, timeout=5.0):
                symbol = futures[future]
                try:
                    results[symbol] = future.result()
                except Exception as e:
                    logger.warning(f"Intraday bars failed for {symbol}: {e}")
        return results
```

所有调用方改为：

### 1.5 analysis.analyze_batch 串行 → 并行

**当前问题**：`analysis_service.py:137-138` 的 `analyze_batch` 完全串行调用 `self.analyze()`。

```python
def analyze_batch(
    self, db_session_factory, requests: list[AnalysisRequest], 
    max_workers: int = 4
) -> list[AnalysisResponse]:
    results: list[AnalysisResponse | None] = [None] * len(requests)
    
    def _analyze_one(index: int, req: AnalysisRequest):
        with db_session_factory() as db:
            service = AnalysisService()
            results[index] = service.analyze(db, req, persist=False)
    
    with ThreadPoolExecutor(max_workers=max_workers) as pool:
        futures = [pool.submit(_analyze_one, i, req) for i, req in enumerate(requests)]
        for f in futures:
            f.result(timeout=30)
    
    return [r for r in results if r is not None]
```

**预期收益**：批量分析从 N×3-5s 降到 N/4×3-5s。

## 三、缓存层

### 3.1 深层拷贝优化

**当前问题**：所有行情和筛选结果的缓存读写都调用 `model_copy(deep=True)`，对大 Pydantic 模型（LowBuyScreenerResponse 含 100+ 候选，每候选 85 字段）开销极大。

**方案**：对不可变数据使用浅拷贝 + 冻结标记。

```python
# 行情缓存：QuoteSnapshot 的字段都是基本类型，浅拷贝安全
def _get_quote_cache(self, symbol: str) -> QuoteSnapshot | None:
    with self._cache_lock:
        entry = self._quote_cache.get(symbol)
        if entry and time.monotonic() - entry[0] < self._quote_ttl:
            return entry[1]  # 直接返回引用，不再 deep copy
            # 调用方不修改返回对象即可。如有修改风险，在修改点做 copy

# 筛选结果缓存：使用 freeze() + 写时复制
from pydantic import BaseModel

class FrozenScreenerResponse(BaseModel):
    """冻结的筛选响应，确保缓存中的对象不会被意外修改。"""
    model_config = {"frozen": True}
```

**预期收益**：缓存读写延迟降 90%（deep copy 是纯 CPU 操作，对大对象尤其重）。

### 3.2 缓存过期清理

**当前问题**：过期的缓存条目不会从 dict 中移除，内存只增不减。

**方案**：在定期清理任务中扫描并删除过期条目。

```python
class TTLCache:
    def __init__(self, max_size: int = 10000):
        self._data: dict[str, tuple[float, Any]] = {}
        self._lock = threading.Lock()
        self._max_size = max_size
    
    def get(self, key: str, ttl: float) -> Any | None:
        with self._lock:
            entry = self._data.get(key)
            if entry and time.monotonic() - entry[0] < ttl:
                return entry[1]
            if entry:
                del self._data[key]  # 命中时顺便清理过期条目
            return None
    
    def set(self, key: str, value: Any):
        with self._lock:
            if len(self._data) >= self._max_size:
                # LRU 驱逐：删除最旧的 20%
                sorted_keys = sorted(
                    self._data.keys(), 
                    key=lambda k: self._data[k][0]
                )
                for k in sorted_keys[:len(sorted_keys) // 5]:
                    del self._data[k]
            self._data[key] = (time.monotonic(), value)
```

### 3.3 缓存层级优化

为盘中实时决策引入新的缓存分层：

```
L1: 进程内存缓存（当前已有）
    ├── 行情快照：3-5s TTL（盘中高频，必须短）
    ├── 分钟线：20s TTL
    ├── 优先级榜：8s TTL
    ├── 大盘情绪：120s TTL
    └── 板块资金流：600s TTL

L2: 数据库物化快照（当前已有）
    ├── low_buy_materialized_results：小时级刷新
    └── strategy_performance_snapshots：日级刷新

L3（新增）: 请求级去重缓存
    └── 同一请求在 inflight 期间不重复执行
```

**请求级去重**：FastAPI middleware，同一 URL+参数在 pending 期间直接返回 pending 的结果。

```python
# backend/app/core/request_dedup.py（新建）

import asyncio
from collections import defaultdict

class RequestDeduplicationMiddleware:
    """请求去重中间件：同一 URL+参数的并发请求共享同一个结果。"""
    
    def __init__(self, app):
        self.app = app
        self._pending: dict[str, asyncio.Event] = {}
        self._results: dict[str, Any] = {}
    
    async def __call__(self, scope, receive, send):
        if scope["type"] != "http":
            await self.app(scope, receive, send)
            return
        
        cache_key = f"{scope['method']}:{scope['path']}?{scope['query_string'].decode()}"
        
        if cache_key in self._pending:
            # 已有相同请求在处理，等待结果
            event = self._pending[cache_key]
            await event.wait()
            # 使用缓存结果响应
            result = self._results.get(cache_key)
            if result:
                await send(result)
            return
        
        self._pending[cache_key] = asyncio.Event()
        try:
            await self.app(scope, receive, send)
        finally:
            event = self._pending.pop(cache_key)
            self._results.pop(cache_key, None)
            event.set()
```

**预期收益**：用户快速重复点击时不会产生重复的昂贵查询。

## 五、后台任务层

### 5.1 当前架构问题

```
threading.Thread → _refresh_full_scan_loop    (3600s)
threading.Thread → _refresh_watchlist_signal_loop (45s)
threading.Thread → _warm_runtime_caches       (once)
```

问题：
- 无任务监控 → 线程死了不知道
- 无优雅停止 → 关闭时任务可能被强制 kill
- 异常不恢复 → 线程内异常后整个循环终止
- 无并发控制 → 如果一次全量扫描超过 3600s，下次扫描会和本次重叠

### 5.2 改进方案：任务管理器

```python
# backend/app/core/task_manager.py（新建）

import threading
import time
import traceback
from dataclasses import dataclass
from datetime import datetime
from enum import Enum

class TaskState(Enum):
    IDLE = "idle"
    RUNNING = "running"
    ERROR = "error"

@dataclass
class TaskStatus:
    name: str
    state: TaskState
    last_run: datetime | None
    last_duration: float | None
    last_error: str | None
    run_count: int
    error_count: int

class TaskManager:
    def __init__(self):
        self._tasks: dict[str, TaskStatus] = {}
        self._stop_events: dict[str, threading.Event] = {}
        self._threads: dict[str, threading.Thread] = {}
    
    def register_loop(
        self, name: str, fn, interval_seconds: int, 
        initial_delay: int = 0, prevent_overlap: bool = True
    ):
        """注册一个周期性后台任务。prevent_overlap=True 时上次未完成不启动下次。"""
        status = TaskStatus(name=name, state=TaskState.IDLE, ...)
        self._tasks[name] = status
        stop_event = threading.Event()
        self._stop_events[name] = stop_event
        
        def _loop():
            time.sleep(initial_delay)
            while not stop_event.is_set():
                try:
                    status.state = TaskState.RUNNING
                    t0 = time.monotonic()
                    fn()
                    status.last_duration = time.monotonic() - t0
                    status.last_run = datetime.now()
                    status.run_count += 1
                    status.state = TaskState.IDLE
                except Exception:
                    status.state = TaskState.ERROR
                    status.last_error = traceback.format_exc()
                    status.error_count += 1
                    logger.error(f"Task {name} failed: {status.last_error}")
                
                # 计算下次等待时间
                if prevent_overlap and status.last_duration:
                    wait = max(0, interval_seconds - status.last_duration)
                else:
                    wait = interval_seconds
                
                stop_event.wait(wait)
        
        thread = threading.Thread(target=_loop, daemon=True)
        self._threads[name] = thread
        thread.start()
    
    def shutdown(self, timeout: int = 30):
        """优雅停止所有后台任务。"""
        for name, event in self._stop_events.items():
            event.set()
        for name, thread in self._threads.items():
            thread.join(timeout=timeout)
    
    def get_status(self) -> dict[str, TaskStatus]:
        return dict(self._tasks)

# 全局单例
task_manager = TaskManager()
```

## 八、监控层

### 8.1 请求级性能监控

```python
# backend/app/core/metrics.py（新建）

import time
from collections import deque
from dataclasses import dataclass

@dataclass
class RequestMetric:
    path: str
    method: str
    duration_ms: float
    status_code: int
    timestamp: float

class MetricsCollector:
    def __init__(self, max_samples: int = 10000):
        self._samples: deque[RequestMetric] = deque(maxlen=max_samples)
    
    def record(self, path: str, method: str, duration_ms: float, status_code: int):
        self._samples.append(RequestMetric(
            path=path, method=method,
            duration_ms=duration_ms, status_code=status_code,
            timestamp=time.time(),
        ))
    
    def get_p50(self, path: str | None = None) -> float:
        return self._percentile(path, 0.50)
    
    def get_p95(self, path: str | None = None) -> float:
        return self._percentile(path, 0.95)
    
    def get_p99(self, path: str | None = None) -> float:
        return self._percentile(path, 0.99)

metrics = MetricsCollector()

# 在 FastAPI middleware 中接入
class MetricsMiddleware:
    async def __call__(self, scope, receive, send):
        t0 = time.monotonic()
        status_code = 200
        
        async def _send(message):
            nonlocal status_code
            if message["type"] == "http.response.start":
                status_code = message["status"]
            await send(message)
        
        await self.app(scope, receive, _send)
        metrics.record(
            path=scope["path"], method=scope["method"],
            duration_ms=(time.monotonic() - t0) * 1000,
            status_code=status_code,
        )
```

## 十一、与新功能的协调

本性能方案是后续所有功能的前提条件：

- **PaperTradingExecutor 自动委托**：依赖 priority-board 快速响应（2s 内）和 watchlist signals 并行（1.4）

- **策略验证管线**：回放历史信号时需要快速撮合（并行行情 + 批量 DB）

不解决性能问题就直接上盘中功能 = 用慢 5 倍的系统做更高频的查询 = 不可用。
