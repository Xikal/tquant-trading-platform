## 一、背景与目标

### 1.1 当前状态

TQuant 目前有策略绩效复盘（`performance.py`，事后统计信号 N 日收益）和信号级模拟（`execution_simulation.py`，单信号独立模拟），但没有**事件驱动的投资组合级回测引擎**。这意味着：

- 无法回答"如果 3 个月前用 50 万本金同时跑 first_board + volume_shrink，现在的净值曲线是多少"
- 无法模拟多信号并发时的资金竞争（信号 A 占用了资金，信号 B 就无法成交）
- 无法模拟复利效应（盈利后可用资金增加，亏损后减少）
- 无法做前视偏差防护（当前性能计算用的是"事后已知"的全量数据）
- 无法做系统性的参数优化和样本外验证

### 1.2 目标

构建一个完整的事件驱动回测引擎，与现有的 12 策略管线、模拟盘匹配引擎、费用模型深度集成，实现：

1. **时间序列仿真**：按交易日逐日推进，在每个交易日执行"市场开盘 → 信号生成 → 订单撮合 → 持仓更新 → 净值计算"的完整循环
2. **投资组合级模拟**：跟踪现金、持仓、净值曲线，处理多信号并发时的资金分配和竞争
3. **前视偏差防护**：每个回测日期只能使用该日期之前已知的数据（Point-in-Time）
4. **交易成本建模**：佣金、印花税、过户费、冲击成本、涨跌停不可交易
5. **标准化绩效报告**：Sharpe、Sortino、Calmar、最大回撤、胜率、盈亏比、月度收益分布、滚动指标
6. **参数优化与样本外验证**：网格搜索/贝叶斯优化 + 滚动窗口 walk-forward +  Combinatorial PBO 测试
7. **绩效归因**：Brinson 归因、因子归因、行业归因、市场状态归因

  │

  ├─ 净值曲线
  ├─ 日度/周度/月度收益

## 三、模块详细需求

### 3.1 Point-in-Time 数据提供层 (`data_provider.py`)

**问题**：当前系统使用的数据是"当前最新"的（如日线数据是不断更新的），在回测中直接使用会导致前视偏差——回测 3 个月前时，系统看到了 3 个月后的数据。

**方案**：建立 `backtest_data_snapshots` 表，在每日收盘后对关键数据做快照。

#### 数据快照表

```sql
CREATE TABLE backtest_data_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    trade_date TEXT NOT NULL,              -- 快照日期 "2026-01-15"
    data_type TEXT NOT NULL,               -- 数据类型: daily_bar / limit_up_pool / market_state / sector_classification
    symbol TEXT,                           -- 标的代码（daily_bar 类型时有值）
    payload_json TEXT NOT NULL DEFAULT '{}',  -- 数据内容
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE(trade_date, data_type, symbol)
);

CREATE INDEX idx_backtest_data_snapshots_date_type
    ON backtest_data_snapshots(trade_date, data_type);
```

#### 快照类型

| data_type | 内容 | 来源 | 频率 |
|-----------|------|------|------|
| `daily_bar` | OHLCV + 成交量 + 涨跌幅 | `daily_bar_snapshots` 表 | 每日收盘后 |
| `limit_up_pool` | 当日涨停股票列表 | akshare `stock_zt_pool_em` | 每日收盘后 |
| `market_state` | 市场状态分类 + 各指标值 | `market_state_rules.py` 计算结果 | 每日收盘后 |
| `sector_classification` | 行业分类映射 | akshare 行业分类 | 每周一次 |

#### PIT 数据提供接口

```python
class BacktestDataProvider:
    """Point-in-Time 数据提供层。
    
    每个回测日期只能访问 ≤ 当日的数据，杜绝前视偏差。
    """
    
    def get_daily_bars(self, trade_date: str, symbols: list[str]) -> dict[str, DailyBar]:
        """获取指定日期指定标的的日线数据。
        返回的是截至 trade_date 已知的最新日线（即 trade_date 当日的收盘数据）。
        """
        
    def get_limit_up_pool(self, trade_date: str) -> list[str]:
        """获取指定日期的涨停股票池。"""
        
    def get_market_state(self, trade_date: str) -> MarketState:
        """获取指定日期的市场状态分类。"""
        
    def get_historical_bars(
        self, trade_date: str, symbol: str, lookback: int
    ) -> list[DailyBar]:
        """获取截至 trade_date 的过去 N 天日线数据。
        用于计算均线、量比等需要历史窗口的指标。
        """
```

#### 历史数据回填

对于已过去的交易日（2024-2026），从现有 `daily_bar_snapshots` 表中回填快照。回填策略：

- **日线数据**：`daily_bar_snapshots` 表已有完整历史，可直接按 `trade_date` 筛选，创建对应快照
- **涨停池**：通过 akshare 历史接口回填（`ak.stock_zt_pool_em(date=...)`），或从现有 `limit_up_pool` 历史数据导入
- **市场状态**：重新运行市场状态计算（纯计算，不依赖外部数据），可回溯任意历史日期
- **行业分类**：使用当前最新分类（行业分类变化缓慢，回溯偏差可接受）

回填命令：

```bash
python -m app.services.backtest.data_sync backfill \
    --start 2024-01-01 \
    --end 2026-05-04 \
    --types daily_bar,limit_up_pool,market_state
```

### 3.2 投资组合状态机 (`portfolio.py`)

```python
@dataclass
class PortfolioState:
    """回测中某一时刻的投资组合状态。"""
    date: str                              # 当前交易日
    cash: float                            # 可用现金
    frozen_cash: float                     # 冻结资金（当日买入未结算）
    total_value: float                     # 总资产 = 现金 + 冻结 + 持仓市值
    positions: dict[str, Position]         # symbol → Position
    equity_curve: list[EquityPoint]        # 净值曲线
    trades: list[Trade]                    # 已成交记录
    orders: list[Order]                    # 待成交/已取消订单

@dataclass
class Position:
    symbol: str
    quantity: int                          # 持仓数量（股）
    cost_basis: float                      # 加权平均成本
    available_quantity: int                # 可卖数量（T+1 规则）
    entry_date: str                        # 买入日期
    entry_price: float                     # 买入价格
    strategy: str                          # 策略来源
    entry_signal_score: float              # 买入时信号分数
    max_holding_days: int                  # 最大持有天数
    stop_loss_price: float                 # 止损价
    take_profit_price: float | None        # 第一止盈价
    trailing_stop_activated: bool          # 是否已激活移动止盈
    trailing_stop_price: float | None      # 移动止盈价
```

#### 核心操作

| 操作 | 描述 | T+1 规则 |
|------|------|---------|
| `submit_buy(symbol, quantity, price, strategy)` | 提交买入订单，冻结资金 | 买入当日不可卖出 |
| `fill_buy(order_id, fill_price)` | 买入成交，更新持仓和现金 | available_quantity 次日解锁 |
| `submit_sell(symbol, quantity, price, reason)` | 提交卖出订单 | 只能卖出 available_quantity |
| `fill_sell(order_id, fill_price)` | 卖出成交，释放资金，记录盈亏 | 卖出资金 T+1 可用（A 股实际） |
| `mark_to_market(prices)` | 按当日收盘价重估持仓市值 | — |
| `check_stop_loss(prices)` | 检查持仓是否触发止损 | — |
| `check_take_profit(prices)` | 检查持仓是否触发止盈 | — |
| `check_max_holding(reached)` | 检查持仓是否到期 | — |
| `daily_settle()` | 日终结算：解冻资金、更新净值、处理分红送股 | 解冻前一日买入的股票 |

### 3.3 事件驱动主循环 (`engine.py`)

```python
class BacktestEngine:
    """事件驱动回测引擎。
    
    使用方式:
        engine = BacktestEngine(config)
        result = engine.run()
        print(result.summary())
    """
    
    def __init__(self, config: BacktestConfig):
        self.config = config
        self.data_provider = BacktestDataProvider(config.start_date, config.end_date)
        self.portfolio = PortfolioState(initial_cash=config.initial_capital)
        self.broker = BacktestBroker(config.slippage_model, config.fee_model)
        self.strategies = self._init_strategies(config.strategies)
        self.analyzer = BacktestAnalyzer()
    
    def run(self) -> BacktestResult:
        """执行完整回测。"""
        trade_dates = self._get_trade_calendar()
        
        for i, date in enumerate(trade_dates):
            # 1. 开盘前准备
            self.portfolio.begin_day(date)
            self.portfolio.unlock_positions(date)  # T+1 解锁
            
            # 2. 信号扫描
            pit_data = self.data_provider.snapshot(date)
            signals = self._scan_signals(pit_data, date)
            
            # 3-4. 信号排序 + 资金分配
            ranked = self._rank_and_allocate(signals)
            
            # 5-6. 订单生成 + 撮合
            orders = self._generate_orders(ranked)
            fills = self.broker.match(orders, pit_data, date)
            
            # 7. 持仓更新
            for fill in fills:
                self.portfolio.apply_fill(fill)
            
            # 8-9. 止损/止盈检查
            exit_orders = self._check_exits(pit_data, date)
            exit_fills = self.broker.match(exit_orders, pit_data, date)
            for fill in exit_fills:
                self.portfolio.apply_fill(fill)
            
            # 10. 持仓到期
            expired = self.portfolio.expire_positions(date)
            expired_fills = self.broker.match(expired, pit_data, date)
            for fill in expired_fills:
                self.portfolio.apply_fill(fill)
            
            # 11. 日终结算
            self.portfolio.mark_to_market(pit_data.close_prices)
            self.portfolio.daily_settle()
            
            # 12. 记录快照
            self.analyzer.record_daily_snapshot(self.portfolio, date)
        
        return self.analyzer.compute_result()
```

#### 交易日历

使用 akshare `tool_trade_date_hist_sina` 获取 A 股交易日历，排除周末和节假日。回测引擎只在真正的交易日推进。

#### 信号扫描

复用现有策略管线，但数据源切换为 PIT 数据：

```python
def _scan_signals(self, pit_data, date) -> list[Signal]:
    """在历史日期上运行策略筛选管线。"""
    signals = []
    for strategy_key in self.config.strategies:
        # 复用现有的 screening.py 管线
        # 关键：所有数据查询通过 data_provider（PIT），不直接查 DB
        candidates = run_strategy_screening(
            strategy=strategy_key,
            data_provider=self.data_provider,
            as_of_date=date,
        )
        for c in candidates:
            if c.buy_signal_state in ("buy_now", "soft_buy_now"):
                signals.append(Signal(
                    date=date,
                    strategy=strategy_key,
                    symbol=c.symbol,
                    score=c.score,
                    entry_zone_low=c.entry_zone_low,
                    entry_zone_high=c.entry_zone_high,
                    position_pct=c.suggested_position_pct,
                    exit_plan=c.exit_plan,
                ))
    return signals
```

### 3.4 模拟券商 (`broker.py`)

复用 `paper/matching.py` 的 `PaperMatchingEngine`，增强以下能力：

#### 撮合模型

| 订单类型 | 撮合价 | 说明 |
|---------|--------|------|
| 买入（开盘） | 当日开盘价 × (1 + slippage) | 默认以开盘价入场 |
| 买入（盘中） | 当日均价 (amount/volume) | 可选，更真实 |
| 卖出（止损） | 触发价 × (1 - slippage) | 止损单可能滑点 |
| 卖出（止盈） | 触发价 × (1 - slippage) | 同上 |
| 卖出（到期） | 当日收盘价 | 持仓到期强制平仓 |

#### 滑点模型（增强版）

当前 `paper/matching.py` 使用固定 5 bps 滑点。回测引擎应支持多级滑点模型：

```python
class SlippageModel:
    """滑点模型基类。"""
    def compute(self, order: Order, bar: DailyBar) -> float:
        ...

class FixedSlippage(SlippageModel):
    """固定滑点：股票 5 bps，ETF 2 bps（当前实现）。"""
    
class VolumeProportionalSlippage(SlippageModel):
    """成交量比例滑点：滑点 = base + k × (order_amount / daily_volume)。
    大盘股流动性好，滑点小；小盘股成交量低，滑点大。
    k 默认 0.1，即成交量占比 1% 则额外滑点 10 bps。
    """
    
class VolatilityAdjustedSlippage(SlippageModel):
    """波动率调整滑点：滑点 = base × (1 + 当日振幅 / 平均振幅)。
    高波动日滑点更大。
    """
```

#### 涨跌停处理

```python
def _check_limit(self, symbol: str, date: str, side: str) -> bool:
    """检查是否涨跌停。
    
    - 涨停 (price == high == limit_up)：买入订单无法成交（一字板）
    - 跌停 (price == low == limit_down)：卖出订单无法成交
    - 非一字涨停（开盘价 < 涨停价）：可以以开盘价买入
    """
```

### 3.5 绩效分析器 (`analyzer.py`)

#### 核心指标

| 类别 | 指标 | 公式/说明 |
|------|------|---------|
| **收益** | 总收益率 | (最终净值 - 初始资金) / 初始资金 |
| | 年化收益率 | (1 + 总收益率)^(252/交易日数) - 1 |
| | 日均收益率 | 日度收益率的均值 |
| | 月度胜率 | 月度正收益月数 / 总月数 |
| **风险** | 年化波动率 | 日收益率标准差 × √252 |
| | 最大回撤 (MaxDD) | max((峰值 - 谷值) / 峰值) |
| | 最长回撤恢复期 | 回撤恢复到前高所需的最长天数 |
| | VaR (95%) | 日收益率的 5% 分位数 |
| | CVaR (95%) | 低于 VaR 的平均损失 |
| **风险调整** | Sharpe Ratio | (年化收益 - 无风险利率) / 年化波动率 |
| | Sortino Ratio | (年化收益 - 无风险利率) / 下行波动率 |
| | Calmar Ratio | 年化收益 / 最大回撤 |
| | Omega Ratio | 收益分布的正负面积比 |
| **交易** | 总交易次数 | — |
| | 胜率 | 盈利交易数 / 总交易数 |
| | 平均盈利 / 平均亏损 | 盈亏金额比 |
| | 利润因子 | 总盈利 / 总亏损 |
| | 平均持仓天数 | — |
| | 换手率 | 月度交易额 / 平均资产 |
| **基准对比** | 超额收益 (Alpha) | 策略收益 - 基准收益 |
| | 跟踪误差 | std(超额日收益) × √252 |
| | 信息比率 (IR) | 年化超额收益 / 跟踪误差 |
| | 贝塔 (Beta) | Cov(策略, 基准) / Var(基准) |

#### 逐策略拆解

每个策略单独计算上述指标，并输出：

- 策略贡献度（该策略盈亏 / 总盈亏）
- 策略间相关性矩阵
- 最佳/最差单笔交易

#### 归因分析

| 归因维度 | 方法 | 输出 |
|---------|------|------|

### 3.6 参数优化器 (`optimizer.py`)

#### 优化参数定义

每个策略的可优化参数通过配置文件定义：

```python
OPTIMIZABLE_PARAMS = {
    "first_board": {
        "min_score": {"type": "float", "range": [78, 92], "step": 2},
        "max_position_pct": {"type": "float", "range": [0.10, 0.35], "step": 0.05},
        "max_holding_days": {"type": "int", "range": [3, 15], "step": 1},
        "stop_loss_multiplier": {"type": "float", "range": [0.96, 0.995], "step": 0.005},
    },
    "volume_shrink": {
        "min_score": {"type": "float", "range": [76, 90], "step": 2},
        "volume_burst_ratio": {"type": "float", "range": [1.3, 2.0], "step": 0.1},
        ...
    },
    ...
}
```

#### 优化方法

| 方法 | 适用场景 | 说明 |
|------|---------|------|
| 网格搜索 (Grid Search) | 参数空间小（< 1000 组合） | 穷举所有组合，找最优 |
| 随机搜索 (Random Search) | 参数空间大 | 随机采样 N 组，效率高于网格 |
| 贝叶斯优化 (Bayesian) | 回测耗时长，需高效搜索 | 使用 Gaussian Process 代理模型，每次迭代选择期望改进最大的参数点 |

贝叶斯优化使用 `scikit-optimize` 的 `gp_minimize`。

#### 优化目标

用户可选择优化目标：

- `sharpe`：最大化 Sharpe Ratio（默认）
- `calmar`：最大化 Calmar Ratio（偏好低回撤）
- `total_return`：最大化总收益（偏好高收益）
- `win_rate`：最大化胜率
- `custom`：自定义加权目标（如 `0.5 × sharpe + 0.3 × calmar + 0.2 × win_rate`）

#### 优化流程

```
选定策略 + 参数空间 + 优化目标
  │
  ├─ 生成参数组合（网格/随机/贝叶斯）
  ├─ 对每组参数：运行回测引擎
  ├─ 收集绩效指标
  ├─ 选择最优参数组
  └─ 输出参数敏感性分析（各参数对目标的影响曲线）
```

### 3.7 样本外验证器 (`validator.py`)

#### Walk-Forward 验证

将整个回测周期分为 N 个窗口，每个窗口包含：

- **训练期**（in-sample，如 18 个月）：进行参数优化
- **测试期**（out-of-sample，如 6 个月）：用训练期找到的最优参数运行回测

窗口滚动推进，最终统计所有测试期的合计绩效。

```
窗口 1: [=====训练 18m=====|==测试 6m==]
窗口 2:           [=====训练 18m=====|==测试 6m==]
窗口 3:                     [=====训练 18m=====|==测试 6m==]
...
```

输出：

- 各窗口的样本内/样本外绩效对比
- Walk-Forward 效率 = 样本外 Sharpe / 样本内 Sharpe（> 0.5 为可接受，> 0.8 为优秀）
- 参数稳定性（各窗口最优参数的分布，参数是否剧烈变化）

#### PBO（Probability of Backtest Overfitting）测试

参考 Bailey et al. (2014) 的 Combinatorial PBO 方法：

1. 生成 N 个随机参数组合（如 1000 组）
2. 对整个回测期做 N 次回测，得到绩效分布
3. 将回测期随机分成 S 个等长子集（如 S=16 季度）
4. 对每个子集组合（共 C(S, S/2) 种），计算该子集的最优参数
5. 统计"在一个子集上最优的参数，在互补子集上表现低于中位数的比例"

PBO < 0.1：低过拟合风险
PBO 0.1-0.3：中等风险，需警惕
PBO > 0.3：高过拟合风险，策略不可信

#### 蒙特卡洛模拟

对最优策略参数做蒙特卡洛模拟：

- 对历史日收益序列做 Bootstrap 重采样（1000 次）
- 每次生成一条合成净值曲线
- 输出：置信区间（5%/50%/95% 分位净值曲线）、最差情景、VaR

## 六、技术决策与约束

### 6.1 语言与框架

- 后端：Python 3.11+（与现有项目一致）
- 回测引擎核心：纯 Python（无 C++ 依赖，保持可维护性）
- 数据处理：pandas + numpy
- 优化：scikit-optimize（贝叶斯优化）
- 前端：React 18 + TypeScript + ECharts（与现有项目一致）

### 6.2 性能约束

- 单策略 2 年回测（约 480 个交易日）耗时 < 30 秒
- 12 策略联合回测耗时 < 5 分钟
- 参数优化（1000 组参数）耗时 < 2 小时（可后台异步运行）
- 数据库快照存储：约 480 × 5000 行 × 200 bytes ≈ 480 MB/年，可接受

### 6.3 与现有系统的边界

- **不复用**：不回测 paper trading 的实时线程（scheduler.py），回测是完全独立的离线仿真
- **复用**：paper 的 matching engine + fees + position lot 逻辑
- **复用**：low_buy 的策略筛选管线（screening / candidate / prefilter / scoring / signal）
- **不修改**：现有的 `performance.py` 复盘统计保持不变，回测引擎是新增能力
- **数据隔离**：回测订单/交易/快照存在独立表中，不污染 paper trading 数据

### 6.4 PIT 数据的取舍

在 Phase 1，为降低复杂度，做以下简化：

- **日线数据**：直接使用 `daily_bar_snapshots` 表（该表本身就是按交易日存储的，天然支持 PIT）
- **涨停池**：Phase 1 不做 PIT 快照，直接复用 pool.py 的 board candidate 逻辑（从日线数据推断涨停）。Phase 3 再引入 akshare 历史涨停池回填
- **行业分类**：使用最新分类（偏差可控）
- **市场状态**：回测时实时计算（纯计算，无前视偏差风险）

这保证了 Phase 1 可以快速交付核心回测能力，PIT 的彻底化在后续版本中逐步完善。

## 八、风险与注意事项

1. **数据质量**：如果日线数据有缺失或复权错误，回测结果将失真。建议 Phase 1 先验证 2025 年数据完整性。
2. **策略管线兼容性**：确保策略筛选管线在 PIT 数据上运行结果与实时一致。关键风险点：`pool.py` 的 `_build_retracement_buckets` 依赖 `latest_trade_date`，回测中该值等于当前模拟日期。
3. **性能瓶颈**：12 策略联合回测在每个交易日运行 12 次完整筛选管线，480 天 × 12 = 5760 次筛选。需确保每次筛选在 100ms 内完成。
4. **过拟合陷阱**：参数优化结果在样本外可能完全失效。Walk-Forward 验证和 PBO 测试不是可选的附加功能，是必须使用的防护机制。

## 附录 A：与 qlib 的关系

qlib（微软）是一个成熟的 AI 量化框架，提供标准化的 PIT 数据管理 + 事件驱动回测 + 因子研究工具链。TQuant 的回测引擎设计上参考了 qlib 的架构，但做了以下取舍：

| 维度 | qlib | TQuant 回测引擎 |
|------|------|----------------|
| 数据格式 | 自定义二进制格式 | SQLite/PostgreSQL（复用现有） |
| 策略定义 | qlib Model/Signal 范式 | 复用现有 12 策略管线 |
| 回测引擎 | C++ 优化，高性能 | Python，可维护性优先 |
| 因子研究 | 完整的 FactorOps 工具链 | 不在 Phase 1 范围 |
| 集成方式 | 独立运行 | 作为 TQuant 后端服务的一部分 |

TQuant 回测引擎不替代 qlib，而是与其互补：
- **短周期快速验证**：用 TQuant 回测引擎，API 调用即可，无需导出数据
- **深度因子研究**：导出数据到 qlib，利用其因子计算、IC 分析、模型训练能力
- **交叉验证**：同一策略在两边回测，结果互相校验

`research/data_sync/tquant_to_qlib.py` 已经实现了 TQuant → qlib 的数据导出，Phase 4 将增强这一通道。
