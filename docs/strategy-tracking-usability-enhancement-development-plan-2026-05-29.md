# 策略跟踪易用性增强开发文档

## 1. 背景

当前 `/strategy-tracking` 已具备策略复盘、失败归因、市场状态分层、Shadow 观测、防未来函数审计、持有期优化等能力，但页面面向的是有交易经验的用户。对无金融基础用户来说，仍存在以下问题：

1. 专业术语较多，如回撤、Shadow、未来函数、后验收益、持有桶。
2. 主表信息密度高，但结论不够突出。
3. 用户无法快速判断一只推荐票是否值得继续看。
4. 不能直接看到股票属于哪些板块。
5. 无法一键过滤创业板、科创板等高波动标的。
6. 每个策略推荐的股票最适合持有多久，缺少直观统计。

本轮目标是增强策略跟踪的可读性和决策辅助能力，使普通用户能在 30 秒内看懂推荐结果。

## 2. 开发目标

### 2.1 产品目标

将策略跟踪从“专业复盘数据表”升级为“推荐结果追踪看板”。

页面应优先回答：

1. 这只票现在是否值得继续看。
2. 这只票是否已经到达计划买点。
3. 推荐后最多涨过多少，最多跌过多少。
4. 是否已经跌破风险线。
5. 盈利是短线冲高，还是有继续持有价值。
6. 这只票属于哪些板块。
7. 当前是否应该屏蔽创业板、科创板等高波动标的。
8. 每个策略更适合短线、波段还是中长线观察。

### 2.2 工程目标

1. 只优化策略跟踪展示和只读统计，不改变策略推荐、排序、风控、模拟盘和真实交易链路。
2. 保留现有专业能力，但默认隐藏复杂审计字段。
3. 新增筛选和统计必须由后端聚合，前端只展示。
4. 继续保持列表后端分页、详情懒加载、React Query 缓存。
5. 不引入大体积新依赖。

## 3. 用户分层

### 3.1 小白用户

默认视角。只关心：

- 哪些票可以重点看。
- 哪些票还没到买点。
- 哪些票已经走弱。
- 哪些票数据异常。
- 适合拿几天。
- 是否需要避开创业板、科创板。

### 3.2 专业用户

可切换专业模式，继续查看：

- Shadow 观测状态。
- 防未来函数审计字段。
- 数据截止时间。
- 回看窗口。
- 后验收益计算起点。
- 策略健康度详细指标。
- 异常收益复核原因。

## 4. 设计原则

### 4.1 结论优先

首屏必须先给结论，不先堆指标。

示例：

```text
近 7 日共有 18 条推荐，其中 7 条到达计划买点，3 条触发止损，2 条收益异常需复核。当前更适合先看“已到买点”和“风险样本”。
```

### 4.2 普通语言替代专业术语

| 专业术语 | 页面默认文案 |
| --- | --- |
| 买点触达 | 已到计划买入区 |
| 未触达 | 还没到计划买入价 |
| 止损 | 已跌破风险线 |
| 最大回撤 | 推荐后最多跌过 |
| 最大涨幅 | 推荐后最多涨过 |
| 当前收益 | 现在涨跌 |
| 冲高回落 | 曾经涨过，但后来明显回落 |
| 异常收益 | 收益过高，需要核对数据 |
| Shadow 为 0 | 模型没有留下观察记录 |
| 防未来函数审计 | 数据时间检查 |

### 4.3 渐进披露

默认只展示用户能直接理解的信息，专业字段进入折叠区或专业模式。

### 4.4 只读边界

所有新增功能只做展示、筛选、复盘、统计，不得自动影响：

- 策略排序。
- 生产推荐。
- 模拟盘交易。
- 真实交易。
- 风控阈值。

## 5. 信息架构

### 5.1 页面结构

建议结构：

1. 顶部一句话结论。
2. 状态总览卡。
3. 小白模式 / 专业模式切换。
4. 简化筛选区。
5. 主表。
6. 持有分析 tab。
7. 复盘诊断 tab。
8. 专业审计折叠区。
9. 单票详情抽屉。

### 5.2 首屏状态卡

新增 4 个状态卡：

| 卡片 | 说明 |
| --- | --- |
| 可以重点看 | 已到买点、未止损、数据质量正常 |
| 还没到价 | 推荐了，但还没到计划买点 |
| 已经走弱 | 跌破止损或跌破支撑 |
| 需要复核 | 数据不足、收益异常、Shadow 无样本、审计异常 |

每个卡片展示：

- 样本数。
- 占比。
- 一句解释。
- 点击后切换筛选。

## 6. 主表改版

### 6.1 默认列

主表默认列调整为：

| 列名 | 内容 |
| --- | --- |
| 股票 / 板块 | 股票名、代码、所属板块、市场板类型 |
| 当前结论 | 值得看、等买点、已走弱、需复核 |
| 推荐计划 | 买点、止损、目标价 |
| 推荐后表现 | 最高涨幅、最大下跌、现在涨跌 |
| 适合持有 | 短线、波段、中长线观察、不适合延长 |
| 为什么 | 失败归因、冲高回落、数据异常、板块退潮 |

### 6.2 股票 / 板块列

展示示例：

```text
宁德时代
300750
新能源车 / 锂电池 / 创业板
```

规则：

1. 股票名第一行。
2. 股票代码第二行。
3. 板块标签第三行。
4. 最多展示 3 个主要板块。
5. 超过 3 个显示 `+N`，hover 或详情中展开。
6. 创业板和科创板必须明确标识。

板块优先级：

1. 市场板类型：主板、创业板、科创板、北交所。
2. 申万行业或中信行业。
3. 热点概念板块。
4. 自定义策略板块标签。

### 6.3 当前结论列

结论枚举：

| 状态 | 文案 | 颜色 |
| --- | --- | --- |
| focus | 值得重点看 | 绿色 |
| wait_entry | 等计划买点 | 黄色 |
| weakening | 已经走弱 | 红色 |
| take_profit_watch | 冲高后观察 | 蓝色 |
| review_needed | 需要复核 | 橙色 |
| data_missing | 数据不足 | 灰色 |

### 6.4 推荐后表现列

默认展示：

```text
最高涨过 +8.4%
最多跌过 -2.1%
现在 +3.2%
```

避免默认展示 `max_gain_pct`、`max_drawdown_pct` 等字段名。

### 6.5 适合持有列

展示：

```text
更适合：短线 1-3 天
最优：2 天
```

或：

```text
可转波段观察
利润垫：8.2%
```

或：

```text
不适合延长
原因：回撤过大
```

## 7. 筛选改版

### 7.1 简化筛选

默认只展示：

1. 时间范围。
2. 当前结论。
3. 策略。
4. 风险偏好。

其他筛选放入“更多筛选”。

### 7.2 一键屏蔽创业板和科创板

新增风险偏好区：

```text
风险偏好：
[x] 屏蔽创业板
[x] 屏蔽科创板
[ ] 只看主板
```

默认策略：

- 小白模式默认开启 `屏蔽创业板` 和 `屏蔽科创板`。
- 专业模式默认不过滤。
- 用户手动修改后本地持久化到 store/localStorage。

### 7.3 筛选提示

当过滤生效时，页面顶部显示：

```text
已隐藏创业板、科创板股票，仅展示主板或低波动样本。
```

### 7.4 筛选参数

后端支持参数：

```text
exclude_chinext=true
exclude_star=true
board_filter=main_only | include_all | exclude_chinext | exclude_star
```

建议优先实现：

- `exclude_chinext`
- `exclude_star`

如后续有北交所过滤，再增加：

- `exclude_bse`

## 8. 单票详情改版

### 8.1 详情首屏

详情首屏必须展示：

1. 当前结论。
2. 推荐计划。
3. 实际结果。
4. 持有建议。

示例：

```text
结论：这条推荐更像短线冲高，不建议无条件转中长线。

推荐计划：
推荐价 10.20，计划买点 9.80 - 10.10，风险线 9.40，目标价 11.20。

实际结果：
推荐后最高涨过 +8.4%，最多跌过 -2.1%，没有跌破风险线。

持有建议：
最优持有 2 天，之后利润回吐明显。
```

### 8.2 时间线

详情中新增“推荐后发生了什么”时间线：

1. 推荐日。
2. 到达计划买点。
3. 实际最高点。
4. 冲高回落。
5. 跌破风险线。
6. 信号失效。
7. 最优退出点。

### 8.3 板块详情

详情中展示完整板块：

- 市场板：主板 / 创业板 / 科创板 / 北交所。
- 行业板块。
- 概念板块。
- 板块状态：主升 / 退潮 / 震荡 / 数据不足。

### 8.4 专业审计折叠区

默认折叠：

- Shadow 观测。
- 数据截止时间。
- 回看窗口。
- 后验收益起点。
- 数据源。
- 异常收益审计。

## 9. 持有期分析

### 9.1 新增 tab

新增 tab：`持有分析`

位置建议在 `策略表现` 与 `复盘诊断` 之间。

### 9.2 目标

回答：

1. 每个策略推荐的票通常适合持有几天。
2. 哪些策略更适合短线冲高止盈。
3. 哪些策略可转波段观察。
4. 哪些策略不适合延长持有。

### 9.3 策略持有期统计字段

后端按策略聚合输出：

```json
{
  "strategy_key": "first_board",
  "strategy_name": "首板回调",
  "sample_count": 24,
  "avg_best_holding_days": 2.4,
  "median_best_holding_days": 2,
  "dominant_holding_bucket": "short_1_3d",
  "dominant_holding_bucket_text": "短线 1-3 天",
  "short_hold_ratio": 66.7,
  "swing_hold_ratio": 20.8,
  "trend_hold_ratio": 8.3,
  "midlong_hold_ratio": 4.2,
  "avg_best_exit_return_pct": 6.8,
  "avg_best_exit_drawdown_pct": -2.1,
  "avg_giveback_from_peak_pct": 18.5,
  "extension_qualified_ratio": 16.7,
  "conclusion": "更适合短线 1-3 天，冲高后应及时复盘止盈。"
}
```

### 9.4 持有桶定义

| 值 | 文案 | 说明 |
| --- | --- | --- |
| short_1_3d | 短线 1-3 天 | 推荐后 1 到 3 个交易日达到较优收益 |
| swing_4_10d | 波段 4-10 天 | 有利润垫且回撤可控 |
| trend_11_20d | 趋势 11-20 天 | 持续走强但需要跟踪支撑 |
| midlong_20d_plus | 中长线观察 | 只作为观察，不作为自动持有建议 |
| unsuitable | 不适合延长 | 回撤或利润回吐过大 |
| unavailable | 样本不足 | 数据不足或样本不足 |

### 9.5 页面展示

卡片示例：

```text
首板回调
更适合：短线 1-3 天
平均最优持有：2.4 天
平均最高收益：+6.8%
平均承受回撤：-2.1%
结论：多数样本在 3 天内冲高，后续利润回吐较明显。
```

```text
龙头回踩波段
更适合：波段 4-10 天
平均最优持有：6.8 天
可延长样本：42%
结论：有利润垫且板块仍强时，可以转波段观察。
```

### 9.6 图表建议

不引入新大型图表库。优先使用现有表格、Tag、进度条和轻量条形图。

建议展示：

1. 横向条形图：短线 / 波段 / 趋势 / 中长线占比。
2. 策略排名表：按平均最优持有天数排序。
3. 风险提示：利润回吐过高、样本不足、止损率偏高。

1. 已有 instrument metadata。

4. 缺失时返回 `[]`，前端显示 `板块数据不足`，不能阻塞列表。

规则应集中在 helper 中，不要散落在前端。

## 12. 防未来函数和过拟合边界

### 12.1 持有期统计边界

1. 最优持有天数属于后验复盘指标。
2. 不允许用于反推推荐当天信号。
3. 不允许自动影响策略排序。
4. 不允许自动进入模拟盘或真实交易。
5. 短线转波段/中长线观察资格只能使用推荐日及以前可见的趋势、板块状态、风险状态。

### 12.2 板块过滤边界

屏蔽创业板和科创板只影响页面展示，不影响：

- 后端生产推荐生成。
- 策略候选池。
- 回测口径。
- 模拟盘账本。

### 12.3 统计口径

持有分析必须按同一时间窗口计算，不能混合不同窗口。

例如：

- 近 7 日。
- 近 30 日。
- 近 60 日。

同一页面中的样本数、最佳持有天数、止损率、回撤统计必须来自同一个 `range`。

5. 主表展示“最高涨过 / 最多跌过 / 现在涨跌”。
6. 持有分析 tab 展示策略持有结论。
7. 单票详情展示完整板块和持有建议。
8. 数据缺失时不白屏。

### 13.3 Go 测试

如果 Go BFF 透传策略跟踪聚合接口，需要覆盖：

1. `exclude_chinext`、`exclude_star` 参数透传。
2. `holding-analysis` 聚合响应透传。
3. upstream 超时时 partial response 不阻塞主页面。

### 13.4 性能测试

验证：

1. 列表仍后端分页。
2. 持有分析后端聚合。
3. 前端不一次性拉取全量历史。
4. 单票详情仍懒加载。
5. 新增 tab 不在首屏加载大数据。
6. 前端 build chunk 无明显膨胀。

## 14. 验收标准

### 14.1 用户体验验收

1. 无金融基础用户能在 30 秒内判断哪些票值得看。
2. 用户能直接看到股票属于哪些板块。
3. 用户能一键隐藏创业板、科创板。
4. 用户能看懂“为什么没买入”“为什么亏损”“为什么收益异常”。
5. 用户能知道每个策略通常适合持有几天。
6. 用户能区分短线冲高、波段观察和不适合延长持有。

### 14.2 工程验收

1. 不改变生产策略推荐、排序、风控、回测、模拟盘账本。
2. 新增接口只读。
3. 后端相关 pytest 通过。
4. 前端 test/lint/build 通过。
5. Go 相关测试通过或说明未改 Go 路径。
6. Rust 测试通过或说明未改 Rust 路径。
7. `git diff --check` 通过。

### 14.3 文案验收

不能默认展示难懂字段名：

- `max_drawdown_pct`
- `posterior_start_date`
- `future_leak_check`
- `holding_bucket`
- `shadow_observation`

普通模式必须转换为自然语言。
