### 2.1 Resolver 边界：严格不入纯函数

**根本原则**：`strategy_policy.py` 中 14 个函数全部不修改。它们是纯函数，没有 DB session，不能引入隐式数据库访问。

**StrategyTierResolver 使用位置**（仅在有 DB session 的上下文中）：

|---|------|------|---------|------|------|

| 2 | `base_strategy.py` | 86 | `participates_in_priority_board(self.key)` | `resolver.resolve(self.key) in {CORE, AUXILIARY}` | 有 `self._db` |

### 2.2 策略元数据新字段：四个落点

新增字段必须同时出现在四个位置：

```python
# 字段定义
enabled: bool = True          # 是否启用（flag 关闭 → false）
probe_status: str = "not_required"  # "not_required" | "pending" | "passed" | "failed"
probe_summary: str = ""       # 探针失败原因（前端展示用）
visibility: str = "full"      # "full" | "backtest_only" | "hidden"
```

| 落点 | 文件 | 形式 |
|------|------|------|
| **SQLAlchemy model** | `backend/app/models/market_entities.py`（或 strategy_metadata 表对应 model） | 新增 4 列 `enabled(Boolean)`, `probe_status(String(20))`, `probe_summary(Text)`, `visibility(String(20))` |
| **Pydantic response** | `backend/app/models/schema_defs/screener.py` 中的策略元数据 schema | 新增 4 字段（含默认值） |
| **Alembic migration** | `backend/alembic/versions/20260506_v7_workbench.py` | `op.add_column("strategy_metadata", ...)` |
| **前端 generated fallback** | `frontend/src/generated/strategyMetaFallback.ts` | `scripts/sync_strategy_meta_fallback.py` 输出时包含 4 字段 |

**现有 5 个策略默认值**：`enabled=true, probe_status="not_required", visibility="full"`。

**新策略初始值**：`ma_channel_band`: `enabled=true, probe_status="not_required", visibility="full"`。`leader_pullback_band`: `enabled=true, probe_status="pending"（探针前）/ "passed" 或 "failed"（探针后）, visibility="full"（passed）或 "backtest_only"（failed）`。

### 2.3 展示规则：按 visibility 过滤

| 消费端 | 过滤逻辑 | 展示效果 |
|-------|---------|---------|
| **Playbook research tabs** | `visibility === "full"` | 仅展示 full 策略 |
| **优先榜** | `visibility === "full"` + tier in {CORE, AUXILIARY} | 仅展示 full 的生产层策略 |
| **策略工作台回测选择器** | `visibility !== "hidden"` | backtest_only 策略可选中，但策略卡片上显示 badge"仅回测研究" |
| **App low-buy** | `visibility === "full"` | 仅 full 策略可选 |
| **策略列表 /api/strategies/meta** | 全部返回 | 每条记录含 visibility 字段，前端自行过滤 |

### 2.4 Feature flag 权限与隔离

| 操作 | 权限 | 存储 | 审计 |
|------|------|------|------|
| `GET /api/settings/feature-flags` | 登录用户 | 读 `system_settings`（key 前缀 `ff_`） | 无 |
| `PUT /api/settings/feature-flags/{key}` | `require_admin_auth` | 写 `system_settings`（key 前缀 `ff_`） | 写 `feature_flag_audit_log` 表 |
| `GET /api/settings`（普通 settings 接口） | admin | — | 查询 **排除** `ff_` 前缀行 |
| `GET /api/settings`（系统 settings query） | admin | — | 查询 **排除** `ff_` 前缀行 |

**隔离实现**：所有读取 `system_settings` 的查询（非 feature-flags endpoint）添加 `WHERE key NOT LIKE 'ff\_%'`。

### 2.5 费用示例：基于真实 `calculate_fee()` 验证

`paper/fees.py` 实际费率：
- 佣金：`max(gross * 0.00025, 5.00)` — 最低 5 元
- 印花税：`gross * 0.0005`（仅卖出，ETF 免）
- 过户费：`gross * 0.00001`（ETF 免）

**验收用固定用例**：

| # | 场景 | 参数 | 买入费 | 卖出费 | 往返费 | 费率占比 |

| 2 | ETF | `510300`, price=4, qty=1000 | 5.00 | 5.00 | 10.00 | 0.25% |
| 3 | 小单最低佣金 | `600036`, price=10, qty=100 | 5.01 | 5.51 | 10.52 | 1.05% |
| 4 | 大单 | `600036`, price=40, qty=10000 | 100.00 | 300.00 | 400.00 | 0.10% |
| 5 | 零价 | price=0 | 0 | 0 | 0 | — |
| 6 | 负价 | price=-10 | 0 | 0 | 0 | — |
