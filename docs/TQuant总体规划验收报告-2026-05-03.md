## 二、按领域汇总

### 安全（Phase 0）：满分

5 项 P0 安全问题全部修复：
- `auth_secret_key` 空值启动拒绝 ✅
- settings 密钥脱敏（`********` 替换）✅
- 4 个路由模块统一鉴权 ✅
- admin token 空值拒接 ✅
- Agent 写工具默认关闭 ✅

12+ 个安全测试持续锁定这些边界。安全已不再是 P0 风险。

### 策略体系：B+（基础扎实，执行治理缺失）

**做得好的：**
- 21 个因子全有 status/stub/experimental 标记，前端彩色展示
- 70+ 魔法数字集中到 `LowBuyThresholds` 数据类
- 8 态市场分类器 + 6 类映射落地，信号附带市场快照
- 策略健康评分公式完整（5 维度 + 2 惩罚项）
- 3 个策略有独立治理文档

**缺口：**
- 健康评分只计算不执行 — 无自动降权触发器
- 策略 × 市场状态交叉绩效矩阵未在前端可视化
- 10 种标准化退出原因未以枚举落地
- 市场分类中文标签与计划不完全对齐

### 模拟盘：C+（核心稳固，深度改进滞后）

**做得好的：**
- 撮合/费用/持仓模块 Decimal 全覆盖
- 停牌阻断三处检查，涨跌停阻断逻辑存在
- 小额佣金警告后端逻辑存在（阈值偏保守 1%/3% vs 计划 0.5%/1%）
- entry_reason/exit_reason 字段存在且前端展示

**缺口：**
- **并发保护缺失** — 余额检查和扣减非原子化，无行锁
- **Decimal 边界泄漏** — sizing/scheduler/performance 层大量 float
- **max_drawdown 从不计算** — 熔断器形同虚设
- T+0 豁免规则未接入模拟盘引擎
- 前端不显示费用警告

### 前端：B-（安全补齐，架构解耦未完成）

**做得好的：**
- PageErrorBoundary 包裹全部 7 个页面
- Loading 状态已结构化为 `Record<string, boolean>`
- entry_reason/exit_reason 已在前端展示
- 因子状态彩色徽章已落地

**缺口：**
- TradingWorkspace 798 行，仅提取 2/6 个 Hook
- **零 useCallback** — 所有 handler 每次 render 重建
- **CSS 未拆分** — 仍为单文件 3493 行
- 数据质量无红绿灯可视化（仅文字）

### Agent：B（边界清晰，交互层简陋）

**做得好的：**
- 10 个工具全部有限流窗口（3-60/min）
- 写工具默认关闭 + 策略强制执行
- Hermes 边界无违反（不直接触 DB/Shell/交易）
- 审计追踪 + 参数脱敏完善

**缺口：**
- **飞书交互卡零实现** — 所有输出纯文本，无按钮/表单/卡片
- 5/8 个 Provider 为骨架存根（2 行子类）
- ratings 限流值不完全匹配计划

### 数据层：B+（质量标签落地，写入优化滞后）

**做得好的：**
- `DataQualitySnapshot` 五级质量系统全覆盖
- 异常快照阻断管道已存在
- 限流器已完全脱离 SQLite 迁移到内存
- 任务可观测性 7 个字段全部记录

**缺口：**
- 所有 upsert 仍为逐行操作，无批量 SQL
- `rows_processed` 字段声明但从未写入
- 无统计异常检测（零价/零量仅基础检查）

## 三、关键未达标项及建议

### P1 — 应在本迭代修复

| # | 事项 | 影响 | 建议方案 |
|---|------|------|----------|
| 1 | **模拟盘并发保护** | 多请求/自动交易并发时可超额下单 | `account.py` 加 `threading.Lock`（账户级）；余额检查与扣减合并在同一事务 |
| 2 | **max_drawdown 计算** | 熔断器不生效 | `performance.py` 或独立定时任务计算实际最大回撤并写回 `PaperAccount.max_drawdown_pct` |
| 3 | **退出原因枚举化** | 绩效归因混乱 | 建立 `ExitReason` 枚举（10 类），`order.py`/`scheduler.py`/`execution_simulation.py` 统一使用 |
| 4 | **飞书交互卡片** | 用户操作体验差 | 至少实现信号卡片（含 [执行] [跳过] 按钮）和日报卡片 |
| 5 | **策略自动降权** | 健康评分无实际约束力 | 添加定时任务：连续 N 笔亏损/月度回撤超标 → 自动将策略设为 `watch` 或 `paused` |

## 四、总体评价

| 维度 | 评分 | 评语 |
|------|------|------|
| 安全合规 | A | 5 项 P0 全部关闭，12+ 测试锁定 |
| 策略体系 | B+ | 治理框架完整，自动执行缺位 |
| 模拟盘 | C+ | 撮合稳健，并发/精度/归因需补齐 |
| 前端架构 | B- | 安全短板补齐，解耦未完 |
| Agent 系统 | B | 边界安全，交互层简陋 |
| 数据质量 | B+ | 标签系统落地，写入未优化 |
| **综合** | **B** | **"可信度治理"框架已成，执行层面待贯通** |

总体规划中"安全闭环"已基本完成。"数据质量闭环"框架已搭建。"策略归因闭环"后端数据已有但前端展示和自动执行缺失。"模拟交易可信闭环"仍有 Decimal/并发/归因三项缺口。"Agent 权限闭环"边界约束到位但交互卡片零落地。

**下一迭代建议聚焦**：并发保护 → 退出原因枚举化 → 策略自动降权 → 飞书卡片。这四项补齐后，平台可信度将发生质变。
