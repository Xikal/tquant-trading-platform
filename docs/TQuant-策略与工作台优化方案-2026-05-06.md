## 一、做 T 信号优化 — 提高信号频率和精准度

### 1.1 当前信号稀疏的根因（按影响排序）

经过对信号管线 8 个文件的完整审查，做 T 信号稀疏的主要根因如下：

**根因 1 — 日均成交额 8,000 万门槛过滤了大部分中小盘股**

`hard_risk.py:83-84`：`amount < 80_000_000` 直接返回 `hard_block`。A 股约 40% 的股票日均成交额低于 8,000 万，这些股票永远不会产生信号。对于做 T 场景——用户通常持有特定的中小盘标的——这个全局一刀切的过滤会直接导致持仓标的无信号。

**根因 2 — 打分阈值叠加降级惩罚后实际上移 10-20 分**

`signal_thresholds.py` 的 soft_buy_min_score 范围是 84-94。同时 `hard_risk.py` 的降级惩罚最多可叠加 17.5 分（成交量 + 分布风险 + 量价异常 + 趋势），加上 `degrade` 风险等级额外 +3.0，再加上动态调整的 `floor_shift`（最多 +5.0）。一个实际打分 82 分的候选，有效阈值可能变成 82 + 17.5 + 3 + 5 = 需要 107.5 分才能通过——实际不可能。

**根因 3 — 成交量骤缩的前置过滤过于严格**

`candidate_rules.py` 中各策略的 `volume_burst_ratio` 门槛：
- `volume_shrink`: >= 1.65（成交量需是前 20 日均值的 1.65 倍以上才进入候选池）
- `classic_retrace`: >= 1.05
- `first_board`: >= 1.25

做 T 场景中，持仓股通常经过了首轮放量（已经持有），当前可能处于缩量回调阶段。前置的放量检测会过滤掉缩量回调中的做 T 机会——这正是做 T 最应该捕捉的时机。

**根因 4 — 反弹比 0.26 的门槛在盘中波动时过于严格**

`signal_resolution.py:58`：`rebound_ratio < 0.26` 拒绝信号。一只股票盘中跌 3% 后反弹 0.7%（ratio = 0.23），被拒绝。但对于做 T，0.7% 的反弹已经足够覆盖交易成本并产生正收益。

**根因 5 — 日内每分钟确认窗口太窄**

`signal_resolution.py:77`：只检查最近 5 根分钟线。如果第 6 根才出现 VWAP 回收确认，信号被拒绝。对于波动剧烈的早盘，5 根分钟线（5 分钟）的确认窗口不足以判断趋势稳定。

**根因 6 — 止损线上方 0.3% 即判"below_stop"**

`signal_entry.py:9`：`latest_price <= stop_loss * 1.003`（0.3% above stop loss）即判为 `below_stop`。一只股票的止损价 10.00，当前价 10.03，被判为"跌破止损"——实际上还有 0.3% 的安全边际。

**根因 7 — 未考虑手续费对盈利点位的侵蚀**

`fees.py` 定义了完整的 A 股费用模型：佣金 0.025%（最低 5 元/笔）、印花税 0.05%（仅卖出）、过户费 0.001%。关键问题是 **5 元最低佣金**对中小仓位的冲击极大：

| 单笔成交金额 | 单边佣金 | 双边佣金 | 印花税(卖) | 双边过户费 | 往返总费用 | 费用率 |
|------------|---------|---------|-----------|-----------|-----------|--------|
| 2,000 元 | 5.00（最低）| 10.00 | 1.00 | 0.04 | **11.04** | **0.55%** |
| 5,000 元 | 5.00（最低）| 10.00 | 2.50 | 0.10 | **12.60** | **0.25%** |
| 10,000 元 | 5.00（最低）| 10.00 | 5.00 | 0.20 | **15.20** | **0.15%** |
| 20,000 元 | 5.00 | 10.00 | 10.00 | 0.40 | 20.40 | 0.10% |
| 50,000 元 | 12.50 | 25.00 | 25.00 | 1.00 | 51.00 | 0.10% |

当前策略设定的止盈目标是 `max(board_high, recent_swing_high) * 1.01`（约 1%），但做 T 场景中：

- 用户持有 10,000 元的某标的，做一笔正 T（先买 5,000 元再当天卖出），往返费用约 12.60 元，占买入金额的 **0.25%**
- 如果该标的当天只涨了 0.5%，用户期望盈利 25 元，实际到手 25 - 12.60 = 12.40 元，净利率仅 0.25%
- 如果该标的当天只涨了 0.2%，用户期望盈利 10 元，实际到手 10 - 12.60 = **亏损 2.60 元**
- **当前系统完全不考虑手续费对盈利的影响**，会导致用户做了信号正确但净亏损的交易

此外，回测引擎使用硬编码的 `ROUND_TRIP_COST_BPS = 16.0`（`execution_simulation.py:9`），这个值对做 T 场景偏保守——实际做 T 的往返费用率因仓位大小差异极大（0.10%-0.55%）。

### 1.2 优化方案（分阶段）

#### 阶段 A: 即时生效的参数调优（0.5 天，无代码风险）

| 调整项 | 当前值 | 建议值 | 预期效果 |
|--------|--------|--------|---------|
| 日均成交额硬阻断门槛 | 8,000 万 | 分策略：核心策略 5,000 万，辅助策略 3,000 万，做 T 专用 2,000 万 | 信号覆盖率 +60% |
| 反弹比门槛 | 0.26 | 0.18（盘中）/ 0.22（尾盘） | 盘中信号 +30% |
| 分钟线确认窗口 | 5 根 | 8 根 | 减少误拒绝 20% |
| below_stop 缓冲带 | 1.003 | 1.008（0.8% 缓冲） | 减少误判 15% |
| `change_pct` 跌幅上限 | -5.8% | -7.2%（允许更深的回调） | 深回调机会覆盖 |
| `distribution_risk_score` 阻断线 | >= 7.0 | >= 8.0 | 减少分布风险阻断 |

#### 阶段 B: 增加"做 T 专用"信号管线（2-3 天）

当前做 T 信号完全依赖低吸管线（LowBuy Pipeline），该管线为"寻找新入场机会"而设计。做 T（对已持仓标的寻找波段操作机会）需要独立的判断逻辑。

**新增模块: `services/low_buy/signal_t_operation.py`**

独立于低吸候选评分，基于持仓标的的实时行情计算做 T 信号：

```
做 T 信号判断流程（独立于 LowBuy Pipeline）:

Step 1: 日线结构判断
  - MA5 > MA10 > MA20？→ 上升趋势，适合正 T（先买后卖）
  - MA5 < MA10 < MA20？→ 下降趋势，适合反 T（先卖后买）
  - 均线缠绕？→ 震荡，观望

Step 2: 日内位置判断
  - 对于正 T: 当前价是否在日均价下方 0.5%-2% 区间？→ 是 → 候选
  - 对于反 T: 当前价是否在日均价上方 0.5%-2% 区间？→ 是 → 候选

Step 3: 量能确认
  - 当前分钟量 > 前 5 分钟均值 × 1.3 → 有放量迹象
  - 或者 当前分钟量 < 前 5 分钟均值 × 0.7 → 缩量筑底

Step 4: 弹性确认
  - 最近 10 日内至少有 2 次"跌 2%+ 后当日或次日收回 1%+"→ 标的有弹性，适合做 T
  - 若无弹性 → 降级为"仅观察"

Step 5: 手续费校验（新增 — 确保做 T 有利可图）
  - 根据当前价、计划买入数量计算单边成交金额
  - 查 `fees.py` 费率表计算往返总费用（佣金最低 5 元 + 印花税 0.05% 卖出 + 过户费 0.001%）
  - 计算盈亏平衡点：`breakeven_pct = 往返总费用 / 买入金额`
  - 预期盈利空间：`expected_profit_pct = (take_profit - entry_price) / entry_price`
  - 净盈利 = expected_profit_pct - breakeven_pct - 滑点(0.05%)
  - 如果净盈利 < 0.30% → 降级为"费用不划算，建议增加仓位或等待更大波动"
  - 如果净盈利 < 0（费用高于预期收益）→ 不产生做 T 信号，提示"当前波动不足以覆盖手续费"

Step 6: 输出
  - direction: "正T" | "反T" | "观望"
  - entry_price: 建议入场价
  - stop_loss: 日内止损（入场价 × 0.985，含费用缓冲）
  - take_profit: 日内止盈（入场价 × 1.015）
  - position_size: 建议买入股数（>= 100 的整数倍）
  - estimated_fee: 预估往返费用（元）
  - net_profit_pct: 扣除费用后的预期净利率
  - confidence: 0-100（基于弹性、量能、位置、费用覆盖的加权）
  - warning: 如果仓位太小导致费用率 > 0.3%，提示"建议增加操作股数以降低手续费占比"
```

**关键区别**：做 T 信号管线不使用 LowBuy 的打分体系，不使用成交量骤缩前置过滤，不使用 8,000 万成交额门槛。它只需要判断"当前持仓标的是否有日内波段操作空间"。

#### 阶段 C: 增加持仓弹性指标追踪（1 天）

在做 T 信号中增加"弹性评分"：

1. 计算最近 20 个交易日内，"盘中跌 >1.5% 后当日或次日反弹超过跌幅 60%"的次数
2. 弹性次数 >= 3：高弹性，适合做 T
3. 弹性次数 1-2：中等弹性，做 T 需谨慎
4. 弹性次数 0：不适合做 T，信号自动降级为"观望"

弹性追踪结果缓存到 `WatchlistSignalSnapshot` 或新建 `TradingElasticityCache` 表。

#### 阶段 D: 手续费感知的盈利点位计算（已融入阶段 B 的 Step 5-6）

做 T 信号必须回答一个核心问题：**这笔操作扣除手续费后是否有利可图？**

**当前系统的问题**：策略止盈目标（+1%）和止损目标（-1.2%）完全不考虑手续费。用户收到信号后操作，可能信号方向正确但净亏损。

**手续费模型**（基于 `fees.py` 实测）：

```
买入费用 = max(成交金额 × 0.025%, 5元) + 成交金额 × 0.001%
卖出费用 = max(成交金额 × 0.025%, 5元) + 成交金额 × 0.05% + 成交金额 × 0.001%

往返总费用 = 买入费用 + 卖出费用
```

**关键发现 — 5 元最低佣金是小仓位的杀手**：

| 单笔买入金额 | 往返费用 | 费用率 | 做 T 是否划算 |
|------------|---------|--------|-------------|
| 2,000 元（200 股 × 10 元） | ~11.04 元 | **0.55%** | ❌ 需要涨 0.55% 才回本，日内波动很难达到 |
| 5,000 元（500 股 × 10 元） | ~12.60 元 | **0.25%** | ⚠️ 加上 0.05% 滑点，需涨 0.30% 才回本 |
| 10,000 元（1000 股 × 10 元） | ~15.20 元 | **0.15%** | ✅ 涨 0.20% 即可覆盖费用 |
| 20,000 元（2000 股 × 10 元） | ~20.40 元 | **0.10%** | ✅ 费用占比合理 |
| 50,000 元（5000 股 × 10 元） | ~51.00 元 | **0.10%** | ✅ 但仓位偏大 |

**做 T 信号中的手续费感知规则**：

```
规则 1: 最小仓位门槛
  如果 (预估往返费用 / 买入金额) > 0.50%
  → 不产生信号，提示"当前仓位太小，手续费占比过高（X%），建议至少买入 Y 股"

规则 2: 盈利目标可行性
  净盈利率 = (止盈价 - 入场价) / 入场价 - 费用率 - 0.05%（滑点）
  如果净盈利率 < 0.30%
  → 信号降级为"费用不划算，建议增加仓位或等待更大波动"

规则 3: 止损净损失标注
  止损净损失 = (入场价 - 止损价) / 入场价 + 费用率
  在信号中标注"止损后预估净亏损 X%（含手续费）"

规则 4: 建议仓位计算
  基于当前价和可用资金，反算最小建议股数：
  min_shares = ceiling(10 / (price × 0.00025) / 100) × 100
  （使佣金超过 5 元最低门槛的最小股数，取整到 100 股的倍数）
```

```
┌─────────────────────────────────────────┐
│ 量能低吸 · 正T                            │

│ ─────────────────────────────────────   │
│ 建议买入 1,000 股  |  买入金额 ¥9,850      │
│ 预估手续费 ¥14.78  |  预期净利 +0.42%       │
│ （佣金 ¥5.00×2 + 印花税 ¥4.78）            │
│ 弹性: ★★★★☆                              │
└─────────────────────────────────────────┘
```

### 1.3 验收标准

- 持仓做 T 信号数量从当前水平增加 80% 以上（在正常市场环境下）
- 做 T 信号明确标注"正 T"或"反 T"方向
- 做 T 信号附带入场价、止损价、止盈价（精确到分）
- **做 T 信号附带预估手续费（元）和扣除费用后的预期净利率**
- **预期净利率 < 0.30% 时信号降级为"费用不划算"**
- **手续费占比 > 0.50% 时不产生做 T 信号（仓位太小不划算）**
- **止损价已包含 0.4% 的费用缓冲（避免止损后净亏损超过预期）**
- 弹性评分 < 1 的标的自动不产生做 T 信号
- 日均成交额 2,000-8,000 万的标的也能产生做 T 信号

## 二、波段策略新增建议

### 2.1 A 股波段策略的设计约束

与当前短线策略（持仓 1-5 天，依赖首板和量能骤缩）不同，波段策略的约束是：

- **持仓周期**: 5-20 个交易日
- **入场逻辑**: 基于中周期趋势和关键支撑位，不依赖首板识别
- **出场逻辑**: 目标价止盈 + 移动止损，不依赖 T+2 快速退出
- **标的池**: 不需要日均成交额极高（5,000 万以上即可），但要流动性健康
- **适合做 T 配合**: 波段持仓中每天可叠加做 T 增厚收益

### 2.2 建议新增策略一：「均线通道策略」(ma_channel_band)

**策略逻辑**：

观察 A 股中大量标的呈现"沿 20 日均线通道运行"的特征——股价在 MA20 ± 5% 的通道内反复触及上下轨。当股价从通道下轨附近放量反弹时，是波段入场点；当股价运行到通道上轨附近缩量时，是波段出场点。

**核心规则**：

```
入场条件（全部满足）:
1. 趋势要求: MA20 > MA60（中期上升趋势确认）
2. 位置要求: 当前价在 MA20 下方 0%-4% 区间（通道下轨区域）
3. 弹性要求: 最近 40 个交易日内至少有 1 次从 MA20 下轨反弹 3%+ 的历史
4. 量能要求: 当日成交量 > MA(volume, 5) × 0.8（不能缩量太严重）
5. 分布要求: distribution_risk_score < 6.5（不能是出货形态）
6. 排除: 近 5 日有跌停、距财报披露日 < 3 日

出场条件（满足任一）:
1. 价格触及 MA20 + 4%（通道上轨）→ 止盈
2. 跌破入场日最低价的 2% → 止损
3. 持仓超过 15 个交易日 → 时间止损
4. MA5 下穿 MA20 → 趋势破坏止损
```

**与现有策略的互补性**：
- 与 `classic_retrace` 不同：不依赖首板，不要求成交量骤缩
- 与 `volume_shrink` 不同：不要求放量→缩量模式，用均线通道替代
- 适合大量"温吞水"标的——没有涨停板但趋势稳定的中小盘股

**风险控制**：
- 单只最大仓位：总资金的 15%
- 最大同时持仓：5 只
- 行业分散：同一行业最多 2 只

### 2.3 建议新增策略二：「龙头回踩策略」(leader_pullback_band)

**策略逻辑**：

A 股短线生态中，每个热点板块都有 1-3 只"龙头股"（率先涨停、成交额最大、关注度最高）。龙头股通常经历"涨停 → 开板回踩 → 再度拉升"的循环。当前 `first_board` 策略捕捉的是"首板 + 首阴回调"，但对于已经确认龙头地位的标的，首板之后的第 2-4 次回踩同样（甚至更）安全。

**核心规则**：

```
龙头识别条件（板块内排名）:
1. 近 20 日涨停次数 >= 2
2. 近 20 日日均成交额在所属行业中排前 3
3. 近 20 日涨幅在所属行业中排前 5
4. 满足以上 2/3 条件 → 标记为"龙头"

入场条件:
1. 龙头确认（满足上述 2/3 条件）
2. 从近 20 日最高点回撤 >= 6%
3. 回撤过程中有明确的缩量（近 3 日均量 < MA(volume, 20) × 0.75）
4. 当前价在 MA10 和 MA20 之间（均线支撑区域）
5. 当日非跌停
6. 排除: 有利空公告、ST、退市风险

出场条件:
1. 反弹至回撤幅度的 50% → 止盈一半
2. 反弹至回撤幅度的 80% → 全部止盈
3. 跌破 MA60 → 止损
4. 持仓超过 12 个交易日未反弹 → 时间止损
```

**与现有策略的互补性**：
- 和 `limit_up_breakout_retrace` 不同：后者要求 20+ 日平台 + 首板突破，门槛极高。`leader_pullback` 不要求平台，龙头已确认
- 和 `sector_mainline_first_divergence_low_buy` 不同：后者捕捉主线板块的首分歧，前者捕捉龙头股的第 N 次回踩
- 本质上是"在龙头股身上反复做波段"，胜率高于普通标的

**风险控制**：
- 必须主板标的（科创板/创业板波动过大不适合）
- 龙头确认需要至少 20 日的板块数据
- 单只最大仓位：总资金的 20%
- 如果板块热度降温（板块内涨停家数 < 2）→ 策略暂停

### 2.4 策略实施方案

1. **后端**: 在 `low_buy/screening.py` 中新增两个策略的 scanner 类，遵循现有的 mixin 模式
2. **种子数据**: 在 `DEFAULT_STRATEGY_META` 中新增两条记录（key: `ma_channel_band`, `leader_pullback_band`）
3. **级别**: 初始设为 `research`，经过 60 日模拟盘验证（≥20 笔信号、胜率 ≥55%）后升级

## 三、策略工作台简化 — 实现傻瓜式操作

### 3.1 当前问题诊断

从代码审查来看，策略工作台"不傻瓜"的根因不是功能缺失，而是**信息过载 + 开发者思维残留**：

1. **Tab 按钮上挂着小字标语** — "一屏提交""防过拟合""入口统一" 是开发时的设计意图说明，对用户是视觉噪音
2. **面板副标题全是内部逻辑说明** — "默认按生产策略集合执行，参数只保留最常用项""减少配置成本，避免参数随意组合""提交后自动刷新最近 8 条"——用户在理解"怎么用"之前被迫吸收"为什么这样设计"
3. **StrategyBridge 中渲染开发者注释为 UI** — "按标的、策略和时间快速定位历史信号，不再加载完整回测页面"——这是给 Codex 看的注释
4. **优化/验证表单字段过多且无折叠** — 优化 Tab 有 14 个控件（含 5 个滑块），用户看到就头大
5. **快速回测表单 8 个字段** — 虽然比 14 个好，但"基准指数"字段几乎不需要改
6. **确认对话框信息太简单** — 只显示"将提交 N 个策略"和日期区间，不显示策略名称、资金、预计耗时

## 四、策略工作台布局重构

### 4.1 当前布局问题

从代码审查中确认的具体问题：

1. **Tab 2-5 右侧空白** — 快速回测 Tab 有双栏布局（左表单 + 右侧边栏），但信号复盘/优化/验证/对比 Tab 是单栏，右侧 300-400px 完全空白。用户从"快速回测"切到其他 Tab 时，会感觉页面"塌了"。

2. **StrategyBridge 有多余的 placeholder 区域** — `strategy-placeholder` div（`StrategyHubPage.tsx:296-299`）渲染一个标题 + 一行描述，下方才是真正的内容。这层嵌套浪费了垂直空间。

3. **BacktestDashboard 状态图例在 Hero 区域挤占首屏** — 8 个状态标签横排（`STATUS_META`），占用 hero 区约 60px 高度，却只是图例。

4. **策略卡片网格在宽屏下留白不均匀** — 策略卡片使用 CSS grid `auto-fill`，在 1920px 宽屏下可能只有 3-4 张卡片，右侧留白。

5. **ConfirmDialog 背景遮罩不关闭弹窗** — `StrategyHubPage.tsx:414` 的 backdrop 角色是 `presentation` 但无 `onClick` 关闭逻辑。用户期望点击遮罩关闭被打破。

6. **性能与布局相关的隐性问题** — `BacktestPage` 在 StrategyBridge 中渲染时，即使该 Tab 不可见也创建完整的 `useBacktestDashboard()` hook 实例，造成不可见 Tab 的 API 请求。

### 4.2 重构方案

#### 4.2.1 统一所有 Tab 为双栏布局

```
│  - 信号复盘: 筛选+结果表    │  │ • 首板回调 完成 +3.2%   │   │
│  - 参数优化: 表单+排名表    │  │ • 量能低吸 完成 -1.1%   │   │
│  - 样本外验证: 表单+窗口卡片 │  │ • 首板回调 运行中...    │   │
│  - 结果对比: 多选+对比表    │  │                       │   │

├────────────────────────────┴─────────────────────────────┤
│  Toast 通知区                                              │
```

**关键改动**：
- 所有 6 个 Tab 统一使用 `grid-template-columns: 1fr 320px` 双栏布局
- 右侧边栏固定 320px，在所有 Tab 下显示相关内容
- 快速回测 Tab：侧边栏显示"最近回测"+"策略状态"
- 信号复盘 Tab：侧边栏显示"最近回测"+"热门标的"
- 优化/验证/对比 Tab：侧边栏显示"最近回测"+"相关任务"
- 策略历史 Tab：侧边栏显示"策略状态"+"快速入口（新建回测）"

#### 4.2.2 移除 StrategyBridge placeholder 包装

`StrategyBridge` 组件当前结构：

#### 4.2.3 状态图例移到折叠区

BacktestDashboard Hero 区的 8 状态图例改为 `details/summary` 折叠区，默认折叠。仅显示当前 Run 的状态标记。

#### 4.2.4 策略卡片自适应改进

当前 `auto-fill` 在宽屏下卡片稀疏。改为：
- 卡片最小宽度从 280px 降到 220px
- 在 1920px 宽屏下可容纳 5-6 张卡片
- 卡片内信息精简：只显示策略中文名 + 分类标签 + 一句话描述（去掉冗长描述）

#### 4.2.5 Backdrop 点击关闭

ConfirmDialog 遮罩层增加 `onClick` 关闭逻辑。确认对话框有实质性操作时（用户已填写表单），点击遮罩不关闭（防止误触丢失数据）。

#### 4.2.6 不可见 Tab 不初始化 hook

`StrategyBridge` 中的 `StrategyResearchFocus` 仅在 tab 匹配时渲染，避免创建不可见 Tab 的 hook 实例。当前代码已经用了条件渲染（`StrategyHubPage.tsx:264-303`），但需确认 `BacktestPage` 在 bridge 中的行为——如果 bridge 渲染了 `BacktestResearchPanel`，该 panel 的 `useBacktestDashboard()` 内部会发起 API 请求。解决方案：仅在 tab 激活时传入 `active={true}`，panel 根据此 prop 决定是否初始化数据加载。

### 4.3 验收标准

- 切换任意 Tab，右侧均有内容（无空白栏）
- StrategyBridge 内无 placeholder 包装 div
- 策略卡片在 1920px 宽屏下至少显示 5 张，无大面积留白
- 点击 ConfirmDialog 遮罩可关闭（无未保存数据时）
- 未激活的 Tab 不产生 API 请求
- 状态图例默认折叠
