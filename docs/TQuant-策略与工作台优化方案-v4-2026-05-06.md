## 二、跨阶段通用设计决策

以下决策影响多个 Phase，在此统一说明。

### 2.1 `action` / `effective_action` / `is_actionable` 三字段语义

这是 v4 最关键的跨模块契约：

```
字段            来源              含义                          使用者
─────────────────────────────────────────────────────────────────────
action           量化引擎原始判断   纯信号判断，不受费用/弹性影响    Agent、回测引擎、信号复盘
effective_action 费用+弹性过滤后   可执行建议                      前端展示（信号卡片）、模拟盘自动交易
is_actionable    费用/弹性/风险    前端是否渲染"可执行"按钮         Web/App 前端展示逻辑
                 综合判断
```

**统一规则**（Web、App、Agent、模拟盘自动交易必须一致遵循）：

- `action` 始终保留原始量化判断（`positive_t` / `negative_t` / `hold`），永不被费用/弹性修改
- `effective_action` 仅在 `action != "hold"` 且有费用/弹性降级时变成 `"hold"`
- `is_actionable = (effective_action != "hold" && action != "hold")`
- 前端信号卡片：根据 `effective_action` 展示建议方向，根据 `is_actionable` 决定是否渲染"执行"入口
- 模拟盘自动交易：仅当 `is_actionable == true` 时允许生成委托
- Agent 解读：引用 `action` 描述原始信号，引用 `effective_action` 描述可执行建议
- 回测/绩效统计：使用 `action`（原始信号），不使用 `effective_action`

### 2.2 策略层级解析器

`get_strategy_tier()` 保持纯函数（查 frozenset 常量）。策略升级不修改这些常量。

新增 `StrategyTierResolver` 服务，用于需要 merge DB override 的场景：

```python
# backend/app/services/low_buy/strategy_tier_resolver.py (新建)

class StrategyTierResolver:
    """在纯函数默认层级上合并 DB override。缓存 TTL 300 秒。"""

    def __init__(self, db: Session):
        self._db = db
        self._cache: dict[str, StrategyTier | None] = {}

    def resolve(self, strategy_key: str) -> StrategyTier:
        """返回 DB override（如果存在且未 revert）→ frozenset 默认。"""
        if strategy_key in self._cache:
            return self._cache[strategy_key]

        default = get_strategy_tier(strategy_key)
        override = self._load_override(strategy_key)
        result = override or default

        self._cache[strategy_key] = result
        return result

    def _load_override(self, strategy_key: str) -> StrategyTier | None:
        row = self._db.execute(
            select(StrategyTierOverride)
            .where(StrategyTierOverride.strategy_key == strategy_key)
            .where(StrategyTierOverride.reverted_at.is_(None))
        ).scalar_one_or_none()
        if row:
            return StrategyTier(row.override_tier)
        return None
```

**使用位置**（仅在需要 override 的边界注入，内部管线继续用纯函数）：

| 使用场景 | 解析方式 |
|---------|---------|
| `GET /api/strategies/meta` | `StrategyTierResolver.resolve()` |
| `GET /api/strategy/governance` | `StrategyTierResolver.resolve()` |
| 优先榜参与判断 | `StrategyTierResolver.resolve()` |
| 低吸策略预过滤 (`candidate_rules.py`) | `get_strategy_tier()` 纯函数（不需要 override） |
| 三天保护判断 | `get_strategy_tier()` 纯函数（不需要 override） |

### 2.3 Feature Flag 服务

```python
# backend/app/services/shared/feature_flags.py (新建)

from dataclasses import dataclass
from typing import Any, Callable
from app.models.entities import SystemSetting

@dataclass(frozen=True)
class FlagDef:
    key: str
    default: Any
    coerce: Callable[[str], Any]
    ttl_seconds: int = 60

FLAGS: dict[str, FlagDef] = {
    "t_engine_fee_aware_enabled": FlagDef("t_engine_fee_aware_enabled", True, lambda v: v.lower() == "true"),
    "t_engine_elasticity_enabled": FlagDef("t_engine_elasticity_enabled", True, lambda v: v.lower() == "true"),
    "t_engine_min_net_profit_pct": FlagDef("t_engine_min_net_profit_pct", 0.30, float),
    "t_engine_max_breakeven_pct": FlagDef("t_engine_max_breakeven_pct", 0.50, float),
    "t_engine_min_elasticity_score": FlagDef("t_engine_min_elasticity_score", 25.0, float),
    "strategy_ma_channel_band_enabled": FlagDef("strategy_ma_channel_band_enabled", False, lambda v: v.lower() == "true"),
    "strategy_leader_pullback_band_enabled": FlagDef("strategy_leader_pullback_band_enabled", False, lambda v: v.lower() == "true"),
}

class FeatureFlagService:
    def __init__(self, db: Session):
        self._db = db
        self._cache: dict[str, tuple[float, Any]] = {}  # key → (expires_at, value)

    def get(self, key: str) -> Any:
        flag = FLAGS.get(key)
        if not flag:
            raise KeyError(f"Unknown flag: {key}")
        now = time.monotonic()
        if key in self._cache and self._cache[key][0] > now:
            return self._cache[key][1]
        value = self._read_from_db(key) or flag.default
        self._cache[key] = (now + flag.ttl_seconds, value)
        return value

    def set(self, key: str, value: Any) -> None:  # 仅管理员调用
        flag = FLAGS.get(key)
        if not flag:
            raise KeyError(f"Unknown flag: {key}")
        row = self._db.query(SystemSetting).filter(SystemSetting.key == f"ff_{key}").first()
        if row:
            row.value = str(value)
        else:
            self._db.add(SystemSetting(key=f"ff_{key}", value=str(value)))
        self._db.commit()
        self._cache.pop(key, None)
```

**存储**：`system_settings` 表，key 前缀 `ff_`（`ff_t_engine_fee_aware_enabled`）。
**权限**：`GET /api/settings/feature-flags` → 登录用户可读。`PUT /api/settings/feature-flags/{key}` → `require_admin_auth`，写入审计日志。
**生产默认值**：新策略的 flag 默认 `false`（配置为 `false` + flag 也为 `false`）。上线后由管理员显式开启。

### 2.4 弹性评分缓存

**选定方案**：新建 `trading_elasticity_cache` 表。

```sql
CREATE TABLE trading_elasticity_cache (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    symbol VARCHAR(16) NOT NULL,
    elasticity_score REAL NOT NULL DEFAULT 0.0,
    rebound_count INTEGER NOT NULL DEFAULT 0,
    lookback_days INTEGER NOT NULL DEFAULT 20,
    computed_at DATETIME NOT NULL DEFAULT (datetime('now')),
    data_quality VARCHAR(16) NOT NULL DEFAULT 'ok',  -- ok | partial | stale
    UNIQUE(symbol)
);
CREATE INDEX idx_elasticity_computed ON trading_elasticity_cache(computed_at);
```

**数据源**：`MinuteBarSnapshot` 表（已有），查询近 20 个交易日的日内高低点。
**预热策略**：每日盘前 9:00 定时任务批量计算所有 `watchlist` 持仓标的的弹性评分，写入缓存表。用户请求热路径只读缓存（~0.1ms）。
**缓存过期**：TTL = 1 个交易日。缓存缺失时不实时计算，返回 `data_quality = "stale"`，`elasticity_score = 10.0`（最低基础分）。

### 4.1 共享费用模块

从 `paper/risk_control.py:229` 的 `_round_trip_fee_pct()` 抽取到共享模块。**保持 `paper/risk_control.py` 旧接口完全兼容**（内部改为从共享模块导入，函数签名不变）。

```python
# backend/app/services/shared/trading_costs.py (新建)

from decimal import Decimal
from app.services.paper.fees import calculate_fee

def round_trip_fee_pct(*, symbol: str, price: float, quantity: int) -> float:
    """往返费用占成交金额百分比。含买入佣金+卖出佣金+印花税+过户费。"""
    if price <= 0 or quantity <= 0:
        return 0.0
    gross = Decimal(str(price)) * Decimal(quantity)
    if gross <= 0:
        return 0.0
    try:
        buy = calculate_fee(symbol=symbol, side="buy", price=Decimal(str(price)), quantity=quantity)
        sell = calculate_fee(symbol=symbol, side="sell", price=Decimal(str(price)), quantity=quantity)
        total = buy.total_fee + sell.total_fee
    except Exception:
        return 0.0
    return float(total / gross * Decimal("100"))

def round_trip_fee_amount(*, symbol: str, price: float, quantity: int) -> float:
    """往返费用金额（元）。"""
    pct = round_trip_fee_pct(symbol=symbol, price=price, quantity=quantity)
    return round(float(Decimal(str(price)) * Decimal(str(quantity)) * Decimal(str(pct)) / Decimal("100")), 2)
```

**必须覆盖的测试**：股票标准费率、ETF（免印花税 0.05%）、小单（2000 元最低佣金 5 元验证）、零价/负价/负数量边界、计算异常降级。

输出字段填充逻辑：
- `direction`：`action == "positive_t"` → `"正T"`，`"negative_t"` → `"反T"`，否则 `"观望"`
- `estimated_fee`：`position_shares > 0` 时调用 `round_trip_fee_amount()`；否则 0
- `breakeven_pct`：`estimated_fee / gross_amount * 100`；`gross_amount = 0` 时返回 0
- `net_profit_pct`：`trade_plan.expected_profit_pct - breakeven_pct - (slippage_bps / 100)`
- `fee_warning`：**不含交易承诺**，使用风险表达：
  - `breakeven_pct > 1.0` → `"成本占比极高（{pct}%），不建议频繁操作"`
  - `breakeven_pct > 0.50` → `"成本占比偏高（{pct}%），建议增加操作股数以降低费率"`
- `elasticity_score`：`flags.get("t_engine_elasticity_enabled")` 为 true 时从 `trading_elasticity_cache` 读取；缓存缺失返回 10.0
- `min_shares_suggestion`：`ceiling(10 / (price * 0.00025) / 100) * 100`（最低委托金额使佣金突破 5 元底线）

## 五、Phase 3：新策略数据探针与全链路接入（7 天）

### 5.1 前置步骤：`leader_pullback_band` 数据探针

在写策略代码之前，必须先跑数据探针脚本。

**脚本**：`backend/scripts/probe_leader_pullback_data.py`

**探测维度**：

| 数据需求 | 查询方式 | 通过标准 |
|---------|---------|---------|
| 近 24 个月每日涨停 ≥2 次的股票数（按行业分组） | `limit_up_pool` + 分组聚合 | 每月至少 1 个行业产出 ≥3 个候选 |
| 行业成交额排名数据可用率 | `DailyBarSnapshot` 的 `amount` 字段非空率 | > 95% |
| `MinuteBarSnapshot` 数据覆盖度 | 近 20 日有分钟线的标的总数 | > 3000 |
| 预估每日候选数 | 全条件（≥2 涨停 + 回撤 ≥6% + 缩量 + MA10-20 间） | 日均 ≥0.3 个 |

**探针输出**：JSON 报告 `scripts/probe_leader_pullback_report.json`，含每月数据可用率、候选数、行业分布。

**硬阻断规则**：如果探针失败（任一维度不达标），`leader_pullback_band` **只允许回测研究**，不进入 Playbook、不进入优先榜、不进入 go-live 流程。

### 5.2 `ma_channel_band` 数据确认

### 5.4 `leader_pullback_band` 行业排名实现策略

`pool.py:408-416` 的 `_rank_pool_candidates()` 排序维度仅 `board_date + board_count + amount`，没有行业概念。重写该函数为支持策略专属排序会牵动整个池系统。

**v4 决策**：池构建使用默认排序（不实现行业排名）。行业排名逻辑放在 `candidate_rules.py` 的 `passes_strategy_prefilter()` 和 `score_candidate()` 中：

- `passes_strategy_prefilter()`：检查基础条件（≥2 涨停、回撤 ≥6%、缩量、价格区间、非跌停）
- `score_candidate()`：调用 `_leader_industry_rank()` 查询 `limit_up_pool` 近 20 日数据，按行业分组聚合涨停次数和成交额排名，给龙头标的加分

这避免了修改池系统核心逻辑，将复杂性限制在策略专属的预过滤评分层。

## 十五、待澄清问题（终版回答）

| # | 问题 | 回答 |
|---|------|------|
| Q1 | `effective_action` 和 `action` 前端显示哪个？ | 前端信号卡片用 `effective_action` 展示可执行建议，`action` 作为详情 tooltip 展示原始信号。Web/App 一致。 |
| Q2 | `is_actionable=false` 时模拟盘是否仍生成委托？ | **否**。`is_actionable=false` 时模拟盘自动交易不生成委托。用户可在模拟盘 UI 手动覆盖（如有 UI）。 |
| Q3 | `StrategyTierOverride` 全局生效还是按用户/环境？ | **全局生效**。不分用户/环境。如需分环境（如 staging 提前升级），通过 feature flag 控制策略可见性。 |
| Q4 | 新策略在研究阶段是否出现在全策略优先榜？ | **不出现**。`participates_in_priority_board()` 对 research 返回 `False`。仅在用户显式选择时展示。 |
| Q5 | `ma_channel_band` 允许非热点行业吗？ | **允许**。ma_channel_band 不依赖行业热度，全市场扫描。这与"主线化"方向不冲突——核心策略聚焦主线，research 策略探索全市场。 |
| Q6 | leader 行业排名和涨停次数数据来源？ | 涨停次数来自 `limit_up_pool`（AkShare `stock_zt_pool_em`）近 20 日聚合。行业排名来自 `DailyBarSnapshot` 的 `amount` + `sector_name` 聚合。在 `candidate_rules.py` 的 `score_candidate()` 中实现，不放入池系统。 |
| Q7 | Feature flag 生产环境默认开启还是关闭？ | 新策略 flag **默认关闭**。Phase 2 的做 T 增强 flag **默认开启**（因为不引入新策略，仅增强现有信号字段）。 |
| Q8 | 弹性缓存过期时接口降级还是等待？ | **降级**。返回 `elasticity_data_quality: "stale"`, `elasticity_score: 10.0`。不在用户请求热路径实时计算。 |
| Q9 | 参数优化/验证权限沿用 `can_research`？ | **是**。前端 `StrategyHubPage.tsx:283,286` 已有 `canOptimize/canValidate` 检查，后端同步加 `require_research_auth`。 |
| Q10 | 新策略是否需要 24 个月回测作为上线前置？ | **是**。升级到 auxiliary 的前置条件之一是 24 个月历史回测 Sharpe ≥1.0。如果探针失败则回测可能无足够数据，升级前置条件自然不满足。 |
