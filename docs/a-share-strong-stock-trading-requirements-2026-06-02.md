## 1. 背景

用户希望把章盟主文章中的短线选股、买点、卖点、仓位、风控和复盘经验整理成平台可实现的需求文档。

这些文章的共同交易框架是：

1. 先判断大盘环境和市场情绪。
2. 再聚焦主线板块。
3. 只筛选有辨识度的龙头、前排、强跟随或容量中军。
4. 买点等待放量突破、缩量回踩、分歧转一致、涨停后洗盘确认。
5. 卖点重点识别高位放量、破位、滞涨、缩量阴跌和主力出货特征。
6. 仓位强调半仓、少标的、盈利安全垫、不补仓、不恋战。
7. 每日复盘强势票和自身交易，形成持续观察池。

本文档目标不是把文章观点直接变成实盘策略，而是把其中可计算、可解释、可验证的部分整理为产品与工程需求。

## 2. 目标

建设一套 `strong_stock_shortline` 强势股短线观察与验证能力。

目标输出：

1. 给出市场环境是否允许短线出手的判断。
2. 识别当日主线板块、板块地位和个股辨识度。
3. 生成强势股观察池，明确观察条件、触发条件、失效条件和风险标签。
4. 对买点、卖点、持仓、做 T、复盘提供结构化解释。
5. 接入 Shadow/Paper 验证，统计文章规则在真实历史数据中的有效性。
6. 输出可读的“为什么观察 / 为什么不观察 / 为什么失效”说明。

不做：

1. 不自动下单。
2. 不输出确定性买卖指令。
3. 不把文章经验直接写入生产分。
4. 不绕过现有 `strategy_policy` 和生产排序门控。
5. 不把“主力”叙事作为不可验证事实，只使用价格、量能、趋势、板块、资金承接等可观测证据。
6. 未经过 24 个月回测、样本外验证和 walk-forward 前，不进入生产排序。

## 3. 用户场景

### 3.1 收盘后选明日观察票

用户希望在收盘后看到：

1. 今日大盘环境是否适合短线。
2. 今日主线板块是谁。
3. 主线里的龙头、前排、强跟随、中军分别是谁。
4. 明日应该观察哪些票。
5. 每只票的观察位、失效位和风险点。

### 3.2 盘中判断是否触发

用户希望盘中看到：

1. 观察票是否触发平台突破、均线回踩、分歧转一致或涨停后洗盘买点。
2. 高开是否可追，还是只能等回踩。
3. 板块是否继续强，还是已经退潮。
4. 个股是否出现破位、放量滞涨、冲高回落等风险。

### 3.3 持仓后管理风险

用户希望系统提示：

1. 趋势是否仍然有效。
2. 回撤属于合理洗盘还是趋势破坏。
3. 是否出现高位放量下跌、缩量阴跌、上涨缩量下跌放量等卖出风险。
4. 盈利后是否应抬高防守位。
5. 是否允许做 T，还是趋势破位应停止做 T。

### 3.4 每日复盘

用户希望系统每日复盘：

1. 涨幅超过 8% 的强势票。
2. 次日放量破位或跌幅居前的剔除票。
3. 连续跟踪三天仍保持强势结构的优质票。
4. 自己的操作是否符合规则。

## 4. 业务定义

### 4.1 强势股短线观察池

强势股短线观察池是面向次日或盘中的候选列表。

它不是买入清单，也不是实盘交易指令。

页面必须显示：

```text
当前性质：观察与验证，不是确定买入
```

### 4.2 主线

主线指资金持续流入、板块联动明显、龙头具有辨识度、持续性强的市场方向。

主线不能只按单日涨幅判断，必须结合：

1. 板块涨幅排名。
2. 板块涨停数量。
3. 板块成交额放大。
4. 龙头晋级、反包或强封。
5. 板块扩散性。
6. 板块连续性。
7. 是否明显强于指数。

### 4.3 个股辨识度

个股辨识度表示市场资金是否容易识别并优先选择该票。

分层如下：

| 代码 | 中文 | 说明 |
|---|---|---|
| `leader` | 龙头 | 板块空间核心或最高辨识度标的 |
| `front_row` | 前排 | 板块内强度靠前，资金优先选择 |
| `strong_follower` | 强跟随 | 跟随龙头紧密，强于板块均值 |
| `center_liquidity` | 中军 | 成交额大、趋势稳、容量适合大资金 |
| `back_row` | 后排 | 补涨或杂毛，原则上剔除或降权 |

### 4.4 观察条件

观察条件表示“什么情况下继续看”。

示例：

```text
观察条件：所属板块继续保持主线，股价回踩 5 日线缩量企稳，或重新放量突破早盘高点。
```

### 4.5 失效条件

失效条件表示“什么情况下放弃观察”。

示例：

```text
失效条件：放量跌破 10 日线，或板块从主线转为退潮，或出现高位放量滞涨。
```

## 5. 选股规则需求

### 5.1 市场环境过滤

系统必须先判断大盘和情绪环境。

允许提高观察权重的环境：

| 环境 | 处理 |
|---|---|
| 指数稳定，题材活跃 | 正常生成观察池 |
| 指数震荡，主线明确 | 正常生成观察池 |
| 缩量轮动但有强主线 | 限量生成观察池 |
| 大盘走弱但核心标的抗跌 | 只观察抗跌核心，不扩散 |

必须降低或暂停的环境：

| 环境 | 处理 |
|---|---|
| 跌停潮 | 暂停新增短线观察 |
| 高位退潮 | 只做风险提示 |
| 主线一日游 | 不推个股，只展示方向 |
| 大盘环境冰点 | 少做或观望 |

### 5.2 五要素选股

候选票必须按五要素打分：

| 要素 | 要求 | 说明 |
|---|---|---|
| 大盘环境 | 顺势 | 大盘和情绪不支持时，降低全部候选权重 |
| 市场主线 | 在主线中 | 优先资金扎堆、反复走强的板块 |
| 个股辨识度 | 龙头/前排/强跟随/中军 | 剔除无辨识度杂毛 |
| 上涨趋势 | 均线多头或趋势走高 | 不抄下降趋势底 |
| 成交量能 | 启动放量、回调缩量 | 无量、长期阴跌、无人关注降权 |

### 5.3 候选来源

候选股票来自：

1. 主线板块成分股。
2. 当日涨幅超过 8% 的强势标的。
3. 当日涨停或近 5 日有涨停的标的。
4. 放量突破整理平台的标的。
5. 上升趋势中缩量回踩关键均线的标的。
6. 现有低吸优先榜、策略跟踪、明日观察池中的候选。
7. 用户自选池中的强势票。

### 5.4 剔除条件

以下股票不得进入强势股短线观察池：

1. 非主线后排杂毛。
2. 长期下降趋势且只出现短期脉冲反弹。
3. 无量反弹。
4. 缩量阴跌、长期无人关注。
5. 高位爆量派发。
6. 高位缩量阴跌。
7. 上涨缩量、下跌放量。
8. 明显高位长上影或放量滞涨。
9. ST、停牌、重大公告风险、退市风险。
10. 用户偏好明确排除的市场范围。

## 6. 买点规则需求

### 6.1 平台突破买点

适用条件：

| 条件 | 要求 |
|---|---|
| 结构 | 前期横盘整理，消化浮筹 |
| 突破 | 放量突破平台 |
| 量能 | 成交量达到近期倍量或明显放大 |
| 回踩 | 突破后回踩平台不破 |
| 风险 | 无量突破标记为诱多风险 |

系统输出：

```text
买点类型：平台放量突破
观察条件：回踩平台不破后再转强
失效条件：跌回平台内且放量走弱
```

### 6.2 均线回踩买点

适用条件：

| 条件 | 要求 |
|---|---|
| 趋势 | 上升趋势未破 |
| 均线 | 沿 5 日线或 10 日线运行 |
| 回踩 | 缩量回踩 5 日线或 10 日线 |
| 止跌 | 不再创新低，或分时重新站回 VWAP |
| 禁忌 | 下降趋势中不做回踩买点 |

系统输出：

```text
买点类型：趋势均线回踩
观察条件：缩量回踩 5 日线或 10 日线不破
失效条件：放量跌破 10 日线并收不回
```

### 6.3 分歧转一致买点

适用条件：

| 条件 | 要求 |
|---|---|
| 板块 | 主线仍然有效 |
| 个股 | 龙头、前排或强跟随 |
| 分歧 | 高位横盘、收阴或缩量震荡 |
| 资金 | 分歧时没有明显出逃 |
| 转强 | 再次放量突破分歧平台 |

系统输出：

```text
买点类型：分歧转一致
观察条件：缩量分歧后重新放量突破
失效条件：分歧后放量下破平台
```

### 6.4 涨停后洗盘买点

涨停不是买点，只是观察起点。

系统只对近 5 日有涨停的股票计算涨停后洗盘形态。

核心判断：

| 维度 | 好信号 | 风险信号 |
|---|---|---|
| 量能 | 缩量回踩、抛压轻 | 放量滞涨、对倒出货风险 |
| 价格 | 不跌破涨停实体一半 | 跌破涨停开盘价 |
| 时间 | 涨停后 3-5 天确认 | 次日盲目追高 |

四类形态：

| 形态 | 规则 |
|---|---|
| 三阴铁底 | 涨停后连收三阴，最低价不破涨停日最低价，第四天放量阳线 |
| 半量暗号 | 涨停后 5 天内出现较前一日缩量一半以上阴线，后续收盘突破该阴线开盘价 |
| 四星旭日 | 涨停实体上方横盘，三到四根小阳线或十字星，成交量逐步缩小，随后放量 |
| 上下试盘 | 涨停后先长上影试抛压，次日长下影洗浮筹，后续放量转强 |

系统输出必须标注：

```text
当前只满足观察形态，不等于确定买入。
```

## 7. 卖点与风控需求

### 7.1 趋势破位

触发条件：

1. 跌破关键支撑。
2. 跌破 5 日线或 10 日线后无法收回。
3. 跌破前期平台高点或趋势线。
4. 均线由多头转弱。

动作建议：

```text
风险动作：退出观察或减仓验证，不恋战。
```

### 7.2 量价背离

触发条件：

1. 股价冲高但量能跟不上。
2. 上涨缩量，下跌放量。
3. 反弹无量。

动作建议：

```text
风险标签：量价背离，资金承接不足。
```

### 7.3 高位出货特征

系统必须识别四类高位出货风险：

| 风险 | 条件 |
|---|---|
| 慢涨后加速冲顶 | 前期稳步上涨，后期突然大幅加速，远离均线 |
| 高位放量见顶 K 线 | 高位放大量，叠加乌云盖顶、黄昏之星等见顶形态 |
| 上涨缩量下跌放量 | 上涨无力，下跌时筹码松动 |
| 分时放量双线走弱 | 黄白线同步下行并放量 |

系统输出：

```text
风险标签：疑似高位派发，禁止追高，优先避险。
```

### 7.4 下跌性质判断

下跌必须结合位置和量能判断。

| 位置 | 量能 | 解释 | 处理 |
|---|---|---|---|
| 高位 | 放量下跌 | 资金分歧巨大，疑似出货 | 避险、减仓、退出观察 |
| 低位 | 放量下跌 | 可能恐慌洗盘或最后砸盘 | 不立即买，纳入跟踪，等放量企稳 |
| 上升趋势中 | 缩量回调 | 良性洗盘概率高 | 观察低吸条件 |
| 高位 | 缩量阴跌 | 多头乏力，缓慢派发 | 反弹减仓 |
| 低位 | 长期缩量阴跌 | 无资金关注，弱势磨底 | 不提前埋伏 |

### 7.5 不补仓规则

短线体系默认禁止亏损补仓。

系统不得输出“补仓摊低成本”类建议。

当持仓亏损时，系统只允许输出：

1. 趋势仍有效，继续按原防守位观察。
2. 结构破位，退出或减仓。
3. 数据不足，保持观察。

## 8. 持仓与做 T 需求

### 8.1 趋势持仓

持仓依据：

1. 20 日线。
2. 5 日线和 10 日线。
3. 前期平台高点。
4. 上升趋势线。
5. 板块主线是否仍有效。

趋势没破时，可以接受合理回撤。

但出现以下情况必须标记止盈或减仓风险：

1. 双头走弱。
2. 冲高乏力。
3. 高位放量滞涨。
4. 长上影抛压明显。
5. 放量跌破关键支撑。

### 8.2 盈利安全垫

当候选或模拟持仓盈利超过 20% 时，系统应提示抬高防守位。

示例：

```text
盈利安全垫：盈利超过 20%，可将防守位上移至成本线以上。
```

### 8.3 做 T 规则

做 T 只适用于主线龙头或强势趋势票。

| 项 | 要求 |
|---|---|
| 底仓 | 50%-60%，用于锁定趋势 |
| T 仓 | 40%-50%，用于日内波动 |
| 目标 | 3%-5% 差价，不追求极致高低点 |
| 适用 | 主线龙头、上升趋势、趋势未破 |
| 禁止 | 杂毛股、下降通道、破位后硬做 T |

做 T 口诀转成系统规则：

| 盘面 | 处理 |
|---|---|
| 急跌缩量 | 可观察低吸 |
| 反弹无力 | 高抛或减仓 |
| 高开缩量 | 先减仓观察 |
| 回落企稳 | 再考虑买回 |

黄金观察时间：

1. 9:45-10:15。
2. 13:30-14:00。

系统只输出做 T 观察提示，不输出自动交易动作。

## 9. 仓位与纪律需求

### 9.1 仓位原则

文章经验转化为系统提示：

| 规则 | 系统表达 |
|---|---|
| 日常半仓 | 默认不建议满仓暴露 |
| 集中少标的 | 重点观察 3-5 只强势票 |
| 盈利适当减仓 | 盈利后分批落袋，剩余跟趋势 |
| 长假前减仓 | 节前标记假期风险 |
| 行情不明观望 | 市场环境不明时降低出手频率 |

### 9.2 行为纪律

系统应持续提示并记录：

1. 不做下跌补仓。
2. 不追无量拉升。
3. 不买无量反弹弱势股。
4. 不猜弱势股底部。
5. 不追连续加速且远离均线的票。
6. 不恋战、不扛单。
7. 不把短线亏损票变成长线被动持仓。

## 10. 复盘需求

### 10.1 收盘复盘

每日收盘后生成强势股复盘。

流程：

1. 筛选当日涨幅超过 8% 的标的。
2. 标记所属板块、板块地位、量能、趋势、是否涨停。
3. 形成初始观察池。
4. 对前一日观察池做结果回看。

### 10.2 次日剔除

对观察池执行剔除：

1. 跌幅居前。
2. 放量破位。
3. 板块退潮。
4. 高位放量滞涨。
5. 分时冲高回落严重。

### 10.3 三日跟踪

优质标的至少跟踪三天。

跟踪项：

1. 是否保持强势结构。
2. 是否缩量回踩不破。
3. 是否重新放量转强。
4. 是否被板块带动或带动板块。
5. 是否触发失效条件。

### 10.4 自身交易复盘

模拟盘或用户记录应支持复盘字段：

1. 进场理由。
2. 买点类型。
3. 防守位。
4. 是否遵守不补仓规则。
5. 卖出原因。
6. 盈亏结果。
7. 错误类型。
8. 下次修正动作。

## 11. 数据需求

### 11.1 日线数据

必需字段：

1. 开高低收。
2. 成交量。
3. 成交额。
4. 换手率。
5. 涨跌幅。
6. 5 日、10 日、20 日均线。
7. 涨停价、跌停价。
8. 是否涨停、炸板、断板。

### 11.2 板块数据

必需字段：

1. 板块涨幅。
2. 板块成交额。

6. 龙头、前排、强跟随、中军识别结果。
7. 板块连续性和退潮状态。

### 11.3 分时数据

1. 分时价格。
2. 分时成交量。
3. VWAP。
4. 早盘高低点。
5. 午盘高低点。
6. 冲高回落幅度。
7. 回踩 VWAP 是否企稳。

### 11.4 风险数据

1. ST、*ST。
2. 停牌。
3. 退市风险。
4. 减持、监管、业绩雷。
5. 财务或公告重大异常。
6. 流动性过低。

## 14. 研究与生产边界

### 14.1 研究模式

默认状态为研究模式。

研究模式允许：

1. 生成观察池。
2. 生成解释。
3. 写 Shadow/Paper 验证。
4. 生成回测和复盘报告。

研究模式禁止：

1. 写生产分。
2. 替换优先榜排序。
3. 自动改变 `strategy_policy`。
4. 自动下单。

### 14.2 生产候选条件

任一规则进入生产候选前，必须满足：

1. 24 个月完整数据回测。
2. 样本外验证。
3. walk-forward 验证。
4. 明确交易成本、滑点、涨跌停、停牌、T+1 约束。
5. 市场状态分层表现清晰。
6. 候选池收益、真实组合收益、观察池收益分开展示。
7. 最大回撤、PF、平均单笔、最长无票、成交留存、信号日留存达标。

### 14.3 强制口径

1. `watch_score` 不等于 `production_score`。
2. `near_entry` 和观察类信号不得进入生产收益排行。
3. 未验证规则必须标记 `research_only`。
4. 缺数据必须标记 `no_data` 或 `blocked_by_data`。
5. 大模型只可用于文本摘要，不作为选股决策源。

## 15. 验证需求

### 15.1 回测范围

必须覆盖：

1. 至少 24 个月。
2. 牛市、震荡市、弱市、普跌行情。
3. 主线明确和主线不明确的日期。
4. 高位退潮日期。
5. 涨停潮和跌停潮日期。

### 15.2 指标

必须输出：

1. 样本数。
2. 成交数。
3. 信号日留存。
4. 成交留存。
5. 平均单笔收益。
6. PF。
7. 最大回撤。
8. 最长无票天数。
9. max5 / max10 真实组合收益。
10. 市场状态分层收益。
11. 板块角色分层收益。
12. 规则命中分层收益。

### 15.3 反泄漏要求

1. 观察池生成只能使用信号日及之前数据。
2. 主线、龙头、量能、均线、支撑压力不能使用未来数据。
3. 次日触发只能用盘中可见数据。
4. 复盘可以使用结果数据，但必须标记为复盘，不得反写信号。

## 16. 验收标准

### 16.1 功能验收

1. 系统能生成强势股短线观察池。
2. 每只票都有主线、板块地位、观察条件、失效条件、风险标签。
3. 页面明确显示观察性质，不误导成买入。
4. 高位出货、下跌趋势反弹、无量反弹、破位风险能被标记。
5. 不补仓规则不会输出补仓建议。
6. 复盘能生成涨幅 8% 强势池、次日剔除、三日跟踪。
7. 做 T 提示只在主线龙头和上升趋势中出现。

### 16.2 工程验收

1. 新能力默认 feature flag 关闭或 research-only。
2. 后端 schema 明确，前端不依赖临时字段。
3. OpenAPI 和前端类型同步。
4. 缺数据状态可见，不造分。
5. 关闭开关后不影响现有生产排序。
6. 生成报告区分观察池、候选池、真实组合。

### 16.3 验证验收

1. 24 个月回测报告生成。
2. 样本外和 walk-forward 结果生成。
3. 市场状态分层结果生成。
4. 未来数据泄漏检查通过。
5. 弱市下信号减少，不强行出票。
6. 牛市或强主线下信号可适度增加。

## 17. 风险与注意事项

1. 文章中的“主力”解释只能转成可观测量价证据，不能当作确定事实。
2. “不看基本面”不能绝对化，系统仍必须做公告、财务、退市、ST、停牌等基础排雷。
3. 强势股规则容易在牛市表现好、弱市失效，必须按市场状态分层验证。
4. 涨停后洗盘形态样本可能少，不能只看收益率，必须看留存、回撤和成交质量。
5. 做 T 规则依赖分钟数据，没有分钟数据时只能展示 `no_data`。
6. 任何规则未经验证不得进入生产排序。

## 18. 实施建议

建议拆成四个包：

1. **R1：规则建模与 schema**：建立强势股观察池 schema，以及市场环境、主线、辨识度、买点、卖点、风险标签枚举。

2. **R2：观察池与复盘**：实现涨幅 8% 强势池、主线过滤、个股辨识度、次日剔除和三日跟踪。

3. **R3：盘中触发与风险提示**：实现平台突破、均线回踩、分歧转一致、涨停后洗盘形态，以及破位、量价背离、高位出货、假反弹识别。

4. **R4：Shadow/Paper 与 24M 验证**：接入模拟验证，生成 24 个月回测，输出市场状态分层和生产候选审查。
