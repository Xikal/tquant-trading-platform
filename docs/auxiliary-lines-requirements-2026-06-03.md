## 1. 背景

用户在查看单只股票时，需要快速判断当前价格处在什么结构位置：是否靠近支撑区、是否进入压力区、是否仍在趋势通道内、是否跌破关键边界、是否只是弱修复。

当前平台已经有关键位、MA、支撑压力和 AKeyLevel Engine 的规划，但图表上的“辅助线”还需要产品化成完整能力：既能画线，也能解释线的来源、可信度和失效条件。

辅助线不是预测工具，也不是交易指令工具。它的价值在于把日线、分时、成交量、均线、前高前低、通道、VWAP 等信息转成可观察、可复盘、可解释的结构标尺。

## 2. 产品定位

辅助线能力是 AKeyLevel Engine 的图形化表达层。

它用于：

1. 观察当前价格所处位置。
2. 展示支撑区、压力区和趋势通道。
3. 解释模拟盘持仓的风险边界。
4. 辅助复盘策略信号是否发生在合理位置。
5. 帮助用户识别“强势延续、区间震荡、弱修复、破位风险”等结构状态。

它不用于：

1. 不替代现有生产排序。
2. 不修改策略打分、策略政策或候选池规则。
3. 不生成生产分。
4. 不输出交易动作、仓位动作或收益承诺。
5. 不把主观判断词当作事实，只能落到可观测价量标签。

## 3. 目标

### 3.1 用户目标

用户打开一只股票时，可以直接看到：

1. 当前价格附近最近的支撑区和压力区。
2. 下降通道、上升通道或横盘区间边界。
3. MA5 / MA10 / MA20 / MA30 / MA60 的位置关系。
4. 重要锚点 VWAP、放量日、涨停日、缺口和前高前低。
5. 每条线为什么存在、强度如何、什么时候视为失效。
6. 数据是否足够、是否过期、是否只能研究观察。

### 3.2 平台目标

1. 将辅助线统一接入 AKeyLevel Engine，而不是前端临时画线。
2. 建立后端计算、API 契约、前端渲染和测试验收的统一口径。
3. 所有线位必须可追溯到数据来源和规则来源。
4. 所有结论必须标记 `as_of`、`data_cutoff`、`data_quality` 和 `engine_version`。
5. 默认 feature flag 关闭，关闭后不影响监控、策略跟踪、模拟盘、回测和生产排序既有行为。

## 4. 用户故事

1. 作为短线观察用户，我想在个股图上看到支撑区和压力区，所以我能快速判断当前价格处在结构低位、区间中部还是压力附近。
2. 作为模拟盘用户，我想看到持仓标的的趋势通道，所以我能判断当前波动是否仍在既有结构内。
3. 作为复盘用户，我想看到策略信号发生时的历史辅助线，所以我能判断信号日的位置是否合理。
4. 作为监控用户，我想看到接近关键位的提醒，所以我能优先关注位置变化明显的标的。
5. 作为盘中观察用户，我想看到盘中 VWAP、昨收、今开、日内高低点，所以我能理解分时价格相对日内结构的位置。
6. 作为风险管理用户，我想看到支撑失效条件，所以我能知道何时结构风险升高。
7. 作为研究用户，我想导出一张带辅助线的分析图，所以我能把复盘结论保存到报告。
8. 作为产品使用者，我想知道每条线的强度和证据，所以我不会把一条弱线误认为强关键位。
9. 作为移动端用户，我想先看到最重要的三条线，所以我能在小屏快速扫读。
10. 作为工程使用者，我想通过 API 拿到标准化线位结果，所以不同页面不用重复实现计算逻辑。

## 5. 辅助线类型

### 5.1 水平关键线

来源：

1. 近期前高和前低。
2. 平台高点和平台低点。
3. 跳空缺口上下沿。
4. 涨停日、开板日、放量日关键价。
5. 昨收、今开、盘中高低点。
6. 整数关口和最小报价单位对齐价位。

输出：

1. 支撑线。
2. 压力线。
3. 支撑区间。
4. 压力区间。
5. 当前价格到该线的距离百分比。

### 5.2 均线辅助线

必须支持：

1. MA5。
2. MA10。
3. MA20。
4. MA30。
5. MA60。

衍生状态：

1. 当前价相对各均线的距离。
2. 均线方向。
3. 均线多空排列状态。
4. 多条均线聚合区。
5. MA30 和 MA60 的趋势过滤说明。

### 5.3 趋势线

趋势线分为：

1. 上升支撑线。
2. 下降压力线。
3. 横盘边界线。

计算要求：

1. 必须基于已确认的摆动高点或摆动低点。
2. 至少两个锚点，推荐三个以上触点提高强度。
3. 摆动点确认必须有确认日期，不能在信号日使用未来数据。
4. 最新未确认摆动点只能标记为 `pending`，不能当作强证据。

### 5.4 通道线

通道线分为：

1. 上升通道。
2. 下降通道。
3. 横向箱体。
4. 回归通道，默认仅研究展示。

通道输出：

1. 上沿价格。
2. 下沿价格。
3. 中轴线。
4. 通道斜率。
5. 通道宽度。
6. 当前价在通道内的位置百分位。
7. 上沿和下沿的失效条件。

通道强度要求：

1. 上沿和下沿至少各有一个有效触点。
2. 通道跨度过短时标记为 `weak_sample`。
3. 通道由异常一字板、停牌或极端缺口主导时降级。
4. 通道突破后的反抽只能描述为结构观察，不能输出动作建议。

### 5.5 成交密集区

成交密集区用于表达筹码密集位置。

要求：

1. 基于日线成交额或分钟成交额聚合。
2. 输出价格区间，不输出单点。
3. 和前高、前低、均线、VWAP 重合时形成共振区。
4. 数据不足时标记 `insufficient`。

### 5.6 Anchored VWAP

锚点来源：

1. 最近涨停日。
2. 最近放量突破日。
3. 最近放量下跌日。
4. 阶段高点。
5. 阶段低点。
6. 缺口日。

要求：

1. 锚点必须发生在 `as_of` 当日或之前。
2. 输出锚点日期、锚点原因、VWAP 价格和当前距离。
3. 锚点过旧或期间停牌过多时降级。

### 5.7 盘中辅助线

盘中线仅在分钟数据充足时启用。

必须支持：

1. 盘中 VWAP。
2. 昨收。
3. 今开。
4. 当日高点。
5. 当日低点。
6. 开盘区间高低点。

盘中线缺分钟数据时必须明确返回 `no_data`，不能回退成伪实时结论。

## 6. 结构结论标签

辅助线可以输出结构标签，但必须是观察语义。

允许标签：

1. `near_support`：接近支撑。
2. `near_resistance`：接近压力。
3. `inside_channel`：仍在通道内。
4. `channel_upper_test`：接近通道上沿。
5. `channel_lower_test`：接近通道下沿。
6. `support_broken`：支撑失效。
7. `resistance_reclaimed`：压力重新站回。
8. `weak_repair`：弱修复。
9. `range_bound`：区间震荡。
10. `insufficient_data`：数据不足。

禁止标签：

1. 交易动作标签。
2. 确定性收益标签。
3. 主观资金行为事实标签。
4. 会改变生产排序的标签。

## 7. 数据口径

### 7.1 输入数据

必需数据：

1. 日线 OHLCV。
2. 复权方式。
3. 实时行情快照或最近完整收盘。
4. 涨跌停价格。
5. 停牌、ST、退市状态。

可选增强数据：

1. 分钟线 OHLCV。
2. 板块和行业归属。
3. 板块指数或代理序列。
4. 大盘指数序列。
5. 策略信号日和模拟盘成交记录。

### 7.2 时间边界

1. 实时观察只能使用当前可见数据。
2. 信号日复盘只能使用信号日及以前数据生成当时的辅助线。
3. 后验走势只能进入复盘、归因和报告，不得参与信号日线位计算。
4. 摆动点确认需要滞后时，必须记录 `confirmation_date`。

### 7.3 数据质量状态

所有结果必须返回状态：

1. `ok`：数据满足计算要求。
2. `stale`：数据过期。
3. `insufficient`：样本不足。
4. `no_data`：没有可用数据。
5. `blocked`：数据异常，禁止输出结构结论。
6. `research_only`：只能研究展示，不能进入生产观察。

## 8. 计算规则

### 8.1 候选生成

后端先生成候选线，再合并为可展示线。

候选来源包括：

1. 摆动高低点。
2. 平台高低点。
3. 成交密集区。
4. 均线。
5. Anchored VWAP。
6. 缺口。
7. 涨跌停相关关键价。
8. 盘中关键价。

### 8.2 候选合并

价格接近的候选合并成区间。

合并参考：

1. 个股价格精度。
2. ATR 波动率。
3. 最近 20 日平均振幅。
4. 候选来源数量。
5. 成交量和成交额权重。

### 8.3 强度评分

强度评分范围为 0 到 100，仅表达观察可信度。

加分项：

1. 多来源共振。
2. 多次触碰有效。
3. 成交密集。
4. 近期有效。
5. 大盘和板块结构共振。

降级项：

1. 数据过期。
2. 样本不足。
3. 停牌或极端缩量。
4. 一字板主导。
5. 线位过旧。
6. 近期被反复击穿。

### 8.4 失效条件

每条线必须输出失效条件。

示例口径：

1. 收盘价有效跌破支撑区下沿。
2. 收盘价有效站回压力区上沿。
3. 通道线被连续两个完整交易日破坏。
4. 盘中线仅对当日有效，收盘后自动过期。

失效条件只用于风险观察，不生成动作指令。

## 10. API 需求

优先复用现有 key-levels API；若现有契约不能表达图表辅助线，再增量新增接口。

建议接口：

1. `GET /api/key-levels/{scope}/{symbol}/auxiliary-lines`
2. `GET /api/key-levels/{scope}/{symbol}/auxiliary-lines/history`
3. `POST /api/key-levels/auxiliary-lines/recompute`

查询参数：

1. `timeframe`
2. `as_of`
3. `include_intraday`
4. `include_research`
5. `max_lines`
6. `chart_width`

接口要求：

1. OpenAPI 和前端 generated types 必须同步。
2. 缺数据时返回明确状态和原因。
3. 默认不返回研究线，除非显式打开研究参数和 feature flag。
4. 重计算请求只创建 worker task，Web 不直接执行重计算 loop。

## 11. 前端需求

### 11.1 图表叠加层

图表必须支持：

1. 支撑区和压力区色带。
2. 水平线。
3. 趋势线。
4. 通道上下沿和中轴线。
5. MA 线。
6. Anchored VWAP。
7. 成交密集区。
8. 盘中 VWAP 和日内关键价。

### 11.2 交互

1. 鼠标悬停显示线位来源、强度、距离和失效条件。
2. 点击线位打开详情抽屉。
3. 支持按线型开关显示。
4. 支持只显示最重要的 3 到 5 条线。
5. 支持展示全部线位表格，表格使用 `DataTable`。
6. 长证据列表使用 `VirtualCardList`。
7. 新面板必须懒加载，避免拖慢首屏。

### 11.3 页面落点

优先落点：

1. 个股分析页。
2. 监控页个股详情。
3. 策略跟踪详情抽屉。
4. 模拟盘持仓详情。
5. 复盘报告页面。

页面文案：

1. 用“支撑、压力、通道、观察、失效、数据不足”等词。
2. 不使用交易指令文案。
3. 数据不足时直接展示原因。
4. 研究线必须带 `research_only` 标识。

### 11.4 导出

支持导出：

1. 带辅助线截图。
2. Markdown 复盘摘要。
3. JSON 线位证据包。

导出必须包含：

1. 标的。
2. 时间范围。
3. 数据截止时间。
4. 引擎版本。
5. 数据质量。
6. 非交易指令声明。

## 12. Worker、缓存与性能

1. 日线辅助线可由 runtime worker 或 analytics worker 预计算。
2. 分钟线辅助线由 runtime worker 按需刷新。
3. Web 请求只读缓存或轻量聚合，不新增后台 loop。
4. 缓存 key 必须包含 `symbol`、`scope`、`timeframe`、`as_of`、`engine_version`。
5. 缓存过期时返回 `stale`，并提示最近可用时间。
6. 单次页面默认最多展示 20 条线，更多线进入详情表。
7. 全市场扫描必须分页或异步任务化。

## 13. Feature Flag

新增能力默认关闭。

建议 flags：

1. `TQUANT_AUXILIARY_LINES_ENABLED=false`
2. `TQUANT_AUXILIARY_LINES_INTRADAY_ENABLED=false`
3. `TQUANT_AUXILIARY_LINES_RESEARCH_ENABLED=false`
4. `TQUANT_AUXILIARY_LINES_EXPORT_ENABLED=false`

关闭要求：

1. 监控页回到既有展示。
2. 策略跟踪回到既有展示。
3. 模拟盘回到既有展示。
4. 生产排序不变。
5. API 返回禁用状态或隐藏入口，不产生空结论。

## 14. 测试要求

### 14.1 后端测试

必须覆盖：

1. 水平支撑压力线计算。
2. MA5 / MA10 / MA20 / MA30 / MA60 输出。
3. 趋势线锚点选择。
4. 通道线上沿、下沿、中轴线计算。
5. Anchored VWAP 计算。
6. 成交密集区合并。
7. 缺数据降级。
8. 过期数据降级。
9. feature flag 关闭回退。
10. 防未来函数。
11. API schema 稳定性。

### 14.2 前端测试

必须覆盖：

1. flag 关闭时入口不可见或降级展示。
2. 加载态、空数据、错误态、过期态。
3. 线型开关。
4. 悬停说明。
5. 详情表格。
6. 移动端信息密度。
7. 图表截图基础渲染。

### 14.3 回测与复盘验证

必须验证：

1. 信号日辅助线只使用当日及以前数据。
2. 后验数据只用于复盘评价。
3. 辅助线标签不改变生产排序。
4. 支撑失效和压力重新站回的统计只作为研究归因。
5. 000533 这类单票样例可复现同一组线位和结论口径。

## 15. 验收标准

### 15.1 功能验收

1. 单票页面可展示支撑区、压力区、MA、趋势线、通道线。
2. 每条线可解释来源、强度和失效条件。
3. 数据不足时不输出伪结论。
4. 研究线和生产观察线明确区分。
5. 可导出带辅助线的图和结构摘要。

### 15.2 工程验收

1. OpenAPI 与 generated types 同步。
2. 后端相关测试通过。
3. 前端 lint、test、build、analyze 通过。
4. `git diff --check` 通过。
5. flag 关闭回退验证通过。
6. Web 不新增后台重计算 loop。

### 15.3 业务边界验收

1. 不影响 low-buy、priority board、front-row weighted 或任何既有生产排序。
2. 不产生生产分。
3. 不修改策略政策。
4. 不输出交易动作、仓位动作或收益承诺。

## 17. 风险与降级

1. 分钟数据覆盖不足：盘中线返回 `no_data`。
2. 历史数据复权不一致：返回 `blocked` 并提示复权口径冲突。
3. 摆动点过少：趋势线和通道线返回 `insufficient`。
4. 极端行情导致通道失真：标记 `research_only`。
5. 前端图表性能下降：默认只展示高优先级线，详情按需加载。
6. 用户误读线位为指令：所有文案保持观察语义，并展示非交易指令说明。

## 20. 审核强化条款（2026-06-03，与对应章节同等效力，冲突时以本节为准）

> 本节为 2026-06-03 独立审核补充，针对实施期必然咬人的缺口。严重度 S1=实施前必须落实，S2=强烈建议，S3=完善项。条款编号 G-x。

### 20.1 与既有 AKeyLevel 同源（强化 §2 / §5 / §9）

- **G1〔S1〕单一候选核心：** 辅助线必须复用既有 `backend/app/services/key_levels/engine.py` 的候选生成与合并/评分（`_merge_candidates` / `build_swing_candidates` / `build_volume_profile_candidates` / `build_anchored_vwap_candidates`），辅助线集合 = 在同一候选上补 trend/channel/slope/display_priority 的**更丰富投影**；`KeyLevelResult` 与辅助线集合互为同源视图。**禁止第二套合并/评分实现**（避免双引擎口径漂移）。
- **G2〔S2〕版本与线型矩阵：** `engine_version` 随新增 trend/channel 升级（如 `akey-level-v2`），契约新增 `supported_line_types[]`；旧缓存按 version 失效。
- **G24〔S2〕代理口径恒 research_only + 复用联动：** `scope=market/sector` 基于成分股等权代理序列时，`data_quality` 恒 `research_only`（与 `engine.py` 现有行为一致）；三层联动**复用既有 `linkage.py`**（大盘/板块跌破→个股支撑降级），禁止重写。

### 20.2 缓存 / 调度 / 性能（强化 §12）

- **G3〔S1〕缓存存储可扩展：** 辅助线物化**不得**沿用 `SystemSetting` 单行大 JSON（全市场不可扩展）；改用专用表或 analytics 存储；保留缓存 key `symbol/scope/timeframe/as_of/engine_version`，并补**旧 `as_of` 清理策略、单 payload 体积上限、命中读走精确键（不得 `LIKE prefix:%` 扫描）**。
- **G4〔S1〕物化必须接调度器：** 明确“收盘后由调度器每日 enqueue 辅助线物化任务”（runtime/analytics worker 消费），并补“调度任务被登记/被消费”的测试；否则线上所有读恒 `stale`。

### 20.3 API / 鉴权 / 契约（强化 §9 / §10）

- **G5〔S2〕鉴权与重算入口：** 所有 `key-levels/*` 端点 `Depends(get_current_user)`；`POST .../recompute` 额外 `require_admin_auth` 且只建 worker task；GET 端点严禁触发计算，出现 `refresh`/`recompute` 等同步重算参数即返回 422。
- **G11〔S2〕删除 `chart_width`：** 该参数把像素渲染耦合进计算，移除；线的取舍由 `max_lines` + `display_priority` 决定，前端按需裁剪。
- **G12〔S2〕补全子 schema 与坐标系：** 定义 `zone`（`zone_low/high/role/strength/evidence`）与 `confluence`（`price_low/high/sources[]/strength`）；`slope` 明确为“价格/交易日，基于 `anchor_base_date`”，单条线补 `as_of_touch_dates[]`。
- **G13〔S3〕`line_id` 稳定派生：** `line_id = hash(scope|symbol|line_type|role|关键锚点)`，跨日稳定、可追溯；history 据此跟踪同一条线演化。
- **G14〔S3〕history 端点：** 只读已存快照、不重算，必须分页/限量。

### 20.4 计算口径与防未来函数（强化 §5.3 / §5.4 / §7 / §8）

- **G6〔S1〕趋势线/通道线算法确定化：** 摆动点分形窗口、有效触点容差(%)、最少触点数、拟合方法（穿点/回归）、最多趋势/通道线数，**全部写成配置常量**；未确认摆动点标 `pending`，不作强证据；保证同输入同输出可复现。
- **G7〔S1〕摆动点确认滞后（隐蔽未来函数）：** 明确“摆动点确认滞后 = 右侧 K 根”；复盘只用 `confirmation_date ≤ as_of` 的摆动点；新增**专门的确认滞后防未来函数测试**。
- **G8〔S2〕复权一致 + 除权除息：** 回看窗口内复权口径必须一致；**除权除息跳空必须识别并排除**，不计入缺口锚点/通道失真（口径冲突仍按 §17.2 返回 `blocked`）。
- **G9〔S2〕“有效跌破/站回”定义：** “有效 = 收盘 < 下沿×(1−buffer) 且 连续 ≥N 个完整交易日”（buffer/N 为配置），并与既有 AKeyLevel 失效口径统一为单一事实源。
- **G10〔S2〕复盘盘中边界：** `data_cutoff` 精确到日内时点；复盘默认**不纳入信号日当天盘中数据**（或纳入但 `data_cutoff` 标到具体时刻），并测试，杜绝把当日盘中结果回灌进信号日判断。

### 20.5 前端 / 图表（强化 §11）

## 21. 智能画线（Smart Auto-Drawing，2026-06-03 合入，强化 §5 / §8 / §9 / §11 / §13 / §16）

> 智能画线是辅助线的“自适应与可解释增强”，**不是新的预测或买卖工具**。分三层，能力与风险递增，默认全部 feature flag 关闭；与 §20 同等效力，冲突以本节为准。

### 21.1 能力分层

- **L1 自适应选线 / 共振（确定性，建议随主线落地）：** 从 §8 全部候选里，按“距现价、强度、role 平衡、共振来源数、大盘/板块联动”自动挑出最相关的 N 条线与共振区呈现，即 `display_priority`（G17）+ `confluence`（G12）的智能表达。**确定性、可复现、可解释。**
- **L2 智能锚点 / 智能确认（规则增强）：** 自适应选 Anchored VWAP 锚点（最近涨停/放量/缺口）、摆动点（含 G7 确认滞后）、平台边界；按 ATR / 近 20 日振幅自适应合并容差。**仍是规则，不是模型。**
- **L3 模型辅助（`research_only`，必须回测）：** 可选用轻量模型/算法提议趋势线、通道、形态（如自动拟合主导趋势线、通道平行度评分、相似历史结构匹配）。**默认关、研究态、不进生产观察/排序，受既有 ML 任务门控（`tquant_ml_jobs_enabled` 体系）约束，重计算走 worker。**

### 21.2 硬边界（叠加在 §2 业务边界 + §20 之上）

- **不输出买卖点/仓位/止损/收益**：智能画线只产线位 + 强度 + 证据 + 失效条件 + §6 允许的结构标签；不得衍生交易动作。
- **可解释强制**：每条智能线必须给 `evidence`（锚点/触点/共振来源）与 `strength`；**无证据的黑盒线不得展示**。
- **可复现强制**：同输入 + 同 `engine_version` + 同参数 → 同一组线（golden 测试）；L3 模型必须固定 artifact 版本并记 `model_version`。
- **无未来函数**：L1/L2/L3 一律只用 `as_of` 及之前数据；L3 模型训练数据截止 < `as_of`，复盘遵守 G7 摆动点确认滞后。
- **`research_only` 门控**：L3 及任何模型/学习成分默认 flag-off、标 `research_only`，不进生产观察/排序/打分，不改策略政策。
- **不引新栈、不黑盒出图**：渲染仍 ECharts（§19 / §20.5）；L3 即便用模型，输出仍是结构化线位 + 证据，不直接生成图文断言。
- **文案守卫**：智能线说明与摘要同样过“无 建议买入/卖出/低吸/必涨/突破即买”守卫（G21）。
- **代理口径**：`scope=market/sector` 的智能线仍恒 `research_only`（G24）。

### 21.3 契约增量（在 §9 基础上）

- 单条线新增：`generation_mode`（`rule` / `adaptive` / `model`）、`model_version`（仅 `model` 模式）、`confidence`（0–100，**与 `strength` 区分**：`confidence` 表达“画线本身可信度”，`strength` 表达“该线作为关键位的观察强度”）。
- 集合新增：`smart_summary`（自适应挑出的 top 线/共振的可解释说明，随 `mode` 带 `research_only` 标识）。

### 21.4 Feature Flag（在 §13 基础上）

- `TQUANT_AUXILIARY_LINES_SMART_ENABLED=false`（L1 / L2 自适应）
- `TQUANT_AUXILIARY_LINES_SMART_MODEL_ENABLED=false`（L3 模型，且受 `tquant_ml_jobs_enabled` 二次门控）

关闭时：智能线入口隐藏，辅助线回到 §13 既有行为，不出空结论、不影响生产排序。

### 21.5 测试增量（在 §14 基础上）

- L1 / L2 确定性 golden 测试（同输入同输出）；自适应选线**至少 1 支撑 + 1 压力**。
- L3 模型：固定 artifact 复现、训练数据截止防未来函数、`research_only` 不进生产硬断言、回测胜率/可信度披露。
- 文案守卫覆盖智能线说明与 `smart_summary`。

### 21.6 落地建议（在 §16 G 批次基础上）

- **L1** 随 G2/G3 落地（自适应选线/共振，几乎零额外风险）。
- **L2** 随 G2/G3 锚点强化落地。
- **L3** 单列为后续研究批次（建议 G7-research），默认关、先回测证伪，**不阻塞 G0–G6 主线交付**。

### 21.7 明确不做

- 不做“智能买卖点 / 智能仓位 / 智能止损动作”。
- 不把模型识别的“主力行为/出货/吸筹”当事实。
- 不做不可解释、不可复现的黑盒线。
- 不因智能画线改变生产排序、生产分或策略政策。
