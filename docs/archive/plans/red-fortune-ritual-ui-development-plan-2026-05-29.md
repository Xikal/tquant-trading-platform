# TQuant 红运仪式感视觉层开发方案

## 1. 背景

平台当前定位是 A 股量化交易 Web 工具，核心能力来自策略、回测、实时监控、模拟盘、风控和市场复盘。用户希望加入一些有“美好寓意”的玄学特点，例如红色象征上涨、红运、好兆头，但明确要求：

- 不影响决策。
- 不参与策略计算。
- 不影响排序。
- 不触发买卖。
- 只作为仪式感和视觉氛围。

因此，本方案将该能力定义为：**红运仪式感视觉层**。

它是一个可开关的轻量 UI 皮肤和文案层，只负责提升使用体验、情绪氛围和仪式感，不改变任何交易结论。

## 2. 目标

1. 新增“红运仪式感”开关。
2. 在不影响现有页面信息密度的前提下，为平台增加红金色寓意、轻量动效和仪式文案。
3. 在实时监控、选股宝典、策略跟踪、模拟盘、登录页等页面加入统一但克制的红运视觉元素。
4. 所有红运内容必须明确是装饰和寓意，不作为投资建议。
5. 默认不污染专业模式；用户可在系统设置中关闭。

## 3. 核心原则

### 3.1 只做视觉，不做决策

红运仪式感不得参与：

- 策略评分
- 候选排序
- 买卖信号
- 仓位建议
- 止盈止损
- 模拟盘自动交易
- 回测指标
- 风控判断

### 3.2 数据只读引用

红运文案可以读取已有页面状态，例如：

- 市场强弱
- 复盘状态
- 买点状态
- 策略跟踪生命周期
- 模拟盘盈亏状态

但只能用于选择展示文案或视觉氛围，不能反向写回业务数据。

### 3.3 克制表达

避免：

- 赌博感
- 夸张荐股感
- “必涨”“稳赚”“上上签必买”等误导性词语
- 遮挡核心数据
- 大面积闪烁动效
- 影响阅读效率

推荐表达：

- 红运临门
- 静待东风
- 守正待机
- 红而不躁
- 绿而不慌
- 买点已至
- 火候未到
- 过火勿追

## 4. 功能模块

## 4.1 系统设置开关

在系统设置中新增：

```text
红运仪式感
```

配置项：

- `ritual_ui_enabled`
- 默认值：`true` 或 `false` 均可，建议默认 `true` 但保持轻量；如果担心专业性，默认 `false`。
- 用户可随时关闭。

建议附加选项：

- `ritual_ui_intensity`: `subtle | standard`
- 默认：`subtle`

不建议提供过多配置，避免设置页膨胀。

## 4.2 红运状态条

位置：

- 顶部导航右侧
- 或实时监控首屏指标区

展示内容：

```text
今日红运：守正待机
今日红运：静待东风
今日红运：红盘有望
今日红运：红而不躁
```

生成规则：

- 可按市场状态轻微变化。
- 也可以按日期稳定随机，确保当天刷新后文案不频繁跳变。
- 不展示具体个股，不给交易动作。

验收标准：

- 关闭红运开关后完全隐藏。
- 不影响顶部导航布局。
- 移动端不换行挤压主导航。

## 4.3 开盘祈愿卡

位置：

- 每天首次进入平台时，以小弹窗或轻量浮层展示。

文案示例：

```text
愿今日少追高，多从容。
愿买点清晰，止损果断。
愿红盘常在，纪律先行。
愿顺势而为，不急不躁。
```

规则：

- 每天最多展示一次。
- 用户关闭后当天不再出现。
- 不阻塞页面使用。
- 不遮挡登录框或核心工作区。

实现建议：

- 使用 `localStorage` 记录当天已展示状态。
- key 示例：`tquant:ritual:daily-blessing:YYYY-MM-DD`

## 4.4 幸运签

位置：

- 顶部导航用户区旁边放一个小图标按钮。
- 或系统设置里提供“抽一签”入口。

签文分类：

- 红运签
- 守正签
- 风控签
- 复盘签

文案示例：

```text
红运签：红而不躁，绿而不慌。
守正签：机会常有，仓位为先。
风控签：先守本金，再等东风。
复盘签：今日得失，明日成章。
```

限制：

- 不出现股票代码。
- 不出现“买入”“卖出”“满仓”等直接指令。
- 不绑定策略结论。

## 4.5 买点红印

位置：

- 选股宝典候选卡片。
- 策略跟踪列表。
- 单票详情抽屉。

展示方式：

- 小红印章、红金标签、轻量边角标。

状态映射：

| 原业务状态 | 仪式感文案 | 含义 |
|---|---|---|
| `buy_now` | 买点已至 | 已有业务信号，不新增判断 |
| `soft_buy_now` | 红运临近 | 小仓试买语义 |
| `near_entry` | 火候未到 | 接近买点但还需等 |
| `observe_confirmed` | 静候确认 | 观察确认 |
| risk / stopped | 过火勿追 | 风险提示 |

要求：

- 仪式文案不能替代原业务状态。
- 原状态仍必须显示。
- 红印只是视觉增强。

## 4.6 收盘福袋

位置：

- 实时监控页收盘复盘区域。

展示示例：

```text
今日收盘福袋：守住本金，也是胜利。
今日收盘福袋：明日再看风向。
今日收盘福袋：纪律还在，机会就在。
```

规则：

- 只在收盘复盘后展示。
- 和复盘结论分区展示，不能混进正式复盘文本。
- 关闭红运开关后隐藏。

## 4.7 节气 / 日历点缀

位置：

- 登录页角落。
- 实时监控页顶部轻量展示。

展示内容：

```text
今日宜：复盘、轻仓、等确认
今日忌：冲动、满仓、追高
```

规则：

- 文案来自固定池。
- 不需要联网。
- 不做复杂农历计算时，可先基于日期稳定随机。
- 后续如需真实节气，可独立扩展。

## 4.8 登录页红金氛围

当前登录页已有动态金融特效，可增加红运仪式感元素：

- 红金流光线。
- 轻量上行 K 线光点。
- 红色印章纹理。
- 金色细线网格。

要求：

- 登录框仍居中。
- 特效不能影响输入性能。
- 移动端降低动效复杂度。
- 遵守 `prefers-reduced-motion`。

## 5. 页面接入范围

### 5.1 实时监控

接入：

- 红运状态条
- 收盘福袋
- 今日宜忌
- 轻量红金氛围

不做：

- 不改变市场复盘结论。
- 不改变风险提示。
- 不隐藏 data_quality。

### 5.2 选股宝典

接入：

- 买点红印
- 候选状态仪式感标签
- 幸运签入口

不做：

- 不改变候选排序。
- 不新增玄学筛选器。
- 不用红运文案替代策略原因。

### 5.3 策略跟踪

接入：

- 红榜 / 避险榜的视觉点缀。
- 单票详情中的推荐日红印。
- 生命周期节点红金标记。

不做：

- 不改变推荐后收益统计。
- 不改变策略表现评价。

### 5.4 模拟盘

接入：

- 持仓页轻量福袋文案。
- 盈亏区域红金祝福文案。

不做：

- 不影响自动交易。
- 不影响委托记录。
- 不影响止盈止损建议。

### 5.5 登录页

接入：

- 红金动态金融特效增强。
- 今日红运短句。

不做：

- 不增加登录阻塞弹窗。
- 不影响表单输入。

## 7. 视觉设计方向

### 7.1 风格

方向：**红金东方金融仪式感**。

关键词：

- 红金
- 克制
- 轻微流光
- 印章
- 细线金融图形
- 上行光点
- 专业工具感

避免：

- 大红大紫
- 赌场风
- 迷信符咒
- 低俗动效
- 过度节庆化

### 7.2 色彩建议

```css
--ritual-red: #d92d20;
--ritual-red-deep: #9f1f18;
--ritual-gold: #d6a84f;
--ritual-gold-soft: #f3d58a;
--ritual-ink: #2b1a12;
--ritual-bg-soft: rgba(217, 45, 32, 0.06);
```

注意：

- 不替换平台主色。
- 只作为点缀色。
- 不让页面变成单一红色主题。

### 7.3 动效建议

允许：

- 轻微流光。
- 标签淡入。
- 红印轻微缩放。
- 登录页背景低频动画。

禁止：

- 高频闪烁。
- 大面积粒子。
- 遮挡文字。
- 影响表格滚动。
- 移动端重动画。

必须支持：

```css
@media (prefers-reduced-motion: reduce) {
  /* 关闭或减少动画 */
}
```

## 9. 后端影响

原则上本功能可以纯前端实现，不要求后端参与。

如需跨设备同步用户偏好，可以后续接入设置接口。

本轮建议：

- 优先前端 localStorage。
- 不新增数据库表。
- 不修改策略接口。
- 不修改回测接口。
- 不修改模拟盘接口。

如果接入设置页：

- 只新增 UI 偏好字段。
- 不影响已有 settings 持久化。
- masked/sensitive 字段逻辑不受影响。

## 10. 测试要求

### 10.1 单元测试

覆盖：

- signal state 到红印文案映射。
- 每日文案稳定随机。
- 红运开关关闭时组件不渲染。
- `prefers-reduced-motion` 下不会依赖动画才能显示内容。

### 10.2 组件测试

覆盖：

- `RitualFortuneStrip`
- `RitualSignalSeal`
- `RitualBlessingModal`
- `RitualLuckyDraw`
- `RitualCloseBag`

### 10.3 页面测试

覆盖：

- 实时监控开启/关闭红运视觉层。
- 选股宝典买点红印。
- 策略跟踪红榜/避险榜视觉点缀。
- 登录页红金特效不遮挡表单。

### 10.4 视觉回归检查

至少检查：

- 375px
- 768px
- 1440px

检查点：

- 不遮挡核心数据。
- 不产生横向滚动。
- 不压缩导航按钮。
- 表格仍可读。
- 移动端动效不过重。

## 11. 验收标准

1. 系统设置或本地偏好可关闭红运仪式感。
2. 关闭后所有红运元素消失，页面恢复专业模式。
3. 开启后实时监控、选股宝典、策略跟踪、模拟盘、登录页有轻量红运视觉。
4. 红运内容不参与策略计算、排序、回测、交易、风控。
5. 页面无重叠、无遮挡、无大面积留白。
6. 移动端可用。
7. 前端构建体积无明显膨胀。
8. 不引入新的大体积依赖。
9. 所有文案不构成投资建议。

## 12. 风险控制

| 风险 | 控制方式 |
|---|---|
| 用户误以为红运代表买入建议 | 明确只做视觉寓意，不替代原状态 |
| 页面变得不专业 | 默认轻量，支持关闭 |
| 动效影响性能 | CSS-only、低频、移动端降级 |
| 遮挡数据 | 不使用覆盖核心内容的大浮层 |
| 代码膨胀 | 组件化、文案池集中管理 |

## 14. 不做事项

本轮不做：

- 不新增玄学策略。
- 不新增玄学排序。
- 不修改策略分数。
- 不修改买卖信号。
- 不修改模拟盘自动交易。
- 不引入真实占卜、星座、八字等敏感或迷信逻辑。
- 不展示“必涨”“稳赚”“上上签买入”等误导文案。
