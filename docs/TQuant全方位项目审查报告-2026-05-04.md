# TQuant 全方位项目审查报告

**日期**: 2026-05-04
**审查范围**: 后端 47,499 行 Python + 前端 11,701 行 TypeScript + 7,794 行 CSS + 39 份文档
**审查维度**: 架构、策略逻辑、数据性能、前端、模拟盘、Agent 接入、安全、测试、部署
**审查方法**: 7 个专项 Agent 并行审查，覆盖全部 272 个后端文件、77 个前端文件、所有主要业务链路

---

## 一、总体结论

### 1.1 是否达到"可正式使用"的程度

**当前阶段：Pilot-ready（内测可用），非 Production-ready（正式生产不可）。**

项目已经具备一个完整的量化辅助平台骨架：12 策略低吸引擎、模拟盘完整生命周期、多 Agent 架构接入、飞书通知、移动端 App。代码整体质量在开源量化项目中处于中上水平——强类型、ORM 参数化、分层清晰、核心策略管线有真实业务测试覆盖。

但在以下 5 个方向上存在关键缺口，阻塞直接上线：

1. **性能与并发**：uvicorn 单 worker、内存限流（多进程失效）、无分页接口、N+1 查询风险
2. **安全加固**：Feishu webhook 验证绕过、Docker root 运行、Nginx 缺少安全头、subprocess 注入风险
3. **策略信号证实**：3 个 AUXILIARY daily_history 策略无历史信号验证（SQLite 此前不扫描），RESEARCH 策略被过度压制
4. **前端架构**：MobileApp.tsx 单文件 1,062 行、TradingWorkspace 515 行、6+ 重复格式化函数
5. **测试缺口**：前端零测试、模拟盘内部逻辑零测试、量化引擎执行零测试、无覆盖率度量

### 1.2 最大的 5 个风险

| 排名 | 风险 | 影响 |
|------|------|------|
| 1 | AUXILIARY daily_history 策略从未在 SQLite 下扫描，信号行为完全未知 | 3 个策略无历史验证就上线 |
| 2 | 单 worker + 内存限流 = 多进程部署下 rate limit 无意义 | 可被绕过 |
| 3 | Feishu webhook 验证空 token 时静默接受所有请求 | 攻击者可伪造事件 |
| 4 | 前端零测试 + MobileApp.tsx 单体 1,062 行 | 移动端 Bug 无法回归 |
| 5 | `divergence_consensus` 策略 entry_zone 设计导致信号永远无法触发 | 无效策略代码 |

### 1.3 最值得优先优化的 5 个方向

1. **策略信号验证**：先让 3 个 AUXILIARY daily_history 策略在真实数据上产出信号，确认 quality gate 合理后再上线
2. **安全加固**：修复 Feishu verify_token 绕过 + Docker 非 root + 路径穿越防护 + Nginx 安全头
3. **前端拆分**：MobileApp.tsx 拆分为 Tab 级组件 + 提取共享 formatters 消除 6+ 重复函数
4. **基础设施**：gunicorn 多 worker + Redis 限流 + 分页 + 覆盖率度量
5. **测试补全**：前端组件测试 + 模拟盘单元测试 + 策略管线回归测试

| 策略 | 当前层级 | 建议 | 理由 |

### 3.2 新增过滤器建议

- **板块主线过滤器**: `sector_mainline_first_divergence_low_buy` 已依赖 `requires_mainline_industry`，建议扩展到 `first_board` 和 `classic_retrace`——非主线板块的首板/回踩胜率显著降低
- **市场状态白名单**: `core_midcap_vwap_ma5_retrace` 在中军行情下应仅在 `broad_rally`/`weight_support_active` 下产生信号，当前 market profile 未区分
- **情绪周期过滤器**: 新增涨停家数/炸板率/连板高度等情绪指标，在全市场情绪极差时全局降级信号（当前仅市场状态 8 分类）

### 3.3 提升胜率与可解释性建议

- **性能归因面板**: performance.py 已计算按行业/回踩天数/市场状态分桶的胜率，但前端未展示——建议在 PerformanceDashboard 增加 Strategy Performance 分桶图表
- **样本量标注**: 每个策略的信号旁标注"近 60 日样本量 N，胜率 X%"，避免用户对小样本策略过度信任
- **信号原因透明度**: `position_breakdown_text` 已展示仓位理由，但策略选择理由（为何此策略选中此标的）缺失——建议在 StockCard 增加"策略匹配理由"字段

- **priority board 合并**: 多个策略共用同一候选池时重复计算 metrics——候选池级别缓存
