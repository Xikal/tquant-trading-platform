## 三、本次审查新发现的优化建议

以下建议不在任何已有计划文档中，是在代码审查中新发现的问题和改进机会。

### 🔴 运营风险类

#### 建议 1：初始化 Git 版本控制

**当前状态**：项目无 `.git` 目录，无任何版本控制。

**风险**：无法回滚、无法协作、无法审计变更。这是一个 30K+ 行的生产系统，没有版本控制是最高优先级风险。

**建议**：
```bash
cd /Users/j/Documents/gupiao
git init
git add -A
git commit -m "Initial commit: TQuant trading platform"
```

后续建立分支策略：`main`（生产）、`develop`（开发）、`feature/*`（功能分支）。

#### 建议 2：建立 CI/CD 流水线

**当前状态**：无 GitHub Actions、无 GitLab CI、无任何自动化流水线。

**影响**：每次部署依赖手工操作（脚本 + Docker），无自动化测试、无 lint 检查、无构建验证。

**建议**（以 GitHub Actions 为例）：
- `lint` job：Python ruff/flake8 + TypeScript tsc --noEmit
- `test` job：pytest + vitest
- `build` job：Docker build + 推镜像
- `deploy` job：SSH 到云服务器 → docker-compose up -d

#### 建议 3：数据库备份策略

**当前状态**：SQLite 数据库（`data/t_quant.db`，4.3 MB）运行在云服务器上，无自动备份。

**风险**：数据库损坏或误删后无法恢复所有模拟盘交易记录和用户数据。

**建议**：
- 每日定时备份 SQLite 文件到 `/backups/` 目录
- 保留最近 7 天的每日备份 + 最近 4 周的每周备份
- 备份脚本加入定时任务（cron）

#### 建议 4：HTTPS 终止

**当前状态**：服务以 HTTP 运行在 `http://43.143.243.97:18090`。

**风险**：密码和 token 明文传输，可被中间人截获。

**建议**：
- 在云服务器上安装 nginx 作为反向代理
- 使用 Let's Encrypt（certbot）配置 HTTPS
- nginx 终止 TLS，转发到后端 18090 端口
- 设置 HTTP → HTTPS 强制跳转

### 🟠 代码质量类

#### 建议 5：API 限流

**当前状态**：`backend/app/core/rate_limit.py` 存在，但需要确认是否已接入关键路由（特别是 `/api/auth/login` 和 `/api/auth/register`）。

**风险**：登录/注册接口无频率限制，可被暴力破解或 DDoS。

**建议**：
- 登录接口：每分钟最多 5 次（防暴力破解）
- 注册接口：每 IP 每小时最多 3 次（防滥用）
- 全局限流：每 IP 每秒最多 30 次
- 使用 FastAPI 的 `slowapi` 或当前 rate_limit 模块

#### 建议 6：请求体大小限制

**当前状态**：FastAPI 默认无请求体大小限制。

**风险**：恶意用户可上传超大 JSON body 耗尽服务器内存。

**建议**：
- 在 FastAPI app 初始化时设置请求体大小上限（如 1MB）
- 文件上传接口单独设置限制
- Nginx 层面也设置 `client_max_body_size`

#### 建议 7：结构化日志

**当前状态**：后端使用 Python `logging` 模块，日志格式为文本行。

**建议**：
- 改用 JSON 格式的结构化日志（`python-json-logger` 或自定义 formatter）
- 统一日志字段：timestamp、level、module、message、request_id、user_id、duration_ms
- 便于后续接入日志聚合系统（ELK / Loki / 云日志服务）

#### 建议 8：健康检查增强

**当前状态**：`/readyz` 返回 `{"status": "ok"}`，不检查数据库连接。

**风险**：数据库挂了但健康检查仍然通过，负载均衡继续转发流量。

**建议**：
```python
@router.get("/readyz")
def readyz(db: Session = Depends(get_db)):
    try:
        db.execute(text("SELECT 1"))
        return {"status": "ok", "database": "connected"}
    except Exception:
        raise HTTPException(status_code=503, detail="database unavailable")
```

#### 建议 9：密码哈希参数调优

**当前状态**：PBKDF2-HMAC-SHA256，210,000 次迭代。

**风险**：210K 迭代在高并发登录时可能导致 CPU 尖峰。对于云服务器（通常是 1-2 vCPU），每次登录约 100-200ms 纯 CPU 时间。

**建议**：
- 当前 210K 迭代安全等级足够，但可在登录接口加上限流（见建议 5）来缓解
- 生产环境建议使用 bcrypt（更高的内存成本，更抗 GPU 攻击）
- 不紧急但值得记录为 future work

#### 建议 10：pytest 依赖加入 requirements.txt

**当前状态**：`requirements.txt` 不含 pytest、pytest-cov、httpx。

**建议**：创建 `requirements-dev.txt`：
```
pytest>=7.0
pytest-cov>=4.0
httpx>=0.24  # FastAPI TestClient 依赖
coverage>=7.0
ruff>=0.1
```

## 六、关键架构决策记录

以下决策在之前的开发中已经确定，本文档不做重新讨论，仅记录供后续参考：

1. **不引入 Agent 框架**：Hermes / LangGraph / CrewAI 均不接入。模拟盘用纯 Python 确定性规则，LLM 仅用于收盘日报。
2. **不拆分后端微服务**：保持 FastAPI 单体，避免分布式复杂度。
3. **不换语言**：Python + Cython 路线在性能达标后不需变动。
4. **Web 与 App 共用认证**：同一套 `/api/auth/*` JWT 体系，`device_name` 参数区分。
5. **白名单用布尔字段**：`can_paper_trade: bool`，不做独立白名单表或完整 RBAC。
6. **不引入 Redis**：缓存用 Python 进程内 dict + TTL，不增加外部依赖。
7. **SQLite 继续用于单机部署**：MySQL 仅作为可选替代，不强制迁移。
