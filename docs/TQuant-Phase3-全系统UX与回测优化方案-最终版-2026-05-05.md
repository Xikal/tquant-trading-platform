# TQuant Phase 3 全系统 UX 与回测优化方案（最终版）

**日期**: 2026-05-05
**版本**: v2.0（两份 Phase 3 文档融合版）
**前置文档**: [Phase 2 最终版需求文档](./TQuant回测Phase2需求文档-最终版-2026-05-05.md)、[Phase 2 审查报告](./TQuant回测Phase2审查报告-2026-05-05.md)
**定位**: Phase 2 完成后的全面易用性革命——覆盖全部 8 个桌面页面 + 4 个移动端 Tab，回测系统作为重点深化

---

## 总纲

经过对全部 12 个界面（含移动端）的逐一摸底，TQuant 当前 UX 存在三个系统性问题：

1. **表单设计停留在开发者思维**——技术术语直接暴露给用户（`lookback_bars`、`max_position_pct`、`walk_forward_windows`），没有中文语义层
2. **共享组件分裂**——`EditableGrid` 在 WorkspaceComponents.tsx 定义了，但回测系统完全不用它，另起炉灶。格式化函数在 4 个地方重复定义
3. **移动端是桌面端的简陋复制**——两者各自实现了同一功能的不同版本，样式、交互、数据结构都不一致

本次优化不改变任何后端计算逻辑，只动前端交互层、展示层和少量后端元数据 API。目标只有一个：**让不会写代码、不懂金融工程术语的用户，也能 3 分钟内完成一次有意义的回测或信号复盘。每个页面，新用户 30 秒内知道怎么用。**

## 一、全系统共享层改造

当前碎片化状态：

| 组件 | 桌面端位置 | 回测系统位置 | 移动端位置 | 问题 |
|------|-----------|-------------|-----------|------|
| 格式化函数 | `workspaceFormatters.ts` | `BacktestDashboard.tsx` 内联 | `PaperTradingPanel.tsx` 内联 | 三套实现，行为不一致 |
| 表单构建器 | `EditableGrid` | `TextField`/`DateField`/`SelectField` | 裸 `<input>` | 三套 API，互不兼容 |
| 股票卡片 | `StockCard` | 无（不涉及） | `MobilePriorityStockCard` 等 4 个变体 | 5 套实现 |
| 指标网格 | `MetricGrid` | 内联 `Metric` | 内联 | 复用尚可，但 tone 值定义不一致 |
| 空状态 | `EmptyState` | `EmptyLine` | 内联 | 3 套实现 |

本次必须把上述分裂统一到一个 `@/components/shared/` 目录下。


### 1.1 统一格式化函数

`workspaceFormatters.ts` 作为唯一格式化来源，删除以下重复实现：
- `BacktestDashboard.tsx` 第 430-467 行的 `formatNumber`/`formatInteger`/`formatMoney`/`formatPrice`/`formatPct`/`toneFromNumber`
- `BacktestResearchPanel.tsx` 第 508-540 行的同名函数
- `PaperTradingPanel.tsx` 中的本地格式化
- 移动端各文件中的本地格式化

`workspaceFormatters.ts` 扩展为完整的格式化工具集，新增：
- `formatPercent(value, digits)` — 统一百分比（+XX.XX% / --）
- `formatRatio(value)` — 比例值自动检测 ×100
- `toneFromValue(value)` — 正/负/零三态颜色（统一桌面 up/down/neutral 和移动端 positive/negative/neutral）


### 1.2 统一表单组件

以回测系统的 `TextField`/`DateField`/`SelectField` 为基础（它们比 `EditableGrid` 更现代），统一升级：

```
@/components/shared/FormFields.tsx
├── TextField        — 文本输入 + label + hint + error
├── DateField        — 日期选择器
├── SelectField      — 下拉选择
├── NumberField      — 数字输入 + 单位后缀 + min/max/step
├── SliderField      — 滑块（含范围模式）
├── CheckboxGroup    — 多选标签
├── SearchField      — 带搜索的 combobox
```

所有页面统一使用这套组件，不再各自内联。


### 1.3 统一空状态/加载/错误组件

```
@/components/shared/Feedback.tsx
├── EmptyPlaceholder — 空状态占位（含图标 + 文字 + 可选操作按钮）
├── LoadingSpinner   — 加载态（含文字描述）
├── ErrorBanner      — 错误提示（含重试按钮）
├── InlineValidation — 行内校验错误（字段下方红色提示）
├── ToastContainer   — 全局 toast 通知系统
```

所有页面用统一的反馈组件，去掉 `EmptyLine`、`EmptyState`、`ErrorDialog` 的重复定义。


### 1.4 统一策略元数据

当前 `STRATEGY_OPTIONS` 和 `STRATEGY_TABS` 在多处硬编码。建立单一数据源：

后端新增 `GET /api/strategies/meta`，扩展到全系统共享。前端所有页面从这里拉取策略列表，不再硬编码。

响应格式：
```json
{
  "strategies": [{
    "key": "first_board",
    "name": "首板回调",
    "description": "追踪首板涨停后回调至关键均线的低吸机会",
    "category": "回调类",
    "risk_level": "medium",
    "typical_holding_days": "3-7"
  }]
}
```

收益：
- Playbook 页面的策略 Tab 不再硬编码
- 回测/优化/验证的策略下拉不再硬编码
- 新增策略只需改数据库，不需要改前端


### 1.5 骨架屏（Skeleton Loading）

所有数据驱动的面板首次加载时使用骨架屏占位，而非空白+转圈。优先实施：
- Monitor 页的优先榜
- Playbook 页的候选列表
- Analysis 页的分析结果
- 回测页的任务列表


### 1.6 全局错误恢复

所有出错面板增加"重试"按钮（调用原 API 重新请求），而非仅显示错误文字。


### 1.7 Toast 通知系统

全局 toast 组件，覆盖以下场景：

| 触发事件 | Toast 内容 | 颜色 |
|----------|-----------|------|
| 回测/优化/验证任务提交 | "回测任务已提交，预计 X 分钟完成" | 蓝色 |
| 任务完成 | "回测完成！总收益 +X%，Sharpe X.XX [查看]" | 绿色 |
| 任务失败 | "回测失败：数据不足，回测区间内无有效交易日" | 红色 |
| OOS 降级 | "样本外验证未通过：OOS Sharpe -0.23，建议暂缓实盘" | 橙色 |
| 任务取消 | "回测任务已取消" | 灰色 |
| WebSocket 断线 | "实时连接断开，正在重连..." | 黄色 |

toast 3 秒后自动消失（失败/警告类 6 秒），可手动关闭。关键消息（OOS 降级）不自动消失，需用户确认。


### 1.8 键盘快捷键

| 快捷键 | 功能 |
|--------|------|
| Cmd/Ctrl+K | 全局搜索 |
| Cmd/Ctrl+1~8 | 切换页面（1=监控, 2=分析, 3=选股, 4=研究, 5=回测, 6=模拟, 7=绩效, 8=设置） |
| Escape | 关闭弹窗/搜索面板 |


### 1.9 全局搜索（Command+K）

新增全局搜索面板（快捷键 Cmd/Ctrl+K），支持：
- 输入标的代码 → 直接跳转 Analysis 页并填入标的
- 输入策略名 → 直接跳转 Playbook 对应策略 Tab
- 输入"回测"→ 跳转回测页
- 输入"设置风控"→ 跳转 Settings 页对应卡片

实现：前端纯路由跳转，不依赖后端。

## 二、逐页面优化方案（桌面端 8 页）

### 2.1 Monitor 监控页（首页）

**当前状态**：6 个裸文本输入 + 4 面板网格布局。持仓编辑通过 `EditableGrid` 直接展示裸输入框。

**核心问题**：
- 持仓编辑暴露了 `base_position`、`available_position`、`cost_basis` 裸字段
- 新增持仓没有搜索（symbol 裸输入）
- 优先榜卡片有 4 个操作按钮挤在一起，目标不明确

**优化方案**：

1. **持仓区改为卡片模式**：当前 EditableGrid 改成卡片列表，每张卡片显示：股票名 + 代码、持仓数/可用数、成本价/现价/盈亏。点击卡片展开编辑抽屉（不常驻编辑态）。新增持仓通过顶部搜索框添加（模糊搜索标的 → 确认 → 自动创建持仓卡片）。

2. **优先榜卡片操作按钮简化**：4 个按钮（详情、分析、编辑、删除）精简为 2 个主操作：🔍 深度分析（打开 Analysis 页面跳转）、⭐ 关注（加入/移出重点关注）。删除和编辑移到卡片内展开操作。

3. **监控首页加载态优化**：首次加载时展示骨架屏，而非空白 + 转圈。


### 2.2 Analysis 分析页

**当前状态**：4 个文本输入 + 1 个 select，复杂的 3 列 6 面板布局。有 ECharts K 线图。

**核心问题**：
- 标的输入是裸文本框（需要输入 `300059`）
- 分析结果信息密度极高（决策面板、K 线图、AI 笔记、执行计划挤在一个页面）
- 用户不知道 `prefer_strategy` 的 `positive_t` / `negative_t` 是什么意思

**优化方案**：

1. **标的输入改为搜索**：替换裸文本框为 `SearchField`，输入代码或名称即时过滤。输入后自动带出底仓/可用数（如果已在持仓中）。

2. **prefer_strategy 改为中文**：下拉选项从 `positive_t`/`negative_t`/`auto` 改为"偏向做多"/"偏向做空"/"自动判断"。

3. **分析结果分层展示**（渐进式暴露）：
   - **第一层（主卡片）**：操作建议 + 入场价/止损价/止盈价 — 3 行核心信息
   - **第二层（展开详情）**：K 线图 + 阻挡规则 + 策略注释 — 需要时展开
   - **第三层（侧边栏）**：AI 完整笔记 — 可选查看

4. **快速分析入口**：Monitor 页和 Playbook 页的标的卡片上，"分析"按钮点击后直接跳转 Analysis 页并自动填入标的，省去手动输入。


### 2.3 Playbook 选股宝典页

**当前状态**：无表单字段（策略 Tab 是按钮），候选标的卡片列表。

**核心问题**：
- 策略 Tab 用硬编码常量，新增策略需改代码
- "确定买入"/"接近买点"/"继续观察"三个分组的含义没有解释
- 各策略的绩效指标（命中率、平均收益、最大回撤等）信息密度高但缺乏对比视图

**优化方案**：

1. **策略 Tab 改为 API 驱动**：从 `GET /api/strategies/meta` 拉取，不再硬编码。

2. **分组标签加解释**：每个分组顶部加一行浅色说明文字——"确定买入：所有条件满足，可执行" / "接近买点：距入场区 <1%，密切关注" / "继续观察：条件未满足，保持跟踪"。

3. **策略绩效对比卡片**：当前每个策略 Tab 下的绩效数据独立展示。增加一个"策略对比"折叠区，将所有策略的命中率/平均收益/最大回撤放在同一表格中横向对比。

4. **一键跳转分析**：候选标的卡片上的"分析"按钮点击后跳转到 Analysis 页并自动填入标的代码和底仓。


### 2.4 Research 研究复盘页

**当前状态**：6 个文本输入 + 2 个 select，密集的报告面板（4 种数据类型在一个滚动区）。

**核心问题**：
- `lookback_bars`（"样本窗口"）、`initial_position`（"底仓数量"）等术语用户看不懂
- 用 bar 数而非自然日期定义时间范围
- 回测/验证/复盘结果混在一个滚动面板中，无分层
- `bar_period` 下拉显示 "1m/5m/15m" 而非 "1分钟/5分钟/15分钟"

**优化方案**：

1. **表单改为自然语言**：

| 旧字段 | 旧术语 | 优化后 | 组件 |
|--------|--------|--------|------|
| symbol | 证券代码 | 标的 | SearchField（模糊搜索） |
| lookback_bars | 样本窗口 | 回看天数 | NumberField + "天"后缀 → 自动换算 bar 数 |
| initial_position | 底仓数量 | 初始仓位（股） | NumberField + "股"后缀 |
| walk_forward_windows | 样本外窗口 | 验证份数 | NumberField（默认 4） |
| low_buy_lookback_days | 执行回测天数 | 回测天数 | 保留（已有单位） |
| low_buy_limit | 执行样本上限 | 最大信号数 | 保留 |
| low_buy_strategy | 低吸策略 | 策略 | SelectField（中文标签） |
| bar_period | 分钟周期 | K线周期 | SelectField（1分钟 / 5分钟 / 15分钟） |

2. **bar 数 → 自然日期自动换算**：用户输入"回看 60 天"，系统根据当前日期和交易日历反算 bar 数传给后端。

3. **结果分层**：回测结果 → 折叠卡片（默认展开第一层：胜率/平均收益/盈亏比），展开后显示完整交易列表。验证结果 → 独立卡片组。复盘列表 → 可搜索/可筛选表格。


### 2.5 回测系统（重点深化）← Phase 3 核心改造

当前回测闭环（`/backtests`）和研究复盘（`/research`）是两个独立页面，各有自己的表单、术语和交互模式。用户需要学两遍。Phase 3 将其改造为统一的策略研究入口。

#### 2.5.1 统一入口 `/strategy`

```
/strategy
├── 快速回测    ← 日线组合回测，3 字段起步
├── 信号复盘    ← 分钟级单标的信号回顾
├── 参数优化    ← 搜索最优参数（Phase 2 产出）
├── 样本外验证  ← Walk-Forward（Phase 2 产出）
└── 结果对比    ← 多组回测/优化/验证对比
```

旧路由保留为 301 redirect：
- `/backtests` → `/strategy?tab=backtest`
- `/research` → `/strategy?tab=replay`

#### 2.5.2 快速回测 Tab（傻瓜式核心）

**默认态：仅 3 个必填字段**

| 字段 | 组件 | 默认值 | 说明 |
|------|------|--------|------|
| 回测区间 | 双日期选择器 | 最近 1 年 | 开始日期 + 结束日期 |
| 策略选择 | 多选标签（中文名） | 全选（5 个策略） | 不显示英文 key，从 API 拉取 |
| 初始资金 | 数字输入 + 单位 | 500,000 | 后缀"元" |

**高级参数（折叠，点击"更多设置"展开）**

| 字段 | 组件 | 默认值 | Tooltip |
|------|------|--------|---------|
| 成交价模型 | 下拉（中文） | 开盘价成交 | "开盘价最保守，VWAP 假设拿到日内均价，收盘价偏乐观" |
| 单票最大仓位 | 滑块 + 数字（% 后缀） | 30% | "单只股票最多占总资金的百分之多少" |
| 最大持仓数 | 数字输入 | 8 | "同时最多持有几只股票" |
| 止损比例 | 滑块（-3% ~ -10%） | -5% | "亏损超过这个比例自动卖出" |
| 止盈比例 | 滑块（5% ~ 20%） | 10% | "盈利超过这个比例自动卖出" |
| 对比基准 | 下拉搜索 | 沪深300（000300） | 预设：沪深300/中证500/创业板指/上证指数 |

**预设场景（一键回测）**

| 场景名 | 自动配置 |
|--------|---------|
| **"快速体检"** | 全策略、最近半年、开盘价成交、30% 仓位、8 持仓 |
| **"年度回顾"** | 全策略、最近 1 年、VWAP 成交、30% 仓位、8 持仓 |
| **"完整检验"** | 全策略、最近 2 年、开盘价成交、30% 仓位、8 持仓、含止损止盈 |

每个场景一个按钮，点击 → 预览确认 → 提交。一步完成。

**提交前预览**

点击"开始回测"后，弹出确认卡片：

```
即将运行回测：
  策略：首板回调、量能低吸、收盘强势承接、中军回踩、主线首分歧（5 个）
  区间：2025-01-02 → 2026-04-30（约 320 个交易日）
  资金：500,000 元
  成交价：开盘价（保守）
  预计耗时：约 2-3 分钟

[ 确认开始 ]  [ 修改参数 ]
```

#### 2.5.3 参数优化 Tab（Phase 2 产出，傻瓜化封装）

当前要求用户手动输入逗号分隔的参数列表（如 `70,75,80,85,90`）——这是开发者的交互模式。

**改造方案**：

| 参数 | 旧组件 | 新组件 |
|------|--------|--------|
| 策略 | 英文 key 下拉 | 中文标签下拉（API 驱动） |
| 日期范围 | 4 个日期选择器 | 2 个日期选择器 + "训练比例"滑块（默认 80%） |
| min_score | 逗号分隔文本 | 范围滑块：最小值 ~ 最大值 + 步长（如 70-90，步长 5） |
| max_holding_days | 逗号分隔文本 | 同上 |
| stop_loss_pct | 逗号分隔文本 | 同上（带负号标注） |

用户只需拖滑块选择"min_score 从 70 到 90，每 5 分一档"，系统自动生成 `[70, 75, 80, 85, 90]`。

优化结果展示：
- 参数排名表：按 Sharpe 降序排列，最优参数高亮
- IS（样本内）vs OOS（样本外）对比柱状图
- OOS 降级警告：红色横幅 + 解释文字

#### 2.5.4 样本外验证 Tab（Phase 2 产出，傻瓜化封装）

- 默认 4 窗口、75% 训练比例——对 90% 用户足够，不需要调
- 验证结果以窗口卡片组展示，每卡片：窗口区间 + 训练 Sharpe + 测试 Sharpe + 通过/不通过图标
- 总体稳定性结论：自然语言（"3/4 窗口盈利，稳定性良好"）

#### 2.5.5 结果对比 Tab（Phase 2 产出，傻瓜化封装）

旧方式：用户手动输入 `42,45,47`（run ID 数字）。新方式：
- 多选复选框列表：从已完成任务列表中勾选，不需要记 ID
- 对比表：自动计算所有选中回测的指标差异
- 净值曲线叠加图：ECharts 多线叠加

#### 2.5.6 WebSocket 实时进度推送

**架构**：
```
WebSocket /ws/strategy/{task_type}/{task_id}
  task_type: backtest | optimize | validate
```

后端 engine/optimizer/validator 在关键节点（每 10 个交易日、每完成一组参数、每完成一个窗口）推送进度消息。

**消息格式**：
```json
{
  "type": "progress",
  "task_id": 42,
  "task_type": "backtest",
  "progress_pct": 35.0,
  "message": "回测中：2025-08-15（156/480 交易日）",
  "timestamp": "2026-05-05T14:30:00"
}
```

```json
{
  "type": "completed",
  "task_id": 42,
  "task_type": "backtest",
  "summary": {
    "total_return_pct": 12.35,
    "sharpe": 1.52,
    "trade_count": 87
  }
}
```

前端表现：
- 任务列表中运行中的任务显示实时进度条

- WebSocket 断线自动重连（exponential backoff，最多 5 次）

#### 2.5.7 ECharts 图表升级

**净值曲线全面升级**

当前 SVG 轻量图（`EquityMiniChart`）替换为 ECharts 实现，但保留 SVG 作为 loading 态和大屏简图的降级方案。

### 2.6 Paper Trading 模拟盘页

**当前状态**：OrderEntryModal 含 11 个字段，PixelTraderWorker 动画，持仓/委托/成交/绩效 4 面板。

**核心问题**：
- 委托弹窗 11 个字段，其中 `strategy_key`、`reason`、`require_intraday_confirmation` 是非交易者语言
- PixelTraderWorker 动画可爱但是否是核心功能存疑
- 移动端的模拟盘只看不操作（无委托入口），与桌面端不一致

**优化方案**：

1. **委托弹窗精简为两步**：

   **第一步（必填，3 字段）**：
   - 标的（SearchField，自动填充当前分析页标的）
   - 方向（买/卖，大按钮切换）
   - 数量（NumberField + 全部/半仓/1/4仓 快捷按钮）

   **第二步（选填，折叠）**：
   - 价格类型（限价/市价）+ 委托价
   - 策略归属（SelectField，中文名，API 驱动）
   - 备注（可选文本框）

   去掉 `require_intraday_confirmation`（非交易者不需要关心的概念，默认开启）。

2. **PixelTraderWorker 保留但降级**：从占据 1/3 主面板改为右上角小挂件，点击展开大图。

3. **移动端补充委托入口**：移动端当前只显示持仓/订单/成交，增加"下单"浮动按钮。


### 2.7 Performance 绩效页

**当前状态**：1 个 select（日期范围），4 个 SVG 图表 + 策略表格 + 市场状态热力图。

**核心问题**：
- 两个手写 SVG LineChart 无交互（不能缩放/悬停/tooltip）
- 策略×市场状态交叉分析矩阵信息密度高但缺乏引导
- 日期范围仅 4 档（7/30/90/180 天），不能自定义

**优化方案**：

1. **日期范围增加自定义选项**：在 7/30/90/180 天后加一个"自定义"选项，弹出日期范围选择器。

2. **SVG 图保留但加基础交互**：增加 hover 提示（显示日期+数值），不需要完整 ECharts 替换。

3. **策略×市场状态矩阵加颜色引导**：红=盈利、绿=亏损、白=无数据、灰=无交易。矩阵上方一行文字解释颜色含义。


### 2.8 Settings 设置页

**当前状态**：12 个文本输入 + 动态因子权重 + 5 个"保存"按钮。6 个 SettingCard。

**核心问题**：
- 全部是裸文本输入，无格式校验（API Key、URL 格式）
- 保存按钮点完后无反馈（不知道是否保存成功）
- 策略治理列表只读、不能操作
- `risk_max_single_loss_pct` 等风控参数无单位提示

**优化方案**：

1. **增加行内校验**：
   - API Key：输入后显示掩码（••••••••），点击眼睛图标可查看
   - URL：失去焦点时校验格式（http/https 前缀）
   - 百分比字段：加 % 后缀标签
   - 保存成功后：按钮短暂变绿 + "已保存"提示（3 秒消失）

2. **策略治理增加操作**：当前只读列表，增加"暂停"/"启用"开关和"编辑参数"链接（跳转到 Playbook 对应策略的配置）。

3. **SettingCard 重构**：当前每个 card 独立 save 按钮。改为：所有修改在顶部统一显示"有 N 项未保存的更改 [全部保存]"。

## 三、移动端统一

当前桌面端和移动端是两套独立代码（`features/trading-workspace/` vs `mobile/`），各自实现了相同功能的独立版本。目标不是把移动端改成桌面端，而是**让移动端的交互逻辑与桌面端一致**。


### 3.1 共享组件层

移动端复用桌面端的格式化函数、API 客户端、类型定义。组件层面保持独立（移动端有自己的设计规范），但内部逻辑共享 hooks。


### 3.2 移动端特有优化

| Tab | 当前问题 | 优化 |
|-----|---------|------|
| 监控 | 优先榜卡片点击后无反馈 | 点击弹出底部抽屉（快捷查看入场区+信号评分） |
| 持仓 | 新增/编辑持仓需从头填写 | 搜索标的 → 自动带出最新价 → 只需输入持仓数和成本价 |
| 选股 | 策略 Tab 横向滚动太长 | 改为下拉 + 左右滑切换（保留横向滚动但加下拉快速跳转） |
| 模拟盘 | 只能看不能下单 | 加右下角浮动"下单"按钮 → 简化版委托弹窗（标的/方向/数量 3 字段） |


### 3.3 移动端表单统一

所有移动端表单统一用 stepper（步进器）替代裸数字输入。所有下拉统一用底部 ActionSheet 而非原生 select。

## 四、数据库与 API 变更

### 4.1 策略元数据表（新增）

```sql
CREATE TABLE strategy_metadata (
    key TEXT PRIMARY KEY,        -- first_board
    display_name TEXT NOT NULL,  -- 首板回调
    description TEXT,            -- 追踪首板涨停后回调至...
    category TEXT,               -- 回调类 / 趋势类 / 事件类
    risk_level TEXT,             -- low / medium / high
    typical_holding_days TEXT,   -- 3-7
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 4.2 预设场景表（新增）

```sql
CREATE TABLE strategy_presets (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,                         -- 快速体检
    description TEXT,                           -- 全策略最近半年快速扫描
    config_json TEXT NOT NULL,                  -- 完整的 BacktestConfig JSON
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

### 4.3 新增 API 端点

```
GET  /api/strategies/meta           ← 策略列表（含中文名、描述、标签）
GET  /api/strategy/presets          ← 预设场景列表
GET  /api/symbols/search?q=东方     ← 模糊搜索股票
GET  /api/strategies/{key}/history  ← 某策略的历史回测记录趋势
WS   /ws/strategy/{type}/{id}       ← 实时进度推送（type=backtest|optimize|validate）
```

Phase 2 的 optimize/validate/compare/attribution/monthly-returns 端点全部保留，仅前端调用方式改变。

## 五、不做清单

1. **不引入新 UI 框架**（Ant Design / MUI）——组件库内部自建，保持零外部 UI 依赖
2. **不做响应式桌面端**——固定宽度布局不变，移动端独立
3. **不做暗色模式**——当前无需求
4. **不做国际化**——仅中文
5. **不改变页面数量/结构**——8 页面 + 4 移动 Tab 保持不变（回测和研究合并为 /strategy 是多 Tab 页面，整体页面数减少但功能不丢失）
6. **不修改后端计算逻辑**——engine/optimizer/validator 核心逻辑不动
7. **不做 ECharts 全面替换 SVG**——仅在回测净值曲线和新增图表使用 ECharts，Performance 页 SVG 保留
8. **不做策略配置热更新**——元数据表需重启/刷新种子数据后生效
9. **不修改策略信号逻辑**——仍然是硬约束
10. **旧路由不删除**——`/backtests` 和 `/research` 保留为 301 redirect

## 九、结论

Phase 3 的本质是把 TQuant 从一个"开发者工具"改造成一个"交易者工具"——不需要会写代码、不需要懂金融工程术语，也能独立完成策略验证、分析、监控。

三个核心交付：

1. **全系统统一**——8 个桌面页 + 4 个移动端 Tab 共享同一套组件、格式化函数、API 客户端和策略元数据，不再各自为政
2. **回测傻瓜化**——从打开页面到看到回测结果，只需 3 次点击（选场景 → 确认 → 查看），实时进度条 + toast 通知全程可见
3. **一眼看懂**——净值曲线能缩放拖动，月度热力图红绿分明，收益分布图让人直观感受赚多赚少

预计 5-6 周。全部完成后，TQuant 的易用性将从"需要文档手册"提升到"30 秒上手、3 分钟出结果"的水平。
