## 六、factor 策略权限过滤

**决策**：**后端过滤**。`GET /api/strategies/meta` 的 handler 中检查 `current_user.roles`：

```python
@router.get("/api/strategies/meta")
def list_strategies(current_user = Depends(get_current_user), db = Depends(get_db)):
    resolver = StrategyTierResolver(db)
    items = [_strategy_meta_out(seed, resolver) for seed in DEFAULT_STRATEGY_META]
    # 普通用户不可查看 factor 策略
    if not _has_role(current_user, {"backtest_optimizer", "backtest_research", "admin", "administrator"}):
        items = [item for item in items if item.category_key != "factor"]
    return StrategyMetaResponse(strategies=items)
```

前端不再做二次过滤。WorkspaceConstants 的 filter 只按 `tier`/`visibility` 过滤，不按权限（权限已由 API 保证）。

## 七、费用验收表（逐项与 `calculate_fee()` 对齐）

`paper/fees.py` 实际费率：佣金 `max(gross×0.00025, 5.00)`，印花税 `gross×0.0005`（仅卖，ETF 免），过户费 `gross×0.00001`（ETF 免）。

| # | 场景 | 参数 | gross | 买入费 | 卖出费 | 往返费 | 费率% |
|---|------|------|-------|--------|--------|--------|-------|
| 1 | 股票标仓 | `600036`, price=40, qty=100 | 4,000 | 5.04 | 7.04 | **12.08** | 0.30% |
| 2 | ETF | `510300`, price=4, qty=1000 | 4,000 | 5.00 | 5.00 | **10.00** | 0.25% |
| 3 | 小单 | `600036`, price=10, qty=100 | 1,000 | 5.01 | 5.51 | **10.52** | 1.05% |
| 4 | 大单 | `600036`, price=40, qty=10000 | 400,000 | 104.00 | 304.00 | **408.00** | 0.10% |
| 5 | 零价 | price=0, qty=100 | 0 | 0 | 0 | **0** | — |
| 6 | 负价 | price=-10, qty=100 | <0 | 0 | 0 | **0** | — |
| 7 | 零量 | price=40, qty=0 | 0 | 0 | 0 | **0** | — |

大单买入费：佣金 `max(400000×0.00025=100, 5)=100` + 过户费 `400000×0.00001=4` = **104**。卖出费：佣金 100 + 印花税 `400000×0.0005=200` + 过户费 4 = **304**。往返 = **408**。

## 八、result_quality 字段规格

| 属性 | 值 |
|------|-----|
| **字段名** | `result_quality` |
| **位置** | `backend/app/models/schema_defs/backtest.py:99` → `BacktestRunDetail` 新增字段 |
| **类型** | `str` |
| **生成位置** | 回测 runner 完成运行后，在 `result` dict 构建时同步计算 |
| **生成逻辑** | `trade_count = len(result.get("trades", []))`；`coverage_pct = 实际有数据的交易日数 / 区间交易日总数 × 100` |

**枚举值**：

```python
RESULT_QUALITY_NORMAL = "normal"           # ≥10 笔成交 且 覆盖率 ≥80%
RESULT_QUALITY_LOW_SAMPLE = "low_sample"    # 5-9 笔成交
RESULT_QUALITY_INSUFFICIENT_DATA = "insufficient_data"  # 覆盖率 <60%
RESULT_QUALITY_NO_SAMPLE = "no_sample"     # 0 笔成交
```

**UI 映射**（前端 `BacktestDashboard.tsx` / `BacktestResearchPanel.tsx`）：

| result_quality | 展示效果 |
|---------------|---------|
| `"normal"` | 正常绩效面板 |
| `"low_sample"` | 顶部 banner 黄色："仅产生 {N} 笔信号，绩效统计可能不具代表性" |
| `"insufficient_data"` | 顶部 banner 橙色："交易日覆盖率仅 {PCT}%，数据可能不完整" |
| `"no_sample"` | 顶部 banner 灰色："未产生任何信号。可能原因：市场环境不匹配、策略条件过严、数据缺失" |

## 九、Feature Flag 缓存失效

| 场景 | 行为 |
|------|------|
| **PUT 后本进程** | 立即 `cache.pop(key)` → 下次 GET 读 DB |
| **PUT 后其他 worker** | 等待 TTL 过期（60s）后从 DB 刷新。多 worker 间容忍最大 60s 延迟 |
| **DB 不可用时 GET** | 返回上一次缓存值（不清空缓存），日志 WARNING |
| **首次部署无 DB 行** | 使用 `FlagDef.default`，不报错 |

**不引入**：DB 时间戳轮询、Redis Pub/Sub、全局缓存失效广播。多 worker 短 TTL 足够。
